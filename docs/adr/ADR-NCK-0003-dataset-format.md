# ADR-NCK-0003: A training dataset derived from the tested sources

**ADR ID**: ADR-NCK-0003
**Status**: accepted
**Date**: 2026-11-19
**Author**: jasagiri (drafted by Claude Opus 5.5)

## Context

The skills (`skills/*/SKILL.md` and `details/`) are read by an agent at work. The same knowledge is
also wanted as fine-tuning data for small models. Hand-writing a separate dataset would let it drift
from the tested modules and the pages.

## Requirements

- Every code answer in the dataset is code that this repository compiles and tests.
- Regenerating from unchanged sources changes no byte.
- Each record says where it came from (file, spec ID, catalog IDs), so a bad record can be traced
  and fixed at its source, not in the dataset.
- Usable by common fine-tuning tools without conversion.

## Options

1. **Hand-written JSONL** next to the modules. Flexible, but a second copy of every fact.
2. **Generated by an LLM** from the pages. Varied phrasing; answers untested and output not
   reproducible.
3. **Derived mechanically** from the pages, modules and tests by tools/dataset_build.nim.

## Trade-offs

Option 3 has the least variety of phrasing (the instructions come from templates), but every answer
is tested and every record traces to a file. Variety can be added later as a separate, clearly
marked augmentation step over this deterministic base.

## Decision

Option 3. `tools/dataset_build.nim` writes two files, sorted by record id:

- `dataset/records.jsonl` — one object per line:
  `{"id", "kind", "area", "concept", "instruction", "input", "output", "specIds", "sources", "files"}`.
  `kind` is one of
  - `explain`: instruction asks for the concept; output is the page's Intent, Use when / avoid when,
    and Complexity sections.
  - `implement`: instruction is the module's doc comment and its public signatures; output is the
    module source.
  - `refactor`: input is a ```nim bad block of a page's Pitfalls; output is the ```nim block that
    follows it in the same section.
  - `law`: instruction is one law bullet with its spec ID; output is the test (from `# SPEC:` tag
    to the end of that test) in the module's test file.
- `dataset/chat.jsonl` — the same records as `{"id", "messages": [{"role": "system"|"user"|"assistant", ...}]}`,
  with one fixed system message stating the house style (ADR-NCK-0002).

`id` is `<kind>:<area>/<concept>[#n]`, stable across runs. `sources` are catalog IDs from the page's
Sources section.

## Not decided here

- Train/validation splits: left to the consumer (records carry `area` and `concept` for grouping).
- Augmented phrasing.

## Rejected alternatives

Options 1 and 2 above.
