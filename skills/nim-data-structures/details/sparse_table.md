# Sparse table

## Intent
Answer range queries in O(1) for an operation that tolerates overlap, after an O(n log n) build. Level `k` stores the combination of every window of `2^k` elements. A query over `[l, r)` combines two windows of the largest power-of-two size that fits, one at the left end and one at the right end; the windows overlap and together cover the range.

## Use when / avoid when
- Use it for static data queried many times with min, max, gcd, bitwise and, bitwise or: range minimum queries are the standard case.
- Avoid it when the data changes: use `segment_tree` (O(log n) update and query) instead.
- Avoid it when the operation is not idempotent (sum, product, xor, count): use `fenwick_tree` for sums or `segment_tree` for any monoid.
- Avoid it when n is huge and memory is tight: it stores n log n values.

## Nim shape
`SparseTable[T]` holds the operation and a `seq` of levels (`levels[k][i]` is the combination of `items[i ..< i + 2^k]`). `fromSeq(items, op)` builds each level from the previous one in O(n). `query(l, r)` is half-open and returns `Option[T]`: there is no identity element, so an empty range has no answer.

```nim
import std/[options, math]
import nimcs/ds/sparse_table

let minOp: Op[int] = proc(a, b: int): int = min(a, b)
let gcdOp: Op[int] = proc(a, b: int): int = gcd(a, b)

let heights = fromSeq([5, 3, 8, 1, 9, 2], minOp)
doAssert heights.query(0, 3) == some(3)
doAssert heights.query(2, 6) == some(1)
doAssert heights.query(2, 2).isNone          # empty range: no answer
let g = fromSeq([12, 18, 24, 36], gcdOp)
doAssert g.query(0, 4) == some(6)
```

Why the operation must be idempotent. For a range of length 3 the two windows are `[l, l+2)` and `[l+1, l+3)`; element `l+1` is combined twice. For a range whose length is exactly a power of two, both windows are the same window, so every element is combined twice. When `op(x, x) == x` the doubling changes nothing, so the answer is right. For a sum it adds the shared elements twice, and the answer is wrong. Only associativity and idempotence are used, so an operation such as "keep the left value" (idempotent, not commutative) also works.

```nim
import std/options
import nimcs/ds/sparse_table

let sumOp: Op[int] = proc(a, b: int): int = a + b
let wrong = fromSeq([1, 1, 1], sumOp)
doAssert wrong.query(0, 3) == some(4)        # the true sum is 3: element 1 counted twice
doAssert not idempotentOn(sumOp, [1, 2, 3])
```

## Public API

Every exported symbol of `src/nimcs/ds/sparse_table.nim`, generated by `nim apiSections` (the
tests fail when it drifts). `import nimcs/ds/sparse_table` brings these names. A type they use from
another module (`Option`, `Result`, `Graph`) needs that module's import too, as in the example
above. A field marked `*` is readable outside the module; a type shown without fields is opaque,
built and read only through the functions.

```text
type Op[T] = proc (a, b: T): T {.noSideEffect, raises: [].}
type SparseTable[T] = object
func fromSeq[T](items: openArray[T]; op: Op[T]): SparseTable[T]
func len[T](t: SparseTable[T]): int
func levelCount[T](t: SparseTable[T]): int
func query[T](t: SparseTable[T]; l, r: int): Option[T]
func get[T](t: SparseTable[T]; i: int): Option[T]
func idempotentOn[T](op: Op[T]; samples: openArray[T]): bool
```

## Laws and invariants
- For min, max, gcd and keep-left, `query(l, r)` equals the fold of the slice (DS-SPARSETABLE-01).
- Empty and out-of-range ranges give `none` (DS-SPARSETABLE-02).
- A table over n elements has floor(log2 n) + 1 levels (DS-SPARSETABLE-03).
- A non-idempotent operation gives wrong answers where the windows overlap, and `idempotentOn` refutes it on samples (DS-SPARSETABLE-04).
- Range minima equal those of a `segment_tree` (DS-SPARSETABLE-05).
- Querying never changes the table: the same range gives the same answer (DS-SPARSETABLE-06).
- Five thousand elements and many ranges agree with the fold (DS-SPARSETABLE-07).

## Complexity
| Operation | Time | Space |
|---|---|---|
| `fromSeq` | O(n log n) | O(n log n) |
| `query`, `get` | O(1) | O(1) |

## Pitfalls
Picking the window size with a floating-point `log2` can round the wrong way at exact powers of two. Use an integer log.

```nim bad
import std/math

func windowBad(len: int): int =
  int(log2(float(len)))          # float rounding can give k with 2^k > len for large len
```

The module uses `fastLog2` from `std/bitops`, which is exact on integers.

```nim
import std/[options, bitops]
import nimcs/ds/sparse_table

let maxOp: Op[int] = proc(a, b: int): int = max(a, b)
let t = fromSeq([4, 9, 2, 7, 5], maxOp)
doAssert fastLog2(5) == 2 and t.levelCount == 3
doAssert t.query(1, 5) == some(9)
```
