# Stack, queue and the monotonic stack

## Intent
A stack gives back the newest item first, a queue gives back the oldest item first. Both are small enough to be plain values here: `push`, `pop`, `enqueue` and `dequeue` return a new container. The monotonic stack is a technique built on a stack: scan once while the stack keeps its values in order, and each element leaves the stack exactly when its answer (for example the next greater element) is known.

## Use when / avoid when
- Use `Stack` for undo history, expression evaluation, depth-first search with an explicit stack and bracket matching, when old versions are rarely kept.
- Use `Queue` for breadth-first search and work lists in arrival order.
- Use `nextGreaterIndex` for "nearest later element that is greater" questions: stock spans, next warmer day, histogram areas.
- Use `cons_list` as a persistent stack and `bankers_queue` as a persistent queue when old versions must stay cheap: here every update copies the storage, O(n).
- Inside one routine, a local `var seq` with `add` and `pop` (or a `std/deques` `Deque`) is the fast shape, and it is allowed because no caller can see it. The monotonic stack below does that.

## Nim shape
`Stack[T]` wraps a `seq` used from its end. `Queue[T]` wraps a `Deque[T]` from `std/deques` (a ring buffer). `top` and `front` return `Option`; `pop` and `dequeue` of the empty container return it unchanged. `toSeq` lists the items in the order they would be returned.

```nim
import std/options
import nimcs/ds/stack_queue

let s = emptyStack[int]().push(1).push(2).push(3)
doAssert s.top == some(3)
doAssert s.pop.toSeq == @[2, 1]
let q = emptyQueue[string]().enqueue("a").enqueue("b").enqueue("c")
doAssert q.front == some("a")
doAssert q.dequeue.toSeq == @["b", "c"]
doAssert s.len == 3 and q.len == 3     # the originals are unchanged
```

The monotonic stack: `pending` holds indices whose values are not yet beaten, and the values it holds never increase from bottom to top. When `xs[i]` is larger than the top, the top has found its answer and is popped. Each index is pushed once and popped at most once, so the scan is O(n) although it contains a loop inside a loop.

```nim
import std/options
import nimcs/ds/stack_queue

doAssert nextGreater([2, 1, 2, 4, 3]) == @[some(4), some(2), some(4), none(int), none(int)]
doAssert nextGreaterIndex([1, 3, 2, 5]) == @[some(1), some(3), some(3), none(int)]

# The same shape, written out (local `var`, nothing escapes):
func daysUntilWarmer(temps: seq[int]): seq[int] {.raises: [].} =
  result = newSeq[int](temps.len)
  var pending: seq[int]
  for i in 0 ..< temps.len:
    while pending.len > 0 and temps[pending[^1]] < temps[i]:
      let j = pending.pop
      result[j] = i - j
    pending.add i

doAssert daysUntilWarmer(@[73, 74, 75, 71, 69, 72, 76, 73]) == @[1, 1, 4, 2, 1, 1, 0, 0]
```

## Laws and invariants
- Items pushed on a stack are popped in reverse order (DS-STACKQUEUE-01).
- `push` then `pop` returns the original stack, and `top` is the pushed item (DS-STACKQUEUE-02).
- Items enqueued are dequeued in the same order (DS-STACKQUEUE-03).
- The empty stack and queue answer `none` and stay empty when popped (DS-STACKQUEUE-04).
- Updates leave the old stack and queue unchanged (DS-STACKQUEUE-05).
- `nextGreaterIndex` equals the quadratic definition on any input (DS-STACKQUEUE-06).
- `nextGreater` gives the textbook answers, including equal items (not strictly greater) and an empty input (DS-STACKQUEUE-07).
- Next-greater indices of 200000 increasing items come out right (DS-STACKQUEUE-08).

## Complexity
| Operation | Time | Space |
|---|---|---|
| `top`, `front`, `len`, `isEmpty` | O(1) | O(1) |
| `push`, `pop`, `enqueue`, `dequeue` | O(n): the storage is copied to keep the old version valid | O(n) |
| `nextGreaterIndex`, `nextGreater` | O(n) | O(n) |

## Pitfalls
Searching to the right for each element is the obvious solution and is O(n^2) on a sorted input.

```nim bad
func nextGreaterSlow(xs: seq[int]): seq[int] =
  for i in 0 ..< xs.len:
    var found = -1
    for j in i + 1 ..< xs.len:         # rescans the same elements again and again
      if xs[j] > xs[i]:
        found = j
        break
    result.add found
```

Let a stack of waiting indices remember what has not found its answer yet.

```nim
import std/options
import nimcs/ds/stack_queue

let r = nextGreaterIndex([5, 4, 3, 2, 1])      # nothing is greater: the stack never pops
doAssert r == @[none(int), none(int), none(int), none(int), none(int)]
```

The two ends differ: a stack works at one end, a queue at both. Do not use a `seq` with `delete(0)` as a queue; it moves every item.
