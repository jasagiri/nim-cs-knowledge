# Suffix trie (and why not a suffix tree)

## Intent
A suffix structure stores every suffix of a text so that substring questions are answered by walking from the root: does a pattern occur, how often, which substring repeats. This page implements a suffix trie: one node per character, with a count of the suffixes through each node. It is simple and immutable, but has O(n^2) nodes, so it is for small texts and for learning.

A suffix tree is the compressed form: unary paths are merged into single edges labelled by text ranges, giving O(n) nodes, and Ukkonen's algorithm builds it in O(n) with suffix links and an end index shared and mutated while building. That construction does not fit this repository's persistent, value-only style without losing the O(n) bound, so it is not written here. For real texts use `suffix_array` (with its LCP array), which answers the same questions in O(n) space.

## Use when / avoid when
- Use it to see what a suffix tree answers, and as an oracle to test faster implementations on short strings.
- Use it when the text is a few hundred characters at most (`maxTextLen` is 400).
- Avoid it for real texts: the trie has up to n(n+1)/2 nodes. Use `suffix_array` in `nimcs/algo` (suffix array plus LCP array), which answers the same questions in O(n) space.
- A real suffix tree compresses unary paths and is built in O(n) by Ukkonen's algorithm. That construction relies on suffix links and end indices shared and mutated while building; it was not written here because it does not fit the persistent, value-only style without losing the O(n) bound.

## Nim shape
`buildSuffixTrie(text)` returns `Result[SuffixTrie, TrieError]` and fails with `textTooLong` above `maxTextLen`. Each node keeps its children sorted by character in a `seq`, so there is no hash order, and a `count` of the suffixes passing through it, which is the number of (overlapping) occurrences of the string spelled by the path. Inserting a suffix copies its path and shares the rest.

```nim
import nimcs/fp/result
import nimcs/ds/suffix_trie

let t = buildSuffixTrie("banana").value
doAssert t.count("ana") == 2                 # overlapping occurrences are counted
doAssert t.contains("nan") and not t.contains("bnan")
doAssert t.distinctSubstrings == 15
doAssert t.longestRepeated == "ana"
```

The main module is `src/nimcs/ds/suffix_trie.nim`. `shortestAbsent(alphabet)` walks the trie level by level and returns the shortest string over the alphabet that does not occur, which is how a suffix tree finds a minimal absent word.

```nim
import nimcs/fp/result
import nimcs/ds/suffix_trie

let t = buildSuffixTrie("aabbcc").value
doAssert t.shortestAbsent("abc") == "ac"
doAssert buildSuffixTrie("x").value.shortestAbsent("") == ""
```

## Public API

Every exported symbol of `src/nimcs/ds/suffix_trie.nim`, generated by `nim apiSections` (the
tests fail when it drifts). `import nimcs/ds/suffix_trie` brings these names. A type they use from
another module (`Option`, `Result`, `Graph`) needs that module's import too, as in the example
above. A field marked `*` is readable outside the module; a type shown without fields is opaque,
built and read only through the functions.

```text
const maxTextLen = 400
type SuffixTrie = object
type TrieError = enum
  textTooLong                ## the text is longer than `maxTextLen`
func buildSuffixTrie(text: string): Result[SuffixTrie, TrieError]
func textLen(t: SuffixTrie): int
func count(t: SuffixTrie; sub: string): int
func contains(t: SuffixTrie; sub: string): bool
func distinctSubstrings(t: SuffixTrie): int
func longestRepeated(t: SuffixTrie): string
func shortestAbsent(t: SuffixTrie; alphabet: string): string
```

## Laws and invariants
- `count` equals a naive scan that includes overlapping occurrences, and `contains` equals substring membership (DS-SUFFIXTRIE-01).
- `distinctSubstrings` equals the size of the set of all substrings (DS-SUFFIXTRIE-02).
- `longestRepeated` is the longest substring that occurs at least twice, the smallest among equally long ones (DS-SUFFIXTRIE-03).
- Known answers hold for "banana" (DS-SUFFIXTRIE-04).
- The empty text has no substrings and counts the empty pattern once (DS-SUFFIXTRIE-05).
- A text over `maxTextLen` is refused with `textTooLong`, the maximum itself is accepted (DS-SUFFIXTRIE-06).
- `shortestAbsent` is absent from the text and every shorter string over the alphabet occurs (DS-SUFFIXTRIE-07).
- Building twice gives the same answers (DS-SUFFIXTRIE-08).

## Complexity
| Operation | Time | Space |
|---|---|---|
| `buildSuffixTrie` | O(n^2 * sigma) for alphabet size sigma, because each of n suffixes copies a path of up to n nodes | O(n^2) nodes |
| `count`, `contains` | O(m * sigma) for a pattern of length m | O(1) |
| `distinctSubstrings`, `longestRepeated` | O(nodes) = O(n^2) | O(n) stack |
| `shortestAbsent` | O(nodes * sigma) | O(nodes) |

Compare with a suffix tree (O(n) space, O(m) search, Ukkonen O(n) build) and a suffix array (O(n) space, O(m log n) search).

## Pitfalls
Building the trie of a long text exhausts memory: the node count grows with the square of the length.

```nim bad
import nimcs/ds/suffix_trie

# a 100_000 character text would need billions of nodes; do not do this
let huge = buildSuffixTrie(newString(100_000))
```

`buildSuffixTrie` refuses such input with `textTooLong`; handle the error, and use a suffix array for large texts.

```nim
import nimcs/fp/result
import nimcs/ds/suffix_trie

let r = buildSuffixTrie(newString(maxTextLen + 1))
doAssert r == err(SuffixTrie, textTooLong)
```
