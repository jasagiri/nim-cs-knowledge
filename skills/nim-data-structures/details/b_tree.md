# B-tree

## Intent
A persistent ordered set whose nodes hold many sorted keys instead of one. Every non-root node keeps between `t - 1` and `2t - 1` keys, an internal node has one child more than keys, and every leaf is at the same depth, so the tree is short and wide: a search reads O(log_t n) nodes. Insertion splits a node that overflows and pushes its median key up.

## Use when / avoid when
- Use it when a node should be one unit of transfer: a disk page, a database index block, or a few cache lines. One node read then decides among up to `2t` subtrees, so the number of reads falls from log2 n to log_t n.
- Use it when a sorted, duplicate-free set with cheap old versions is wanted and a large `t` (for example 16 to 64) suits the memory hierarchy.
- Avoid it for small in-memory sets where pointer chasing is cheap: `rb_tree` has smaller nodes and a simpler shape.
- Avoid it when order is irrelevant: `std/sets` (hash) is faster. Avoid it when you need deletion: this module is insert-only.

## Nim shape
`BTree[T]` is a value object: the minimum degree, a `ref` root and a size. A `Node` is an immutable `ref` with a `seq` of keys and a `seq` of children (empty in a leaf). The element type needs `<` only; equality is "neither is smaller". `newBTree` is the smart constructor: a degree below 2 would allow empty nodes, so it returns `none`.

`insert` is a recursive function that returns what the subtree became: one node, or two nodes and the key between them (the object variant `Grown`, exhaustive `case`). The parent copies its own key and child arrays, splits when they pass `2t - 1` keys, and passes the result up; a split of the root adds one level. Only the nodes on one path are copied, so an older tree keeps working.

```nim
import std/options
import nimcs/ds/b_tree

let t = fromSeq(2, [5, 3, 8, 1, 9, 2, 7]).get
doAssert t.toSortedSeq == @[1, 2, 3, 5, 7, 8, 9]
doAssert t.contains(8) and not t.contains(4)
let u = t.insert(4)
doAssert u.len == 8 and t.len == 7           # t is unchanged
doAssert u.insert(4).toSortedSeq == u.toSortedSeq   # inserting a member changes nothing
doAssert u.invariantsHold
```

Why wide nodes pay off. A binary tree of one million keys is about 20 levels deep, and each level is a separate allocation, so a lookup can touch 20 cache lines or 20 pages. With `t = 64` the same set is 3 to 4 levels deep, and each node's keys are contiguous, so a search is a binary search inside a few contiguous runs. The gain is the number of node visits, not the comparisons: a B-tree does about as many comparisons as a binary tree.

```nim
import std/options
import nimcs/ds/b_tree

var tall = newBTree[int](2).get
var wide = newBTree[int](32).get
for i in 1 .. 10_000:
  tall = tall.insert(i)
  wide = wide.insert(i)
doAssert tall.height > wide.height
doAssert wide.height <= 3                 # 2 * 32^2 - 1 = 2047 < 10_000 <= 2 * 32^3 - 1
```

## Public API

Every exported symbol of `src/nimcs/ds/b_tree.nim`, generated by `nim apiSections` (the
tests fail when it drifts). `import nimcs/ds/b_tree` brings these names. A type they use from
another module (`Option`, `Result`, `Graph`) needs that module's import too, as in the example
above. A field marked `*` is readable outside the module; a type shown without fields is opaque,
built and read only through the functions.

```text
type BTree[T] = object
func newBTree[T](minDegree: int): Option[BTree[T]]
func minDegree[T](t: BTree[T]): int
func len[T](t: BTree[T]): int

iterator items[T](t: BTree[T]): T

func invariantsHold[T](t: BTree[T]): bool
```

## Laws and invariants
- A degree below 2 gives `none`; otherwise the tree starts empty with that degree (DS-BTREE-01).
- Iteration yields the distinct inserted keys in ascending order, and `len` counts them (DS-BTREE-02).
- `contains` is true exactly for the inserted keys (DS-BTREE-03).
- After every insert each non-root node has `t - 1` to `2t - 1` keys, internal nodes have `keys + 1` children, all leaves have equal depth and the in-order keys ascend strictly (DS-BTREE-04).
- Inserting a member returns the same set: insert is idempotent (DS-BTREE-05).
- Insertion leaves the old version unchanged (DS-BTREE-06).
- Height stays logarithmic for ascending and descending inserts (DS-BTREE-07).
- A tree of height h holds at least `2 * t^(h-1) - 1` keys, which bounds the height by `1 + log_t((n + 1) / 2)` (DS-BTREE-08).
- Keys are ordered by `<` alone: equivalent keys collapse to one (DS-BTREE-09).

## Complexity
| Operation | Time | Space |
|---|---|---|
| `contains` | O(log n) comparisons, O(log_t n) node visits | O(1) |
| `insert` | O(t log_t n) (copies one path of nodes of up to `2t` entries) | O(t log_t n) new |
| `toSortedSeq`, iteration | O(n) | O(n) |
| `height`, `len`, `minDegree` | O(log_t n), O(1), O(1) | O(1) |

## Pitfalls
Splitting a node by copying the child array into a new node and mutating it in place breaks persistence: an older tree that shares the node sees the change.

```nim bad
type Node = ref object
  keys: seq[int]
  kids: seq[Node]

proc addKey(n: Node; x: int) =           # mutates a node an older tree may share
  n.keys.add x
```

Build new nodes from copies of the arrays and return them; check `invariantsHold` in tests after each step.

```nim
import std/options
import nimcs/ds/b_tree

var t = newBTree[int](2).get
for x in [10, 20, 30, 40, 50, 60]:
  let before = t
  t = t.insert(x)
  doAssert t.invariantsHold
  doAssert before.len + 1 == t.len
```

A second pitfall is choosing `t` by habit: the best `t` depends on the node size you want (page size divided by key size), and `t = 2` gives a 2-3-4 tree, useful for teaching but not for performance.
