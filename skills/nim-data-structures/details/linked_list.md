# Doubly linked list (arena)

## Intent
A doubly linked list gives O(1) insertion and removal at a known position because every node knows both neighbours. In its pointer form the nodes point at each other, which is a cycle of mutable references: it does not fit a persistent, value-oriented style. This version keeps the nodes in one array and links them by index, so the list is an ordinary value.

## Use when / avoid when
- Use it when elements must be inserted or removed in the middle through handles: an LRU order, an editor buffer, a free-slot list.
- Use `cons_list` for the persistent singly linked case (prepend, share tails, fold): it needs no back links, so structure sharing works.
- Use `bankers_queue` or `deque` for a queue or both ends, and `seq` when you only append and scan.
- Avoid a doubly linked list when you mostly iterate: a `seq` has better cache behaviour and a doubly linked list rarely wins.

## Nim shape
Why pointers do not fit: with `prev` and `next` as `ref`s, building the list needs mutation of shared nodes, a node cannot be shared between two versions of the list (its neighbours differ), and ORC has to collect cycles. In the arena form, `ArenaList[T]` holds `cells: seq[Cell[T]]`, the indices of the head and tail, a free list and a count. A cell stores `prev` and `next` as indices. `pushBack`, `pushFront` and `insertAfter` return the new list and a `NodeId` handle; `remove` takes a handle. An update copies the arena (O(n)) and does its relinking on the copy, so the old list stays valid.

A removed slot goes on the free list and is reused. Its generation is bumped when it is removed, and a `NodeId` carries the generation it was issued with, so a stale handle is rejected (`none`) instead of silently naming whatever reused the slot.

```nim
import std/options
import nimcs/ds/linked_list

let a = emptyList[string]().pushBack("a")
let c = a.list.pushBack("c")
let ab = c.list.insertAfter(a.id, "b").get          # splice in the middle by handle
doAssert ab.list.toSeqForward == @["a", "b", "c"]
doAssert ab.list.toSeqBackward == @["c", "b", "a"]  # the prev links agree
let without = ab.list.remove(ab.id).get
doAssert without.toSeqForward == @["a", "c"]
doAssert ab.list.len == 3                           # the old list is unchanged
```

A stale handle is refused:

```nim
import std/options
import nimcs/ds/linked_list

let first = emptyList[int]().pushBack(1)
let emptied = first.list.remove(first.id).get
let again = emptied.pushBack(2)                     # reuses the freed slot
doAssert again.id.index == first.id.index
doAssert again.list.get(first.id).isNone            # old handle: wrong generation
doAssert again.list.get(again.id) == some(2)
```

## Public API

Every exported symbol of `src/nimcs/ds/linked_list.nim`, generated by `nim apiSections` (the
tests fail when it drifts). `import nimcs/ds/linked_list` brings these names. A type they use from
another module (`Option`, `Result`, `Graph`) needs that module's import too, as in the example
above. A field marked `*` is readable outside the module; a type shown without fields is opaque,
built and read only through the functions.

```text
type NodeId = object
  index*: int
  generation*: int
type ArenaList[T] = object
func emptyList[T](): ArenaList[T]
func len[T](l: ArenaList[T]): int
func isEmpty[T](l: ArenaList[T]): bool
func pushBack[T](l: ArenaList[T]; x: T): tuple[list: ArenaList[T], id: NodeId]
func pushFront[T](l: ArenaList[T]; x: T): tuple[list: ArenaList[T], id: NodeId]
func insertAfter[T](l: ArenaList[T]; id: NodeId; x: T): Option[tuple[list: ArenaList[T], id: NodeId]]
func remove[T](l: ArenaList[T]; id: NodeId): Option[ArenaList[T]]
func get[T](l: ArenaList[T]; id: NodeId): Option[T]
func toSeqForward[T](l: ArenaList[T]): seq[T]
func toSeqBackward[T](l: ArenaList[T]): seq[T]
func invariantsHold[T](l: ArenaList[T]): bool
```

## Laws and invariants
- Pushing at the back gives the input order forward and its reverse backward (DS-LINKEDLIST-01).
- Pushing at the front gives the reverse of the input order forward (DS-LINKEDLIST-02).
- `insertAfter` places the new element right after the handle, in both directions (DS-LINKEDLIST-03).
- `remove` takes the element out of both directions and keeps the list consistent (DS-LINKEDLIST-04).
- A handle to a removed element is rejected even after its slot is reused (DS-LINKEDLIST-05).
- Updates leave the old list unchanged (DS-LINKEDLIST-06).
- Forward and backward links agree, the count matches, and every dead cell is on the free list exactly once, after every operation (DS-LINKEDLIST-07).
- The empty list is empty and a handle that is out of range is rejected (DS-LINKEDLIST-08).

## Complexity
| Operation | Time | Space |
|---|---|---|
| `get`, `len`, `isEmpty` | O(1) | O(1) |
| `pushBack`, `pushFront`, `insertAfter`, `remove` | O(n): the arena is copied to keep the old version valid; the relinking itself is O(1) | O(n) |
| `toSeqForward`, `toSeqBackward` | O(n) | O(n) |

Inside one routine with a local `var`, the relinking alone is O(1) per operation; that is the cost a textbook states.

## Pitfalls
Reusing a freed slot without a generation makes an old handle point at an unrelated element.

```nim bad
type Cell = object
  elem: int
  prev, next: int

func removeAndReuse(cells: var seq[Cell]; id: int) =
  cells[id] = Cell(elem: 0, prev: -1, next: -1)   # id stays valid forever: a stale id is accepted
```

Pair the index with a generation, bump it on removal and compare it on every use (`NodeId`).

```nim
import nimcs/ds/linked_list

var l = emptyList[int]()
for x in 1 .. 5:
  l = l.pushBack(x).list
doAssert l.invariantsHold and l.len == 5
```
