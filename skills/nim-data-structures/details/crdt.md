# State-based CRDTs

## Intent
Replicas of a value change their own copies without talking to each other and still agree afterwards. A state-based CRDT makes that possible by giving the state a `merge` that is commutative, associative and idempotent (the join of a semilattice): copies can be merged in any order, repeatedly and in any grouping, and every replica that has seen the same updates ends with an equal state. This module has four: `GCounter`, `PNCounter`, `LwwRegister` and `OrSet`.

## Use when / avoid when
- Use it for data that replicas update while disconnected (offline apps, multi-region counters, collaborative sets) and reconcile later, over a network that may duplicate, delay or reorder messages.
- Use `GCounter` for counts that only grow, `PNCounter` when they also shrink, `LwwRegister` for a single value where "the latest write wins" is acceptable, `OrSet` for a set where a concurrent add should beat a remove.
- Avoid it when updates need a global order or a guard such as "never below zero" or "unique username": merge cannot enforce an invariant across replicas; use consensus (a single writer, or Raft) for those.
- Avoid `LwwRegister` when losing a concurrent write is not acceptable: keep both values (a multi-value register) and let the application resolve them.
- Avoid shipping whole states when they are large: send deltas (a state is also a valid delta) or use an operation-based design.

## Nim shape
Every type is a plain value with a canonical form (sorted sequences, no duplicates, no zero entries), so `==` means "knows the same things". Each local update is a merge with a small state, which is why updates and merges can never contradict each other. `ReplicaId` is a `distinct string` made by `replicaId`, which refuses an empty name.

```nim
import nimcs/ds/crdt

let a = replicaId("a").value
let b = replicaId("b").value
# two replicas count while disconnected
let onA = emptyGCounter().increment(a, 3)
let onB = emptyGCounter().increment(b, 4).increment(b)
doAssert onA.merge(onB) == onB.merge(onA)
doAssert onA.merge(onB).value == 8
doAssert onA.merge(onB).merge(onB) == onA.merge(onB)       # a repeated message changes nothing
# a PN-Counter also goes down
let pn = emptyPNCounter().increment(a, 5).decrement(b, 2)
doAssert pn.value == 3
```

`LwwRegister[T]` orders writes by (stamp, replica id, value), so any two different writes have a winner and the merge is symmetric; `T` needs a `<` that is a strict total order consistent with `==`. `OrSet[T]` tags each addition with (replica, counter). `remove` cancels the tags this copy has seen, so an addition made concurrently by another replica survives the merge.

```nim
import std/options
import nimcs/ds/crdt

let a = replicaId("a").value
let b = replicaId("b").value
let title = emptyRegister[string]().write(10, a, "draft")
let other = emptyRegister[string]().write(12, b, "final")
doAssert title.merge(other).value == some("final")          # the later stamp wins
doAssert other.merge(title).value == some("final")

let shared = emptyOrSet[string]().add(a, "milk")            # both replicas hold this state
let removedOnA = shared.remove("milk")
let addedOnB = shared.add(b, "milk")                        # concurrent with the removal
doAssert "milk" in removedOnA.merge(addedOnB)               # add wins
doAssert "milk" notin removedOnA.merge(shared)              # a seen addition is removed
```

The main module is `src/nimcs/ds/crdt.nim`. The module does no networking: shipping states between replicas, and choosing how often, is the shell's job.

## Laws and invariants
- A replica id is non-empty (DS-CRDT-01).
- `GCounter`: the value after merging separately updated copies is the total of the increments, each replica keeping its own count (DS-CRDT-02); `merge` is commutative (DS-CRDT-03), associative (DS-CRDT-04) and idempotent (DS-CRDT-05); merging many copies gives one result in any order and grouping (DS-CRDT-06); merges and increments never lower the value (DS-CRDT-07).
- `PNCounter`: the merged value is all increments minus all decrements (DS-CRDT-08); commutative (DS-CRDT-09), associative (DS-CRDT-10), idempotent (DS-CRDT-11), order-free (DS-CRDT-12).
- `LwwRegister`: the winner has the largest stamp, then the largest replica id, then the largest value; an empty register loses; an older write does not replace a newer one (DS-CRDT-13); commutative (DS-CRDT-14), associative (DS-CRDT-15), idempotent (DS-CRDT-16), order-free (DS-CRDT-17).
- `OrSet`: remove cancels only the additions it has seen, a concurrent add wins, an element can be added again after removal (DS-CRDT-18); one replica's operations agree with an ordinary set at every step (DS-CRDT-19); commutative (DS-CRDT-20), associative (DS-CRDT-21), idempotent (DS-CRDT-22), order-free (DS-CRDT-23).

## Complexity
R is the number of replicas that have written, E the number of additions held by an `OrSet` (live and removed), T its tombstones.

| Operation | Time | Space |
|---|---|---|
| `GCounter` / `PNCounter` `merge` | O(R) | O(R) |
| `increment`, `decrement`, `countOf`, `value` | O(R) | O(R) |
| `LwwRegister` `merge`, `write`, `value` | O(1) | O(1) |
| `OrSet` `merge` | O(E + T) | O(E + T) |
| `OrSet` `add` | O(E + T) (finds the next tag, then merges) | O(E + T) |
| `OrSet` `remove` | O(E + T) | O(E + T) |
| `OrSet` `elements` | O(E log T) | O(E) |
| `OrSet` `contains` | O(E log T) | O(1) |

An `OrSet` never forgets a tombstone, so E and T grow with the number of removals; the module does not compact them.

## Pitfalls
Merging counters by adding the slots is not idempotent: a duplicated message counts twice.

```nim bad
type Counter = seq[int]            # one slot per replica

func merge(a, b: Counter): Counter =
  for i in 0 ..< max(a.len, b.len):
    result.add (if i < a.len: a[i] else: 0) + (if i < b.len: b[i] else: 0)   # merge(a, a) doubles every slot
```

Take the larger slot, as `GCounter.merge` does. Two further traps: two live copies that both update as the same replica id (restoring a backup and carrying on) can lose counter increments or give one tag to two additions, so a replica id belongs to one lineage of state; and last-write-wins trusts the stamps, so a replica whose clock runs slow loses its writes.

```nim
import nimcs/ds/crdt

let a = replicaId("a").value
let one = emptyGCounter().increment(a, 2)
doAssert one.merge(one) == one                     # idempotent: a duplicate is harmless
doAssert one.merge(emptyGCounter()) == one         # the empty counter is the identity
doAssert one.increment(a, 3).merge(one).value == 5 # the larger slot wins
```
