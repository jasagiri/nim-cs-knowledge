# Binary search tree (unbalanced, persistent)

## Intent
A binary search tree keeps items in order by giving every node a left subtree of smaller items and a right subtree of larger ones, so a lookup discards half of the remaining items only when the tree is balanced. This version has immutable nodes: an update copies the path it walks and shares everything else with the old tree.

## Use when / avoid when
- Use it to learn the ordered-tree operations (insert, contains, delete with the in-order successor) and the three depth-first traversals.
- Use it for small sets whose insertion order is effectively random.
- Avoid it when items can arrive sorted or nearly sorted: the tree degenerates into a list and every operation is O(n). Use `rb_tree` or `avl_tree`, which keep the height logarithmic. In practice, balanced trees (or `std/tables`, `std/sets` when order is not needed) are used and a plain BST is not.
- Avoid it when you need the persistent update of a map: `rb_tree` has `RbMap` with values.

## Nim shape
`Bst[T]` is a value with a `ref` root and a size. A node is an immutable `ref` with an item and two children. The item type needs `<`; two items are equal when neither is smaller, and inserting an item that is present returns the same tree.

A degenerate tree is as deep as it has items, so a custom `=destroy` frees nodes with a work list instead of one recursive call per node; a node still shared with another tree is left to its last owner. `ascendingChain` builds the worst case iteratively in O(n) (the recursive `insert` would need O(n) stack for it). The traversals, `height` and `invariantsHold` are recursive: on a chain that long, they need a deep stack; use a balanced tree for such sizes.

Deleting a node with two children replaces it with the smallest item of its right subtree (the in-order successor), which is removed from that subtree.

```nim
import nimcs/ds/bst

let t = fromSeq([4, 2, 6, 1, 3, 5, 7])
doAssert t.inOrder == @[1, 2, 3, 4, 5, 6, 7]     # left, node, right: sorted
doAssert t.preOrder == @[4, 2, 1, 3, 6, 5, 7]    # node, left, right: rebuilds the shape
doAssert t.postOrder == @[1, 3, 2, 5, 7, 6, 4]   # left, right, node: children first
doAssert t.height == 3
let d = t.delete(4)
doAssert d.inOrder == @[1, 2, 3, 5, 6, 7]
doAssert t.contains(4)                           # t is unchanged
```

The same items inserted in sorted order produce a tree as tall as it has items:

```nim
import nimcs/ds/bst

let sortedIn = fromSeq([1, 2, 3, 4, 5, 6, 7])
let balancedIn = fromSeq([4, 2, 6, 1, 3, 5, 7])
doAssert sortedIn.height == 7
doAssert balancedIn.height == 3
doAssert sortedIn.inOrder == balancedIn.inOrder  # same set, very different cost
```

## Public API

Every exported symbol of `src/nimcs/ds/bst.nim`, generated by `nim apiSections` (the
tests fail when it drifts). `import nimcs/ds/bst` brings these names. A type they use from
another module (`Option`, `Result`, `Graph`) needs that module's import too, as in the example
above. A field marked `*` is readable outside the module; a type shown without fields is opaque,
built and read only through the functions.

```text
type Bst[T] = object
func emptyBst[T](): Bst[T]
func len[T](t: Bst[T]): int
func isEmpty[T](t: Bst[T]): bool
func contains[T](t: Bst[T]; x: T): bool
func insert[T](t: Bst[T]; x: T): Bst[T]
func delete[T](t: Bst[T]; x: T): Bst[T]
func smallest[T](t: Bst[T]): Option[T]
func largest[T](t: Bst[T]): Option[T]
func height[T](t: Bst[T]): int
func inOrder[T](t: Bst[T]): seq[T]
func preOrder[T](t: Bst[T]): seq[T]
func postOrder[T](t: Bst[T]): seq[T]
func ascendingChain[T](items: openArray[T]): Option[Bst[T]]
func fromSeq[T](items: openArray[T]): Bst[T]
func invariantsHold[T](t: Bst[T]): bool
```

## Laws and invariants
- In-order traversal is the sorted list of distinct inserted items, and `len` counts them (DS-BST-01).
- `contains` is true exactly for the inserted items (DS-BST-02).
- Inserting a present item returns the same tree (DS-BST-03).
- `delete` removes the item and keeps the rest in order (DS-BST-04).
- A node with two children is replaced by its in-order successor (DS-BST-05).
- The three traversals give the textbook lists for the tree 4 2 6 1 3 5 7 (DS-BST-06).
- Re-inserting the pre-order list rebuilds the same shape (DS-BST-07).
- Updates leave the old tree unchanged (DS-BST-08).
- The empty tree has no smallest or largest item and `delete` keeps it empty (DS-BST-09).
- Sorted inserts make the height equal to the item count (DS-BST-10).
- The search-order invariant (every item strictly between the bounds of its ancestors) holds after every insert and delete (DS-BST-11).
- A chain of one million nodes (the worst-case shape) can be built, queried with `contains`, `smallest`, `largest` and `delete` at its end, and dropped without overflowing the stack (DS-BST-12).
- `ascendingChain` returns `none` unless the items are strictly ascending, and otherwise the same shape repeated `insert` would build (DS-BST-13).

## Complexity
| Operation | Time | Space |
|---|---|---|
| `contains`, `insert`, `delete` | O(h), h = height: O(log n) for random order, O(n) worst case | O(h) new nodes |
| `smallest`, `largest` | O(h) | O(1) |
| `inOrder`, `preOrder`, `postOrder`, `fromSeq` of n items | O(n) for the traversals, O(n h) for `fromSeq` | O(n) |

## Pitfalls
Deleting a node with two children by moving its subtrees around and forgetting the successor loses items or breaks the order.

```nim bad
type Node = ref object
  elem: int
  left, right: Node

func deleteRoot(n: Node): Node =
  if n.left.isNil: n.right
  elif n.right.isNil: n.left
  else: n.left                         # the whole right subtree is dropped
```

Take the smallest item of the right subtree, put it at the deleted position and remove it from there (`delete` does this). The invariant check catches both mistakes after every step.

```nim
import nimcs/ds/bst

var t = emptyBst[int]()
for x in [5, 2, 8, 1, 3, 7, 9]:
  t = t.insert(x)
  doAssert t.invariantsHold
let d = t.delete(5)
doAssert d.invariantsHold and d.len == 6
```

Do not use a plain BST on data that may be ordered (ids, timestamps): that is the degenerate case, not a rare one.
