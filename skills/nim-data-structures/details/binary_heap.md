# Binary heap (array-based min-heap)

## Intent
A binary heap is a priority queue stored in one array: the children of index `i` are `2i + 1` and `2i + 2`, and no child is smaller than its parent, so the minimum sits at index 0. Pushing appends and sifts up; popping moves the last item to the root and sifts down; both take O(log n) steps. As a value type, the update returns a new heap.

## Use when / avoid when
- Use it when you need the smallest item repeatedly and a flat array is acceptable: schedulers, Dijkstra's frontier, top-k, heap sort.
- Use `heapify` plus `toSortedSeq` for a one-shot sort or a snapshot: both sift on a local copy.
- Use `std/heapqueue` when the heap is a local `var` updated in place, which is the fastest shape and is allowed inside one routine.
- Use the persistent `leftist_heap`, `pairing_heap` or `binomial_heap` when old versions must stay cheap or two heaps must be merged: here `push` and `pop` copy the array, O(n).
- Avoid it when you need decrease-key or removal of an arbitrary item: none of the heaps here supports it.

## Nim shape
`BinaryHeap[T]` wraps a `seq[T]`. `siftUp` and `siftDown` are private routines with a `var seq` parameter, which is allowed because the public functions call them on a local copy. `heapify` is Floyd's construction: sift down every parent from the last one to the root, O(n) in total. `toSortedSeq` is heap sort on a copy: it moves the minimum to the end of the shrinking heap round after round and reads the array backwards. Items need `<`; define `<` for your own types at module level before use.

```nim
import std/options
import nimcs/ds/binary_heap

let h = heapify([5, 3, 8, 1, 9, 2])
doAssert h.peek == some(1)
doAssert h.pop.peek == some(2)
doAssert h.toSortedSeq == @[1, 2, 3, 5, 8, 9]
doAssert h.len == 6                    # h is unchanged
let g = h.push(0)
doAssert g.peek == some(0) and g.invariantsHold
```

A priority queue of jobs, ordered by a field:

```nim
import std/options
import nimcs/ds/binary_heap

type Job = object
  prio: int
  name: string

func `<`(a, b: Job): bool {.raises: [].} = a.prio < b.prio

let jobs = heapify([Job(prio: 3, name: "c"), Job(prio: 1, name: "a"), Job(prio: 2, name: "b")])
doAssert jobs.peek.get.name == "a"
doAssert jobs.pop.peek.get.name == "b"
```

## Public API

Every exported symbol of `src/nimcs/ds/binary_heap.nim`, generated by `nim apiSections` (the
tests fail when it drifts). `import nimcs/ds/binary_heap` brings these names. A type they use from
another module (`Option`, `Result`, `Graph`) needs that module's import too, as in the example
above. A field marked `*` is readable outside the module; a type shown without fields is opaque,
built and read only through the functions.

```text
type BinaryHeap[T] = object
func emptyHeap[T](): BinaryHeap[T]
func len[T](h: BinaryHeap[T]): int
func isEmpty[T](h: BinaryHeap[T]): bool
func push[T](h: BinaryHeap[T]; x: T): BinaryHeap[T]
func peek[T](h: BinaryHeap[T]): Option[T]
func pop[T](h: BinaryHeap[T]): BinaryHeap[T]
func heapify[T](items: openArray[T]): BinaryHeap[T]
func toSortedSeq[T](h: BinaryHeap[T]): seq[T]
func invariantsHold[T](h: BinaryHeap[T]): bool
```

## Laws and invariants
- Pushing items and draining with `peek` and `pop` yields them sorted (DS-BINARYHEAP-01).
- `heapify` builds a heap in which no item is smaller than its parent, and `toSortedSeq` gives the sorted items (DS-BINARYHEAP-02).
- `peek` is the minimum and `pop` removes one copy of it (DS-BINARYHEAP-03).
- Updates leave the old heap unchanged (DS-BINARYHEAP-04).
- The empty heap has no minimum and `pop` leaves it empty (DS-BINARYHEAP-05).
- No item is smaller than its parent after every push and pop (DS-BINARYHEAP-06).
- The drain order equals that of `std/heapqueue` (DS-BINARYHEAP-07).
- Items with equal keys come out in key order (DS-BINARYHEAP-08).

## Complexity
| Operation | Time | Space |
|---|---|---|
| `peek`, `len`, `isEmpty` | O(1) | O(1) |
| `push`, `pop` | O(n) because the array is copied; the sift itself is O(log n) | O(n) |
| `heapify` of n items | O(n) | O(n) |
| `toSortedSeq` | O(n log n) | O(n) |

## Pitfalls
Building a heap by n pushes costs O(n log n) and, with this value type, O(n^2) from the copies.

```nim bad
import nimcs/ds/binary_heap

func build(xs: seq[int]): BinaryHeap[int] =
  result = emptyHeap[int]()
  for x in xs:
    result = result.push(x)            # one array copy per item
```

Use `heapify`, which builds in one pass over a local array.

```nim
import nimcs/ds/binary_heap

let h = heapify(@[9, 4, 7, 1, 3])
doAssert h.invariantsHold
doAssert h.toSortedSeq == @[1, 3, 4, 7, 9]
```

Equal keys are not kept in insertion order: a binary heap is not stable. Add a sequence number to the key if order among equals matters.
