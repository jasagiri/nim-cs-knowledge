# Bit vector

## Intent
A fixed-size set of the integers `0 ..< n`, one bit per possible member, packed into 64-bit words. Membership is a shift and a mask, `count` is a population count per word, and union, intersection and difference work on 64 elements per operation. The size is part of the value and never changes.

## Use when / avoid when
- Use it when the universe is a known range of small integers: visited marks, flags, sieve results, dense id sets, adjacency rows of a small graph.
- Use it for rank and select: `rank(i)` counts members below `i`, `select(k)` finds the k-th member; they invert each other.
- Avoid it for sparse sets over a huge universe or non-integer members: `std/sets` stores only the members.
- Avoid it when memory must be below one bit per possible member and a false positive is acceptable: `bloom_filter` hashes into fewer bits, but it can answer "present" wrongly. A bit vector never does.

## Nim shape
`BitVector` is a value object (a `seq[uint64]` and the bit count). It is an `object` with private fields rather than `distinct seq[uint64]` because the length in bits must travel with the words: the last word has unused bits, and two vectors of different sizes must not be combined. `bitVector(size)` is the smart constructor and returns `none` for a negative size. The invariant "bits past the end are zero" is kept by every routine (complement masks the last word) and checked by `invariantsHold`.

Index errors are values, not exceptions, but reading is like a set: `test(i)` is `false` outside `0 ..< len`, because a non-member is not an error. Writing an out-of-range bit is a mistake, so `withBit` and `withoutBit` return `Option[BitVector]`.

```nim
import std/options
import nimcs/ds/bit_vector

let v = fromIndices(100, [3, 64, 99]).get
doAssert v.count == 3 and v.len == 100
doAssert v.test(64) and not v.test(65) and not v.test(100)
doAssert v.rank(64) == some(1)             # members below index 64: just 3
doAssert v.select(2) == some(99)
let w = v.withBit(7).get
doAssert w.toIndices == @[3, 7, 64, 99] and v.toIndices == @[3, 64, 99]
doAssert v.withBit(100).isNone
```

Set algebra needs equal sizes, so it returns `Option`:

```nim
import std/options
import nimcs/ds/bit_vector

let a = fromIndices(10, [1, 2, 3]).get
let b = fromIndices(10, [3, 4]).get
doAssert a.union(b).get.toIndices == @[1, 2, 3, 4]
doAssert a.intersection(b).get.toIndices == @[3]
doAssert a.difference(b).get.toIndices == @[1, 2]
doAssert a.complement.count == 7
doAssert a.union(bitVector(11).get).isNone
```

## Public API

Every exported symbol of `src/nimcs/ds/bit_vector.nim`, generated by `nim apiSections` (the
tests fail when it drifts). `import nimcs/ds/bit_vector` brings these names. A type they use from
another module (`Option`, `Result`, `Graph`) needs that module's import too, as in the example
above. A field marked `*` is readable outside the module; a type shown without fields is opaque,
built and read only through the functions.

```text
type BitVector = object
func bitVector(size: int): Option[BitVector]
func len(v: BitVector): int
func test(v: BitVector; i: int): bool
func withBit(v: BitVector; i: int): Option[BitVector]
func withoutBit(v: BitVector; i: int): Option[BitVector]
func fromIndices(size: int; indices: openArray[int]): Option[BitVector]
func count(v: BitVector): int
func rank(v: BitVector; i: int): Option[int]
func select(v: BitVector; k: int): Option[int]
func toIndices(v: BitVector): seq[int]
func union(a, b: BitVector): Option[BitVector]
func intersection(a, b: BitVector): Option[BitVector]
func difference(a, b: BitVector): Option[BitVector]
func complement(v: BitVector): BitVector
func invariantsHold(v: BitVector): bool
```

## Laws and invariants
- A negative size or an out-of-range index gives `none`; otherwise `len` is the size (DS-BITVECTOR-01).
- Exactly the given indices are set; `toIndices` lists them ascending (DS-BITVECTOR-02).
- `withBit` and `withoutBit` are idempotent and set or clear exactly that bit (DS-BITVECTOR-03).
- Updating leaves the old vector unchanged (DS-BITVECTOR-04).
- `count` is the number of distinct members (DS-BITVECTOR-05).
- `rank(i)` is the number of members below `i` for `0 <= i <= len` (DS-BITVECTOR-06).
- `select(k)` is the k-th smallest member and `rank(select(k)) == k` (DS-BITVECTOR-07).
- Union, intersection and difference match the set operations (DS-BITVECTOR-08).
- Union and intersection are commutative, associative and idempotent (DS-BITVECTOR-09).
- Complement flips exactly the bits below `len`, and complementing twice is the identity (DS-BITVECTOR-10).
- Combining vectors of different sizes gives `none` (DS-BITVECTOR-11).
- At word boundaries no bit past the end appears (DS-BITVECTOR-12).

## Complexity
Let w = ceil(n / 64) be the number of words.

| Operation | Time | Space |
|---|---|---|
| `test` | O(1) | O(1) |
| `withBit`, `withoutBit` | O(w) (copies the words) | O(w) |
| `count`, `rank`, `select`, `toIndices` | O(w) (`toIndices` also O(members)) | O(1) (`toIndices`: O(members)) |
| `union`, `intersection`, `difference`, `complement` | O(w) | O(w) |
| `fromIndices` with m indices | O(w + m) | O(w) |

## Pitfalls
A complement that flips whole words leaves ones past the end, so `count` is too large and equality with a rebuilt vector fails.

```nim bad
func complementBad(words: seq[uint64]): seq[uint64] =
  for w in words:
    result.add not w            # bits past nbits in the last word are now 1
```

Mask the last word, as the module does, and test the invariant.

```nim
import std/options
import nimcs/ds/bit_vector

let v = fromIndices(70, [0]).get
let c = v.complement
doAssert c.count == 69 and c.invariantsHold
doAssert c.complement == v
```

Another pitfall is calling `len` for the number of members: `len` is the universe size, `count` is the number of set bits.
