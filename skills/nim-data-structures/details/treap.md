# Treap

## Intent
An ordered set that is a binary search tree on the keys and a max-heap on a priority stored in each node. The priority is a fixed mixing function of a seed and the key, so the tree is balanced in expectation and, for one seed, its shape depends only on the key set, never on the insertion order. Updates are `split` and `merge`, which copy one path and share the rest.

## Use when / avoid when
- Use it when an ordered set must also be cut at a key (`split`) or joined with another set of a disjoint key range (`merge`) cheaply.
- Use it when a deterministic shape matters: the same seed and keys give the same tree on every run and in every insertion order, which makes tests and snapshots stable.
- Avoid it when a worst-case height bound is required: the bound is expected O(log n), not guaranteed. Reach for `rb_tree` instead.
- Avoid it for unordered lookup: `hamt` is the better fit.
- A skip list solves the same ordered-set problem with mutable towers of forward pointers; the treap is the persistent, deterministic choice here, so there is no skip list in this repository.

## Nim shape
`Treap[K]` is a value object holding a `ref` root and the seed. Nodes are immutable `ref` objects that store the key, the priority and the subtree size. There is no random generator: `priorityOf(seed, key)` hashes the key and mixes it with the seed through a bijective 64-bit finaliser, so equal keys always get equal priorities. The key type needs `<` and `hash`.

```nim
import std/options
import nimcs/ds/treap

let t = fromSeq(7'u64, [5, 1, 9, 3])
let s = t.split(5)
doAssert s.found
doAssert s.less.toSeq == @[1, 3] and s.greater.toSeq == @[9]
doAssert t.insert(4).toSeq == @[1, 3, 4, 5, 9]
doAssert t.len == 4                      # t is unchanged
doAssert t.minKey == some(1)
```

The main module is `src/nimcs/ds/treap.nim`. `merge` is the one operation that can be misused, so it returns a `Result`: a different seed gives `seedMismatch`, overlapping key ranges give `keysOverlap`.

```nim
import nimcs/fp/result
import nimcs/ds/treap

let low = fromSeq(1'u64, [1, 2, 3])
let high = fromSeq(1'u64, [10, 11])
let joined = low.merge(high)
doAssert joined.isOk and joined.value.toSeq == @[1, 2, 3, 10, 11]
doAssert low.merge(fromSeq(1'u64, [3, 4])) == err(Treap[int], keysOverlap)
doAssert low.merge(fromSeq(2'u64, [10])) == err(Treap[int], seedMismatch)
```

## Public API

Every exported symbol of `src/nimcs/ds/treap.nim`, generated by `nim apiSections` (the
tests fail when it drifts). `import nimcs/ds/treap` brings these names. A type they use from
another module (`Option`, `Result`, `Graph`) needs that module's import too, as in the example
above. A field marked `*` is readable outside the module; a type shown without fields is opaque,
built and read only through the functions.

```text
type Treap[K] = object
type TreapError = enum
  seedMismatch,             ## the two treaps were made with different seeds, so their priorities disagree
  keysOverlap                ## some key of the left treap is not smaller than every key of the right one
func emptyTreap[K](seed: uint64 = 0'u64): Treap[K]
func seed[K](t: Treap[K]): uint64
func len[K](t: Treap[K]): int
func isEmpty[K](t: Treap[K]): bool
func contains[K](t: Treap[K]; key: K): bool
func split[K](t: Treap[K]; key: K): tuple[less: Treap[K], found: bool, greater: Treap[K]]
func minKey[K](t: Treap[K]): Option[K]
func maxKey[K](t: Treap[K]): Option[K]
func merge[K](a, b: Treap[K]): Result[Treap[K], TreapError]
func insert[K](t: Treap[K]; key: K): Treap[K]
func delete[K](t: Treap[K]; key: K): Treap[K]
func fromSeq[K](seed: uint64; items: openArray[K]): Treap[K]
func toSeq[K](t: Treap[K]): seq[K]
func preorder[K](t: Treap[K]): seq[K]
func height[K](t: Treap[K]): int
func invariantsHold[K](t: Treap[K]): bool
```

## Laws and invariants
- `contains` agrees with a set and `toSeq` is the sorted distinct keys (DS-TREAP-01).
- Inserting a present key and deleting an absent one change nothing (DS-TREAP-02).
- `delete` removes exactly the given key (DS-TREAP-03).
- One seed and one key set give one shape, whatever the insertion order (DS-TREAP-04).
- Different seeds give the same contents but may give different shapes (DS-TREAP-05).
- `split` returns the smaller keys, the larger keys and whether the key was present (DS-TREAP-06).
- `merge` of the two halves of a split restores the key set and the shape (DS-TREAP-07).
- `merge` rejects overlapping ranges and different seeds with an error value (DS-TREAP-08).
- Updates leave the old version unchanged (DS-TREAP-09).
- Key order, heap order on seeded priorities and stored sizes hold after every insert and delete (DS-TREAP-10).
- The empty treap has no min or max and deleting from it leaves it empty (DS-TREAP-11).
- Twenty thousand ascending inserts give a height below 60, not a chain (DS-TREAP-12).
- String keys work and give an insertion-order-independent shape (DS-TREAP-13).

## Complexity
| Operation | Time | Space |
|---|---|---|
| `insert`, `delete`, `split`, `merge`, `contains` | O(log n) expected, O(n) worst case | O(log n) new nodes |
| `len`, `isEmpty` | O(1) | O(1) |
| `minKey`, `maxKey` | O(height) | O(1) |
| `toSeq`, `preorder` | O(n) | O(n) |

The expectation is over the seed: a priority function that behaves like random numbers gives expected height O(log n). An adversary who knows the seed and the function can choose keys that build a chain, so pick the seed from outside the data when the keys are untrusted.

## Pitfalls
Using the key itself as the priority (or any monotone function of it) turns the treap into an unbalanced search tree: ascending inserts build a chain.

```nim bad
type Node = ref object
  key: int
  left, right: Node

func prio(key: int): int = key           # not mixed: a sorted input makes a chain
```

Derive the priority through a mixing function of the seed and the key, as `priorityOf` does, and check `height` on a sorted input.

```nim
import nimcs/ds/treap

var t = emptyTreap[int](123)
for i in 1 .. 2000:
  t = t.insert(i)
doAssert t.height < 40
doAssert t.invariantsHold
```
