# Write-ahead log

## Intent
Before a change is applied to the state, it is written to a log; after a crash the state is rebuilt by replaying the log. Here the log is a value: an append-only sequence of records, each with a sequence number and a CRC-32, that `replay` folds into state, `encode` turns into bytes and `recover` reads back, dropping a torn tail instead of trusting it.

## Use when / avoid when
- Use it when a state machine (a key-value store, a counter, an order book) must survive a crash and the log is the source of truth: the state is a pure function of the records.
- Use it to test recovery logic without a disk: cut or damage the bytes of `encode` at every position and check what `recover` keeps.
- Avoid it as the file layer itself: writing, `fsync`, truncating the file to `keptBytes`, segment rotation and checkpoints are effects and belong in the shell around this value. This page covers the value only.
- Avoid it when you need tamper evidence: CRC-32 finds accidental damage only; use a keyed MAC or a hash chain (`merkle_tree`) against an adversary.
- Avoid it when appends are the hot path of a very large log: `append` copies the record sequence (see Complexity); reach for a file-backed log or a persistent sequence such as `pvector`.

## Nim shape
`Wal` holds a sequence of `WalEntry` (sequence number, payload, checksum). `append` returns `Result[Wal, WalError]`: the only failure is a payload over `maxPayload`. `replay(log, initial, apply)` takes `apply: (state, payload) -> state` as a pure function, so replaying twice from the same start gives the same state.

```nim
import nimcs/ds/write_ahead_log

func apply(state: int; payload: string): int {.raises: [].} =
  if payload == "inc": state + 1 else: state

let appended = emptyLog().appendAll(["inc", "noop", "inc"])
doAssert appended.isOk
let log = appended.value
doAssert log.len == 3 and log.nextSeq == 3
doAssert log.replay(0, apply) == 2
doAssert log.replay(0, apply) == log.replay(0, apply)      # replay is a pure fold
```

The bytes of one record are `seq (8, big-endian) | length (4) | payload | crc32 (4)`, the checksum covering the first three parts. `recover` walks the bytes from the start and stops at the first record that is short, whose length field is larger than the bytes left, whose sequence number is not the next one, or whose checksum fails. It reports `keptBytes` and `droppedBytes`, so the shell can truncate the file to `keptBytes` and carry on appending.

```nim
import nimcs/ds/write_ahead_log

let log = emptyLog().appendAll(["a", "b", "c"]).value
let bytes = log.encode
let torn = bytes[0 ..< bytes.len - 3]          # the crash cut the last record short
let r = recover(torn)
doAssert r.log.payloads == @["a", "b"]         # earlier records are kept
doAssert r.droppedBytes == torn.len - r.keptBytes
doAssert recover(r.log.encode).droppedBytes == 0   # a recovered log is a clean log
doAssert decodeStrict(torn).isErr              # a log closed cleanly must have no tail
```

The main module is `src/nimcs/ds/write_ahead_log.nim`.

## Public API

Every exported symbol of `src/nimcs/ds/write_ahead_log.nim`, generated by `nim apiSections` (the
tests fail when it drifts). `import nimcs/ds/write_ahead_log` brings these names. A type they use from
another module (`Option`, `Result`, `Graph`) needs that module's import too, as in the example
above. A field marked `*` is readable outside the module; a type shown without fields is opaque,
built and read only through the functions.

```text
const maxPayload = 16777216
type WalError = enum
  weTooLarge,               ## a payload longer than `maxPayload`
  weCorrupt                  ## `decodeStrict` found bytes that are not a whole, intact log
type WalEntry = object
  seqNo*: int
  payload*: string
  checksum*: uint32          ## CRC-32 of the sequence number, length and payload as encoded
type Wal = object
type Recovery = object
  log*: Wal                  ## the records that were read intact, a prefix of what was written
  keptBytes*: int            ## length of the prefix of the input that holds exactly those records
  droppedBytes*: int         ## bytes after that prefix: a torn or damaged tail
func emptyLog(): Wal
func len(log: Wal): int
func nextSeq(log: Wal): int
func entries(log: Wal): seq[WalEntry]
func payloads(log: Wal): seq[string]
func at(log: Wal; seqNo: int): Option[WalEntry]
func `==`(a, b: Wal): bool
func crc32(data: string): uint32
func append(log: Wal; payload: string): Result[Wal, WalError]
func appendAll(log: Wal; payloadList: openArray[string]): Result[Wal, WalError]
func replay[S](log: Wal; initial: S; apply: proc (state: S; payload: string): S {. noSideEffect, raises: [].}): S
func encode(log: Wal): string
func recover(bytes: string): Recovery
func decodeStrict(bytes: string): Result[Wal, WalError]
```

## Laws and invariants
- `append` gives the new record the next sequence number (0, 1, 2, ...), keeps the order, and leaves the old log unchanged (DS-WRITEAHEADLOG-01).
- `replay` is the left fold of `apply` over the payloads; the empty log returns the initial state (DS-WRITEAHEADLOG-02).
- Round trip: `recover(log.encode)` is the same log, nothing dropped, and `decodeStrict` agrees (DS-WRITEAHEADLOG-03).
- Cut at any byte, recovery keeps exactly the records that lie wholly before the cut (DS-WRITEAHEADLOG-04).
- Change any one byte and recovery keeps exactly the records before the damaged one, and `decodeStrict` reports `weCorrupt` (DS-WRITEAHEADLOG-05).
- `recover` never fails on arbitrary bytes, and `encode(recover(bytes).log)` is the first `keptBytes` bytes of the input; junk after a valid log never removes records before it (DS-WRITEAHEADLOG-06).
- Recovery is idempotent: recovering the encoding of a recovered log changes nothing, and replay gives the same state each time (DS-WRITEAHEADLOG-07).
- `crc32("123456789")` is `0xCBF43926` and the other check values hold (DS-WRITEAHEADLOG-08).
- A payload over `maxPayload` is refused with `weTooLarge`; a length field larger than the bytes left ends recovery without reading past the end (DS-WRITEAHEADLOG-09).

## Complexity
| Operation | Time | Space |
|---|---|---|
| `append` | O(n) in the records held (the value copies its sequence) plus O(payload) | O(n) new sequence |
| `appendAll` of k payloads | O(n + total payload) | O(n + k) |
| `replay` | O(n) calls of `apply` | what `apply` keeps |
| `encode`, `recover` | O(total bytes); `recover` also copies each record body once to check it | O(total bytes) |
| `at`, `len`, `nextSeq` | O(1) | O(1) |

## Pitfalls
Trusting the length field before checking it against the bytes that are left lets damaged bytes ask for a huge allocation, or read past the end.

```nim bad
func readPayload(bytes: string; at: int): string =
  var n = 0
  for i in 0 ..< 4:
    n = (n shl 8) or ord(bytes[at + 8 + i])
  bytes[at + 12 ..< at + 12 + n]       # n comes from the file: it may be larger than the file
```

Compare the length with `maxPayload` and with what remains first, and put the sequence number under the checksum too, as `recover` does. A second trap is to skip a bad record in the middle and carry on with later good ones: after a gap the order of the records is unknown, so recovery stops at the first bad record.

```nim
import nimcs/ds/write_ahead_log

let log = emptyLog().appendAll(["one", "two", "three"]).value
var damaged = log.encode
damaged[31] = char(ord(damaged[31]) xor 1)     # the first payload byte of the second record
let r = recover(damaged)
doAssert r.log.payloads == @["one"]            # "three" is dropped as well, though its bytes are intact
```

Finally, an unflushed log is not a log: the durability of `encode` bytes is the job of the file layer (`fsync` before acknowledging a write), which this value does not do.
