# kd-tree (2-d)

## Intent
A static binary tree over points in the plane. At each level the points are sorted along one axis, the median becomes the node and the halves become its subtrees, alternating x and y. Nearest-neighbour and rectangle queries then skip whole subtrees that cannot contain an answer. The tree is built once and never changes.

## Use when / avoid when
- Use it for many spatial queries over a point set that does not change: nearest point, all points in a rectangle.
- Use it when answers must be deterministic: ties in distance go to the lexicographically smaller point, and rectangle results come out in lexicographic order.
- Avoid it when points are inserted or removed often: it has no update. Rebuild it, or use a structure designed for updates.
- Avoid it for one query over a short list: a linear scan is simpler and as fast.

## Nim shape
`buildKdTree(points)` returns `Result[KdTree, KdError]`; it fails with `badCoordinate` for NaN, infinite or oversized coordinates (beyond `maxCoord`, so that a squared distance cannot overflow). `nearest(q)` returns `Option[Point]` (none for an empty tree). `inRect(r)` takes a closed rectangle and returns the points inside, duplicates repeated.

```nim
import std/options
import nimcs/fp/result
import nimcs/ds/kd_tree

let built = buildKdTree([point(2, 3), point(5, 4), point(9, 6), point(4, 7), point(8, 1)])
doAssert built.isOk
let t = built.value
doAssert t.nearest(point(9, 2)) == some(point(8, 1))
doAssert t.inRect(rect(3, 6, 3, 8)) == @[point(4, 7), point(5, 4)]
doAssert t.len == 5
```

The main module is `src/nimcs/ds/kd_tree.nim`. The sort at each level breaks coordinate ties with the full lexicographic order, so the tree for a given multiset of points does not depend on the input order, and so do all answers. Pruning uses `<=` where a strict test would be tempting: with equal coordinates both subtrees can hold a point at the same distance.

```nim
import std/options
import nimcs/fp/result
import nimcs/ds/kd_tree

let bad = buildKdTree([point(0, 0), point(NaN, 1)])
doAssert bad == err(KdTree, badCoordinate)
let empty = buildKdTree(newSeq[Point]()).value
doAssert empty.nearest(point(0, 0)).isNone
```

## Public API

Every exported symbol of `src/nimcs/ds/kd_tree.nim`, generated by `nim apiSections` (the
tests fail when it drifts). `import nimcs/ds/kd_tree` brings these names. A type they use from
another module (`Option`, `Result`, `Graph`) needs that module's import too, as in the example
above. A field marked `*` is readable outside the module; a type shown without fields is opaque,
built and read only through the functions.

```text
const maxCoord = 1e+150
type Point = object
  x*, y*: float
type Rect = object
  xLo*, xHi*, yLo*, yHi*: float
type KdError = enum
  badCoordinate              ## a coordinate is NaN, infinite or larger than `maxCoord` in magnitude
type KdTree = object
func point(x, y: float): Point
func rect(xLo, xHi, yLo, yHi: float): Rect
func `==`(a, b: Point): bool
func `<`(a, b: Point): bool
func dist2(a, b: Point): float
func buildKdTree(points: openArray[Point]): Result[KdTree, KdError]
func len(t: KdTree): int
func isEmpty(t: KdTree): bool
func nearest(t: KdTree; q: Point): Option[Point]
func inRect(t: KdTree; r: Rect): seq[Point]
func toSeq(t: KdTree): seq[Point]
func height(t: KdTree): int
func invariantsHold(t: KdTree): bool
```

## Laws and invariants
- The tree holds exactly the input points and satisfies its structural invariants: axis order at every node and sizes balanced to within one (DS-KDTREE-01).
- `nearest` equals the brute-force answer, with the lexicographically smallest point on distance ties (DS-KDTREE-02).
- `inRect` equals the brute-force filter, in lexicographic order (DS-KDTREE-03).
- The empty tree has no nearest point and every rectangle is empty (DS-KDTREE-04).
- A NaN, infinite or oversized coordinate makes the build fail with `badCoordinate` (DS-KDTREE-05).
- The input order does not change any answer (DS-KDTREE-06).
- Duplicate points are kept and counted (DS-KDTREE-07).
- Ten thousand grid points give height at most 14 (DS-KDTREE-08).
- Queries do not change the tree (DS-KDTREE-09).

## Complexity
| Operation | Time | Space |
|---|---|---|
| `buildKdTree` | O(n log^2 n) with a comparison sort at each level | O(n) |
| `nearest` | O(log n) on typical data; O(n) worst case | O(log n) stack |
| `inRect` | O(sqrt n + k) for k reported points on typical data; O(n) worst case | O(k) |
| `len`, `isEmpty` | O(1) | O(1) |

The query bounds are properties of well-spread data, not guarantees: a query point far from all stored points, or points on one line, can force the search into both subtrees.

## Pitfalls
Pruning the far side with a strict `<` loses answers when an equally close point sits across the splitting line, and the result then depends on tree shape.

```nim bad
import std/options

type Point = object
  x, y: float

func dist2(a, b: Point): float = (a.x - b.x) * (a.x - b.x) + (a.y - b.y) * (a.y - b.y)

func shouldVisitFar(diff: float; best, q: Point): bool =
  diff * diff < dist2(best, q)           # strict: skips an equally close point on the far side
```

Visit the far side when the line is at least as close (`<=`), and break ties by a total order on points; the tests compare with a brute-force scan on points with many ties.

```nim
import std/options
import nimcs/fp/result
import nimcs/ds/kd_tree

let t = buildKdTree([point(0, 1), point(2, 1)]).value
doAssert t.nearest(point(1, 1)) == some(point(0, 1))   # a tie: the smaller point wins
```
