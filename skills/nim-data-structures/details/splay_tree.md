# Splay tree

## Intent
A binary search tree that moves every key it touches to the root with zig, zig-zig and zig-zag rotations, so recently used keys are cheap to reach again. A classic splay tree does this by mutating on every read. A persistent value cannot, so here a lookup returns the answer together with the new tree, and the caller carries that tree forward.

## Use when / avoid when
- Use it for single-threaded access patterns with locality: a few keys asked for again and again, or sequential scans.
- Use it when you do not want to store balance information in the nodes.
- Avoid it when many readers hold the same version: the amortized bound does not apply to a version that is reused, and its deepest key costs O(n) every time. Reach for `rb_tree` or `treap`.
- Avoid it when worst-case per-operation time matters: a single operation can take O(n).

## Nim shape
`SplayTree[K]` is a value object with an immutable `ref` root and a size. `lookup(key)` returns `tuple[found: bool, tree: SplayTree[K]]`. The returned tree has the key at the root when it was found, and the last node visited when it was absent. `insert` and `delete` splay as well and return the new tree. `contains` is the one read that does not adapt: it walks without copying and gives up the locality gain.

```nim
import std/options
import nimcs/ds/splay_tree

var t = fromSeq([10, 20, 30, 40, 50])
let r = t.lookup(20)
doAssert r.found
t = r.tree                               # carry the returned tree forward
doAssert t.rootKey == some(20)
doAssert t.depthOf(20) == some(0)
doAssert t.toSeq == @[10, 20, 30, 40, 50]
```

The main module is `src/nimcs/ds/splay_tree.nim`. When the amortized bound holds: the O(log n) amortized cost per operation is a statement about a sequence of operations in which each one starts from the tree the previous one returned. If you ask the same old version again, it has not improved.

```nim
import std/options
import nimcs/ds/splay_tree

let chain = fromSeq([1, 2, 3, 4, 5, 6])          # ascending inserts: the key 1 is deepest
doAssert chain.depthOf(1) == some(5)
doAssert chain.lookup(1).tree.depthOf(1) == some(0)
doAssert chain.depthOf(1) == some(5)             # the old version is unchanged
```

Ascending inserts leave a chain as long as the tree. A custom `=destroy` frees nodes with a work list instead of one recursive call per node, so a chain of a million nodes can be built, queried with `depthOf` and `contains`, and dropped; a node still shared with another version is left to its last owner. `lookup`, `insert` and `delete` recurse to the depth of the path they walk, so on a chain they can still exhaust the stack: that limit was not measured, and the tests run those operations on trees of at most a thousand keys.

## Public API

Every exported symbol of `src/nimcs/ds/splay_tree.nim`, generated by `nim apiSections` (the
tests fail when it drifts). `import nimcs/ds/splay_tree` brings these names. A type they use from
another module (`Option`, `Result`, `Graph`) needs that module's import too, as in the example
above. A field marked `*` is readable outside the module; a type shown without fields is opaque,
built and read only through the functions.

```text
type SplayTree[K] = object
func emptyTree[K](): SplayTree[K]
func len[K](t: SplayTree[K]): int
func isEmpty[K](t: SplayTree[K]): bool
func lookup[K](t: SplayTree[K]; key: K): tuple[found: bool, tree: SplayTree[K]]
func contains[K](t: SplayTree[K]; key: K): bool
func insert[K](t: SplayTree[K]; key: K): SplayTree[K]
func delete[K](t: SplayTree[K]; key: K): SplayTree[K]
func fromSeq[K](items: openArray[K]): SplayTree[K]
func rootKey[K](t: SplayTree[K]): Option[K]
func depthOf[K](t: SplayTree[K]; key: K): Option[int]
func toSeq[K](t: SplayTree[K]): seq[K]
func invariantsHold[K](t: SplayTree[K]): bool
```

## Laws and invariants
- `toSeq` is the sorted distinct keys and `lookup` finds exactly the stored keys (DS-SPLAYTREE-01).
- After a successful `lookup`, the returned tree has that key at the root and the same key set (DS-SPLAYTREE-02).
- A failed `lookup` returns `found = false` and splays the last node visited (DS-SPLAYTREE-03).
- `insert` leaves the key at the root; a present key leaves the key set unchanged (DS-SPLAYTREE-04).
- `delete` removes exactly the key; an absent key changes nothing (DS-SPLAYTREE-05).
- `lookup`, `insert` and `delete` leave the old version unchanged (DS-SPLAYTREE-06).
- Asking again on the returned tree finds the key at depth 0 (DS-SPLAYTREE-07).
- Repeating a lookup on one old version never gets shallower, while threading the tree does (DS-SPLAYTREE-08).
- A run of lookups threaded forward keeps every tree valid and the key set unchanged (DS-SPLAYTREE-09).
- The empty tree answers with none and false and deleting from it leaves it empty (DS-SPLAYTREE-10).
- A chain of one million nodes can be built, read with `depthOf` and `contains`, and dropped without overflowing the stack (DS-SPLAYTREE-12).
- A thousand ascending inserts followed by lookups in order cost about five levels per key, far below the quadratic cost of a chain (DS-SPLAYTREE-11).

## Complexity
| Operation | Time | Space |
|---|---|---|
| `lookup`, `insert`, `delete` | O(log n) amortized when the returned tree is carried forward; O(n) worst case for one operation | O(path) new nodes |
| `contains`, `depthOf` | O(height), O(n) worst case | O(1) |
| `len`, `isEmpty`, `rootKey` | O(1) | O(1) |
| `toSeq` | O(n) | O(n) |

## Pitfalls
Throwing the returned tree away keeps the answer but loses the rearrangement, so the next lookup pays the full depth again.

```nim bad
import nimcs/ds/splay_tree

let t = fromSeq([1, 2, 3, 4, 5, 6])
for _ in 1 .. 100:
  doAssert t.lookup(1).found             # `t` never changes: every call walks 5 levels
```

Keep the new tree in a `var` and assign it on every step.

```nim
import nimcs/ds/splay_tree

var t = fromSeq([1, 2, 3, 4, 5, 6])
for _ in 1 .. 100:
  let r = t.lookup(1)
  doAssert r.found
  t = r.tree                             # after the first call the key is at the root
```
