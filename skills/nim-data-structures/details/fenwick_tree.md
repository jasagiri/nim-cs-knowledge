# Fenwick tree

## Intent
Prefix sums with point updates over integers, using a single flat array. Slot `i` (1-based) holds the sum of the `lowbit(i)` elements that end at `i`, where `lowbit(i)` is the largest power of two dividing `i`. Walking down by stripping the lowest set bit gives a prefix sum in O(log n); walking up by adding it gives an update in O(log n).

## Use when / avoid when
- Use it for running totals that change: counting how many items are below a value (rank), counting inversions, histograms with cumulative queries.
- Use it when memory matters: it stores exactly n integers, a segment tree stores about 2n nodes.
- Avoid it when the operation has no inverse (min, max, gcd, concatenation): a range query needs `prefix(r) - prefix(l)`. Reach for `segment_tree` (only associativity needed) or `sparse_table` (static data, idempotent operations).
- Avoid it when many old versions are kept and updated one at a time: this value copies the array on each update (see Complexity). `segment_tree` shares structure and copies only a path.

## Nim shape
`FenwickTree` is a value object around one `seq[int]`. `fromSeq` builds it in O(n) by pushing each slot into the next slot that also covers it. `prefixSum(r)` sums elements `0 ..< r`; `rangeSum(l, r)` is half-open like `segment_tree.query`. Out-of-range input is `none`, never a wrong sum.

```nim
import std/options
import nimcs/ds/fenwick_tree

let f = fromSeq([3, 1, 4, 1, 5, 9, 2, 6])
doAssert f.prefixSum(4) == some(9)
doAssert f.rangeSum(2, 6) == some(19)
let g = f.add(2, 10).get                  # element 2 becomes 14
doAssert g.get(2) == some(14) and f.get(2) == some(4)
doAssert f.prefixSum(9).isNone
```

Comparison with `segment_tree`. Both answer range sums with point updates in O(log n). The Fenwick tree needs an inverse (a group: integers under `+`) and is smaller and faster per operation; the segment tree needs only a monoid, so it also does min, gcd and ordered concatenation, and its persistent update shares all but one path. Here the Fenwick tree is a plain value, so one update costs O(n) for the copy plus O(log n) for the walk; `addAll` applies a batch with one copy.

```nim
import std/options
import nimcs/ds/fenwick_tree

let f = zeros(5).get
let g = f.addAll([(0, 2), (3, 7), (0, 1), (4, -2)]).get
doAssert g.values == @[3, 0, 0, 7, -2]
doAssert g.rangeSum(0, 5) == some(8)
doAssert f.addAll([(0, 1), (9, 1)]).isNone   # one bad index: no change at all
```

```text
type FenwickTree = object

func rangeSum(f: FenwickTree; l, r: int): Option[int]

func add(f: FenwickTree; i, delta: int): Option[FenwickTree]

```

## Laws and invariants
- `prefixSum(r)` is the sum of the first `r` elements for every `0 <= r <= len` (DS-FENWICK-01).
- `rangeSum(l, r)` is the sum of the slice `l ..< r`, and `none` outside `0 <= l <= r <= len` (DS-FENWICK-02).
- After any sequence of point updates the tree agrees with a plain array: elements and all prefix sums (DS-FENWICK-03).
- Updating leaves the old tree unchanged (DS-FENWICK-04).
- `addAll` equals the same updates applied one by one, and fails as a whole on a bad index (DS-FENWICK-05).
- Negative sizes, out-of-range indices and prefixes give `none` (DS-FENWICK-06).
- All range sums equal those of a `segment_tree` over the same array (DS-FENWICK-07).
- Rebuilding from `values` gives a tree with the same answers (DS-FENWICK-08).

## Complexity
| Operation | Time | Space |
|---|---|---|
| `fromSeq` | O(n) | O(n) |
| `prefixSum`, `rangeSum`, `get` | O(log n) | O(1) |
| `add` | O(n) copy + O(log n) walk | O(n) new array |
| `addAll` with m updates | O(n + m log n) | O(n) new array |

## Pitfalls
Using 0-based indices in the walk makes `lowbit(0) = 0` and the loop never moves.

```nim bad
func prefixSumBad(slots: seq[int]; r: int): int =
  var i = r - 1                   # 0-based: lowbit(0) is 0, so the loop would not end
  while i >= 0:
    result += slots[i]
    i -= i and -i                 # i = 0 stays 0 forever (and i = -1 exits too early)
```

Keep the slots 1-based (slot 0 unused) and convert at the boundary, as the module does. A second pitfall is overflow: all prefix sums must fit in `int`; the tree does not check.

```nim
import std/options
import nimcs/ds/fenwick_tree

let f = fromSeq([5, -2, 7])
doAssert f.prefixSum(0) == some(0)         # the empty prefix is 0
doAssert f.prefixSum(3) == some(10)
```
