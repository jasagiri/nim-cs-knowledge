# Consistent hashing

## Intent
Spread keys over a changing set of nodes so that adding or removing a node moves only a small share of the keys. Keys and nodes are hashed onto a circle; each node sits at many points (virtual nodes) and a key belongs to the first point at or after its own position.

## Use when / avoid when
- Use it for caches, shards and partitions whose membership changes while running: with 4 nodes growing to 5, about one key in five moves.
- Use it to pick a replica list for a key: `owners(key, 3)` gives three distinct nodes walking clockwise.
- Avoid it when the node set never changes: `hash mod n` is simpler (`hash_table`).
- Avoid it when every node must hold exactly the same number of keys: the share varies by a few percent; give heavier nodes more virtual nodes, or use a table of explicit slots (as Redis Cluster does).
- Avoid it for adversarial keys with this hash: `ringHash` is not cryptographic.

## Nim shape
`Ring` is a value. `newRing(vnodes)` checks the virtual node count; `addNode` and `removeNode` return new rings; `owner` returns `Option[string]` (none when the ring is empty). The hash is `ringHash`, FNV-1a 64 plus the MurmurHash3 finalizer, fixed in the module, so owners are the same on every run and machine. Virtual node `i` of `n` sits at `ringHash("n#i")`. The layout depends on which nodes are present, never on the order they were added.

```nim
import std/options
import nimcs/ds/consistent_hashing

let empty = newRing(64).value
let ring = empty.addNode("cache-a").value.addNode("cache-b").value.addNode("cache-c").value
doAssert ring.len == 3
doAssert ring.owner("user:42").isSome
doAssert ring.owner("user:42") == ring.owner("user:42")
doAssert empty.owner("user:42").isNone
let replicas = ring.owners("user:42", 2)
doAssert replicas.len == 2 and some(replicas[0]) == ring.owner("user:42")
```

Adding a node takes over only arcs just before its new points, so every key that moves, moves to the new node; removing a node hands its arcs to the next points, so only its keys move.

```nim
import std/options
import nimcs/ds/consistent_hashing

let before = newRing(128).value.addNode("a").value.addNode("b").value.addNode("c").value
let after = before.addNode("d").value
var moved = 0
var toNew = 0
for i in 0 ..< 1000:
  let key = "key-" & $i
  if before.owner(key) != after.owner(key):
    inc moved
    if after.owner(key) == some("d"): inc toNew
doAssert moved == toNew                        # nothing moved between old nodes
doAssert after.removeNode("d") == before       # and removing the node restores the old ring
```

The main module is `src/nimcs/ds/consistent_hashing.nim`. Measured with this module (128 virtual nodes per node, keys `key-0` to `key-3999`): four nodes held 900, 1004, 1019 and 1077 keys; adding a fifth moved 802 keys (the ideal is 800); `hash mod n` going from 4 to 5 moved 3213 of the same keys.

## Laws and invariants
- An empty ring has no owner; otherwise the owner is a member and is the same on every call and for every ring built from the same nodes (DS-CONSISTENTHASHING-01).
- The ring is the same whatever order the nodes were added in and however often one was added (DS-CONSISTENTHASHING-02).
- Adding a node: the keys that move are exactly the keys the new node owns; no key moves between old nodes (DS-CONSISTENTHASHING-03).
- Removing a node: only its keys move; removing an absent node changes nothing; re-adding the node restores the ring (DS-CONSISTENTHASHING-04).
- `owners(key, n)` returns `min(n, nodes)` distinct nodes starting with the owner (DS-CONSISTENTHASHING-05).
- `ringHash` is a fixed function: its values for given strings are pinned (DS-CONSISTENTHASHING-06).
- With 128 virtual nodes each, four nodes hold 20 to 30 percent of 4000 keys and a fifth node moves about a fifth of them, where `hash mod n` moves most (DS-CONSISTENTHASHING-07).
- A ring needs at least one virtual node per node and every node a name (DS-CONSISTENTHASHING-08).

## Complexity
| Operation | Time | Space |
|---|---|---|
| `owner` | O(log(N V)) for N nodes with V virtual nodes | O(1) |
| `owners(key, k)` | O(log(N V) + the points walked to meet k nodes) | O(k) |
| `addNode` | O(N V log(N V)) (the points are sorted again) | O(N V) new ring |
| `removeNode` | O(N V) | O(N V) |

## Pitfalls
One point per node gives lumpy shares: a node's share is the length of one random arc, which can be several times the average (see the measured shares below).

```nim bad
import nimcs/ds/consistent_hashing

let ring = newRing(1).value.addNode("a").value.addNode("b").value.addNode("c").value
# three arcs of random length: measured on 3000 keys, the nodes held 2050, 519 and 431
doAssert ring.len == 3
```

Use 64 to 256 virtual nodes per node. Other traps: hashing with a function whose output depends on the process (a seeded or randomized string hash) gives different owners in different processes (the ring uses the fixed `ringHash`); and a node name that is reused with another meaning keeps its old positions, so renaming a node is a removal plus an addition and moves its keys.

```nim
import std/options
import nimcs/ds/consistent_hashing

let ring = newRing(128).value.addNode("a").value.addNode("b").value.addNode("c").value
var counts = [0, 0, 0]
for i in 0 ..< 3000:
  let o = ring.owner("k" & $i).get
  counts[ord(o[0]) - ord('a')] += 1
doAssert counts[0] + counts[1] + counts[2] == 3000
doAssert min(counts) > 500                     # no node is starved with many virtual nodes
```
