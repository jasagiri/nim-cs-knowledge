# Prefix sums and difference arrays

## Intent
Answer "what is the sum of this range?" in constant time by keeping the running sums once: the sum of `xs[l ..< r]` is `prefix[r] - prefix[l]`. The difference array does the reverse job: it makes "add d to every element of a range" cost two writes, and a final running sum restores the values. The two are inverses of each other, and both extend to two dimensions.

## Use when / avoid when
- Use a prefix table when the data is fixed and many range-sum (or rectangle-sum) questions are asked.
- Use a difference array when many range additions come first and the values are read once at the end (booking intervals, painting ranges, event counts).
- Avoid both when the data changes between questions: each change would rebuild O(n) of the table; use a Fenwick tree or `segment_tree.nim` in `ds/`.
- Avoid prefix sums for operations that are not invertible (minimum, maximum): subtraction has no counterpart there; use a sparse table or a segment tree.
- For "longest window under a bound" over non-negative numbers a sliding window (`two_pointers.nim`) needs no table.

## Nim shape
`PrefixSums` and `PrefixSums2D` are opaque values built by `prefixOf` and `prefixOf2D`; ranges are half-open (`l ..< r`) and a bad range is a value: `rangeSum` and `rectSum` return `Result[int, SpanError]` with `reOutOfBounds` or `reReversed`, `prefixOf2D` fails with `reRagged` on rows of different length. `differences` and `fromDifferences` convert between values and changes; `applyRangeAdds(n, updates)` applies `(l, r, delta)` updates to n zeros through a difference array.

```nim
import nimcs/fp/result
import nimcs/algo/prefix_sum

let p = prefixOf([3, -1, 4, 1, -5])
doAssert p.rangeSum(1, 4) == ok(4, SpanError)               # -1 + 4 + 1
doAssert p.rangeSum(2, 1) == err(int, reReversed)

doAssert differences([5, 7, 7, 4]) == @[5, 2, 0, -3]
doAssert fromDifferences(differences([5, 7, 7, 4])) == @[5, 7, 7, 4]

# three bookings of ranges of days 0 ..< 5: how many overlap each day?
doAssert applyRangeAdds(5, [(0, 3, 1), (2, 5, 1), (1, 2, 1)]) == ok(@[1, 2, 2, 1, 1], SpanError)

let grid = prefixOf2D(@[@[1, 2, 3], @[4, 5, 6]]).value
doAssert grid.rectSum(0, 1, 2, 3) == ok(16, SpanError)      # 2 + 3 + 5 + 6
```

## Public API

Every exported symbol of `src/nimcs/algo/prefix_sum.nim`, generated by `nim apiSections` (the
tests fail when it drifts). `import nimcs/algo/prefix_sum` brings these names. A type they use from
another module (`Option`, `Result`, `Graph`) needs that module's import too, as in the example
above. A field marked `*` is readable outside the module; a type shown without fields is opaque,
built and read only through the functions.

```text
type SpanError = enum
  reOutOfBounds,            ## an index outside 0 .. length (rows or columns for a rectangle)
  reReversed,               ## the start of a range is after its end
  reRagged                   ## the rows of a grid do not all have the same length
type PrefixSums = object
type PrefixSums2D = object
func prefixOf(xs: openArray[int]): PrefixSums
func count(p: PrefixSums): int
func rangeSum(p: PrefixSums; l, r: int): Result[int, SpanError]
func differences(xs: openArray[int]): seq[int]
func fromDifferences(diffs: openArray[int]): seq[int]
func applyRangeAdds(n: int; adds: openArray[(int, int, int)]): Result[seq[int], SpanError]
func prefixOf2D(grid: openArray[seq[int]]): Result[PrefixSums2D, SpanError]
func rowCount(p: PrefixSums2D): int
func columnCount(p: PrefixSums2D): int
func rectSum(p: PrefixSums2D; row0, col0, row1, col1: int): Result[int, SpanError]
```

## Laws and invariants
- The table has one entry more than the data, starts at 0 and adds each element (TECH-PREFIX-01).
- `rangeSum(l, r)` equals the sum added element by element, is additive over a split point, and is 0 for an empty range (TECH-PREFIX-02).
- An outside range gives `reOutOfBounds`, a reversed one `reReversed` (TECH-PREFIX-03).
- `fromDifferences(differences(xs)) == xs` and `differences(fromDifferences(d)) == d` (TECH-PREFIX-04).
- `applyRangeAdds` equals adding each range element by element; overlapping deltas add and an empty range changes nothing (TECH-PREFIX-05).
- An update outside 0 .. n, a reversed update and a negative size are errors (TECH-PREFIX-06).
- `rectSum` equals the sum added cell by cell, for the whole grid, one cell and an empty rectangle (TECH-PREFIX-07).
- A rectangle outside the grid or reversed on either axis is an error (TECH-PREFIX-08).
- Ragged rows give `reRagged`; an empty grid and a grid of empty rows are accepted (TECH-PREFIX-09).

## Complexity
| Operation | Time | Space |
|---|---|---|
| `prefixOf`, n elements | O(n) | O(n) |
| `rangeSum` | O(1) | O(1) |
| `applyRangeAdds`, n elements and k updates | O(n + k) | O(n) |
| `prefixOf2D`, r rows and c columns | O(r c) | O(r c) |
| `rectSum` | O(1) | O(1) |

## Pitfalls
Using an inclusive right end with a table that has one extra leading zero (or the reverse): the answer is off by one element, and only when the range touches the end, so casual tests miss it.

```nim bad
let prefix = prefixOf(xs)
# "sum of xs[l..r] inclusive": the table is for half-open ranges, so this drops xs[r]
let total = prefix.rangeSum(l, r).value
```

Pick one convention (here half-open) and convert at the boundary: for an inclusive `l..r` ask for `rangeSum(l, r + 1)`.

```nim
import nimcs/fp/result
import nimcs/algo/prefix_sum

let xs = [10, 20, 30, 40]
let p = prefixOf(xs)
doAssert p.rangeSum(1, 3 + 1) == ok(20 + 30 + 40, SpanError)     # inclusive 1..3
doAssert p.rangeSum(1, 3) == ok(20 + 30, SpanError)               # half-open 1 ..< 3
```
