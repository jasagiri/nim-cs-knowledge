# Huffman coding

## Intent
Give each symbol a binary code word so that frequent symbols get short words and no word begins another, which makes the bit stream decodable without separators. The greedy idea: repeatedly merge the two lightest subtrees; the finished tree's left/right edges spell the words.

## Use when / avoid when
- Use it to teach greedy construction with a provable optimum among symbol-by-symbol prefix codes.
- Use it when symbol frequencies are known up front and skewed.
- Avoid it when you need a fixed-width code or random access into the encoded stream: use fixed-length codes.
- Avoid it when symbols are correlated (text with long repeats): dictionary methods exploit that, a symbol code cannot.
- This module returns code words as `'0'`/`'1'` strings for readability; a production coder packs bits.

## Nim shape
`buildCode(freqs)` takes (symbol, frequency) pairs in any order and returns `Result[HuffmanCode, HuffmanError]`. `HuffmanCode` is an immutable value holding the tree (a flat `seq` of nodes, no `ref`) and the word table. Ties are broken by weight, then by the smallest symbol inside the subtree; the subtree taken first becomes the `0` side. `encode` and `decode` return `Result`, so an unknown symbol or malformed bits is a value.

```nim
import nimcs/fp/result
import nimcs/algo/huffman

let code = buildCode(frequencies("abracadabra"))
doAssert code.isOk
let bits = code.value.encode("abracadabra")
doAssert bits.isOk
doAssert code.value.decode(bits.value) == ok("abracadabra", HuffmanError)
doAssert code.value.encode("z") == err(string, heUnknownSymbol)
```

built and read only through the functions.

```text
type HuffmanError = enum
  heEmptyInput,             ## no symbol to build a code from
  heBadFrequency,           ## a frequency below one
  heDuplicateSymbol,        ## the same symbol listed twice
  heWeightOverflow,         ## the total weight does not fit in an `int`
  heUnknownSymbol,          ## `encode` met a symbol that has no code word
  heBadBits                  ## `decode` met a character other than '0' or '1', a path that leads nowhere, or an unfinished code word
type HuffmanCode = object
func frequencies(text: string): seq[(char, int)]
func buildCode(freqs: openArray[(char, int)]): Result[HuffmanCode, HuffmanError]
func codeWords(code: HuffmanCode): seq[(char, string)]
func wordOf(code: HuffmanCode; c: char): Option[string]
func isPrefixFree(code: HuffmanCode): bool
func encode(code: HuffmanCode; text: string): Result[string, HuffmanError]
func decode(code: HuffmanCode; bits: string): Result[string, HuffmanError]
```

## Laws and invariants
- The code depends only on the multiset of (symbol, frequency) pairs, not on their order; a hand-derived example fixes the tie-break (CODING-HUFFMAN-01).
- No code word begins another (CODING-HUFFMAN-02).
- `decode(encode(t)) == t` for every text `t` built into the code (CODING-HUFFMAN-03).
- The weighted length equals the cost found by repeatedly merging the two smallest weights, the words fill the code space (Kraft sum 1) and a more frequent symbol never has a longer word (CODING-HUFFMAN-04).
- Empty input, a frequency below one, a repeated symbol and an overflowing total each give their own error (CODING-HUFFMAN-05).
- Encoding a symbol outside the code gives `heUnknownSymbol` (CODING-HUFFMAN-06).
- Decoding non-binary characters or bits that stop inside a word gives `heBadBits` (CODING-HUFFMAN-07).
- A single symbol gets the word `"0"`; only zero bits decode (CODING-HUFFMAN-08).

## Complexity
| Operation | Time | Space |
|---|---|---|
| `buildCode` for k distinct symbols | O(k log k) | O(k) |
| `encode`, text of n characters | O(n log k) (binary search in the word table) | O(output) |
| `decode`, b bits | O(b) | O(output) |

## Pitfalls
Breaking ties by whatever order the heap or hash table happens to give makes two runs (or two machines) produce different, equally short codes, so an encoder and a decoder built separately disagree.

```nim bad
import std/tables

var counts = initCountTable[char]()
for c in "abracadabra":
  counts.inc c
for c, n in counts:          # hash order decides the leaf order, so ties break differently per run
  discard (c, n)
```

Sort the symbols first and use a total order on (weight, smallest symbol), as `buildCode` does, or ship the frequency table (or the code lengths) with the data.

```nim
import nimcs/algo/huffman

let a = buildCode([('b', 2), ('a', 2), ('c', 1)])
let b = buildCode([('c', 1), ('a', 2), ('b', 2)])
doAssert a.value.codeWords == b.value.codeWords
```
