# External merge sort

## Intent
Sort data that does not fit in fast memory. Read as much as fits, sort it in memory and write it out as a sorted run; then merge several runs at a time with a heap until one run is left. The goal is to move every item as few times as possible, because on disk or over a network moving data costs far more than comparing it.

## Use when / avoid when
- Use the shape when the data lives on slow storage and a pass over it is the unit of cost: log files, database sort-merge joins, batch jobs.
- Use `merge_sort.md` or `heap_sort.md` when the data fits in memory.
- Avoid a fan-in larger than the number of buffers that memory can hold (one input buffer per run plus one output buffer); the model here counts items, not buffers.

## Nim shape
The external store is simulated by a sequence of runs (`Run` is a sorted `seq[int]`); no file is touched. `formRuns(data, memory)` cuts the input into chunks of at most `memory` items and sorts each. `mergeRuns(runs)` is a k-way merge driven by a heap. `externalSort(data, memory, fanIn)` runs both phases and returns the items with an `IoCost`.

Cost model: a pass reads each item once and writes it once. Run formation is one pass; each merge pass is one more. With r = ceil(n / memory) runs and fan-in k the number of merge passes is ceil(log_k r), so reads = writes = n * (1 + passes). `expectedMergePasses(r, k)` computes the closed form. Module: `src/nimcs/algo/external_sort.nim`.

```nim
import nimcs/fp/result
import nimcs/algo/external_sort

let r = externalSort(@[5, 3, 9, 1, 7, 2, 8], 3, 2)
doAssert r.isOk
doAssert r.value.items == @[1, 2, 3, 5, 7, 8, 9]
# runs [3,5,9] [1,2,7] [8]: 3 runs, then 2, then 1 -> two merge passes
doAssert r.value.cost.mergePasses == 2
doAssert r.value.cost.reads == 21
doAssert expectedMergePasses(3, 2) == 2
```

## Public API

Every exported symbol of `src/nimcs/algo/external_sort.nim`, generated by `nim apiSections` (the
tests fail when it drifts). `import nimcs/algo/external_sort` brings these names. A type they use from
another module (`Option`, `Result`, `Graph`) needs that module's import too, as in the example
above. A field marked `*` is readable outside the module; a type shown without fields is opaque,
built and read only through the functions.

```text
type ExtSortError = enum
  eeBadMemory,              ## memory must hold at least one item
  eeBadFanIn                 ## the fan-in must be at least 2 (a 1-way merge never ends)
type Run = seq[int]
type IoCost = object
  mergePasses*: int
  reads*: int                ## items read from the store, run formation included
  writes*: int               ## items written to the store, run formation included
type Sorted = object
  items*: seq[int]
  cost*: IoCost
func `==`(a, b: IoCost): bool
func formRuns(data: openArray[int]; memory: int): Result[seq[Run], ExtSortError]
func mergeRuns(runs: openArray[Run]): Run
func expectedMergePasses(runCount, fanIn: int): int
func externalSort(data: openArray[int]; memory, fanIn: int): Result[Sorted, ExtSortError]
```

## Laws and invariants
- The result equals the in-memory sort, for every data, memory and fan-in (EXTSORT-SORT-01).
- Sorting sorted output changes nothing (EXTSORT-SORT-02).
- Empty data, memory holding everything, and invalid parameters behave as stated (EXTSORT-SORT-03).
- Run formation gives ceil(n / memory) sorted, non-empty runs of at most `memory` items (EXTSORT-RUNS-01).
- The runs together hold exactly the input (EXTSORT-RUNS-02).
- `mergeRuns` of sorted runs is the sorted concatenation (EXTSORT-MERGE-01).
- Merge passes equal ceil(log_k r) and reads and writes both equal n * (1 + passes) (EXTSORT-COST-01).
- A larger fan-in never needs more passes (EXTSORT-COST-02).

## Complexity
Comparisons O(n log n) overall (each merge pass spends O(log k) per item). I/O: n * (1 + ceil(log_k (n / memory))) item reads and the same number of writes. Space in memory: `memory` items during run formation, one head per run during a merge; the simulation itself holds the whole input.

## Pitfalls
A fan-in of 1 never reduces the number of runs, so the loop never ends:

```nim bad
while runs.len > 1:
  runs = mergeGroupsOf(runs, 1)       # each group is one run: runs.len never shrinks
```

Fix: refuse a fan-in below 2 (`eeBadFanIn`). Another trap is merging by repeatedly scanning all run heads for the smallest, which costs O(k) per item instead of O(log k) with a heap.
