# Convex hull (Andrew's monotone chain)

## Intent
Find the smallest convex polygon that contains a set of points. Sort the points by (x, y), build the lower chain and the upper chain with a stack that drops the last point whenever it would make a clockwise or straight turn, and join the two chains. With integer coordinates the only arithmetic is the cross product, so the answer is exact.

## Use when / avoid when
- Use it for the outline of a point set, for farthest pairs (rotating calipers), for bounding polygons and for collision shapes with integer coordinates.
- Use a robust-predicate library when the coordinates are floating point: `cross` would round and the hull could be wrong.
- Avoid it when you need the collinear boundary points as well: this version removes them.

## Nim shape
`convexHull(points)` returns `Result[seq[Point], HullError]`: the vertices counter-clockwise starting at the smallest (x, y) point, no three consecutive collinear, duplicates ignored. Coordinates are limited to `MaxCoord` (10^9) so a cross product fits in `int`; beyond that the call fails instead of overflowing. `cross(o, a, b)` is exported. Module: `src/nimcs/algo/convex_hull.nim`.

```nim
import nimcs/fp/result
import nimcs/algo/convex_hull

let cloud = @[point(0, 0), point(4, 0), point(4, 4), point(0, 4),
              point(2, 2), point(2, 0), point(0, 0)]
let hull = convexHull(cloud)
doAssert hull.isOk
doAssert hull.value == @[point(0, 0), point(4, 0), point(4, 4), point(0, 4)]
doAssert cross(point(0, 0), point(1, 0), point(1, 1)) > 0     # a left turn
```

built and read only through the functions.

```text
const MaxCoord = 1000000000
type Point = object
  x*, y*: int
type HullError = enum
  heCoordinateTooLarge       ## a coordinate is outside -MaxCoord .. MaxCoord
func point(x, y: int): Point
func `==`(a, b: Point): bool
func `<`(a, b: Point): bool
func cross(o, a, b: Point): int
func convexHull(points: openArray[Point]): Result[seq[Point], HullError]
```

## Laws and invariants
- The hull vertices are exactly the extreme points of the input (checked against a cubic triangle-membership oracle) (GEO-CONVEXHULL-01).
- The hull starts at the smallest point and every turn is strictly counter-clockwise (GEO-CONVEXHULL-02).
- Every input point is on or left of every hull edge and every vertex is an input point (GEO-CONVEXHULL-03).
- Degenerate inputs give the empty hull, a single point, or the two endpoints of a collinear set (GEO-CONVEXHULL-04).
- The hull is idempotent and does not depend on input order or duplicates (GEO-CONVEXHULL-05).
- The sign of `cross` is the turn direction and is exact up to `MaxCoord` (GEO-CONVEXHULL-06).
- Coordinates beyond `MaxCoord` are refused (GEO-CONVEXHULL-07).

## Complexity
Time O(n log n) for the sort, then O(n) for the two chains (each point is pushed and popped at most once per chain). Space O(n).

## Pitfalls
Popping only on a clockwise turn (`< 0`) keeps collinear points on the boundary and, for a collinear input, returns a chain that doubles back:

```nim bad
while result.len >= 2 and cross(result[^2], result[^1], p) < 0:   # keeps straight turns
  result.delete(result.high)
```

Fix: pop on `<= 0` as `convexHull` does, so only strict left turns survive. A second trap is computing the cross product in `int32` or from unchecked 64-bit coordinates; the limit `MaxCoord` is what makes the difference of two products fit.
