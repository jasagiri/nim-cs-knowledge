# Approximation algorithm: 2-approximate vertex cover

## Intent
Some problems have no known fast exact algorithm, but a fast algorithm can be proved never to be far from optimal. A vertex cover is a set of vertices touching every edge; finding a smallest one is NP-hard. Take edges in order, and whenever an edge has both ends uncovered, put both ends in the cover. The matched edges are disjoint and any cover needs one end of each, so the optimum is at least the matching size m while the answer has at most 2m vertices.

## Use when / avoid when
- Use it when a cover of any reasonable size is needed quickly (monitoring placement, conflict sets) and a guaranteed factor of 2 is acceptable.
- Use an exact search or `backtracking.md` for small graphs, where the optimum is affordable.
- Avoid it when the factor matters: the bound is tight, so on some graphs the answer really is twice the optimum (a path on four vertices).

## Nim shape
`maximalMatchingCover(g)` returns the matching and the cover derived from it, `vertexCover2Approx(g)` just the ascending cover, both as `Result[_, GraphError]` (a directed graph is refused with `geNotUndirected`). `isVertexCover(g, set)` is the checker. Edges are scanned in the graph's own order, so the answer is deterministic. A self-loop is covered only by its own vertex, so it joins the matching with that single vertex. Module: `src/nimcs/algo/approximation.nim`.

```nim
import nimcs/fp/result
import nimcs/algo/graph
import nimcs/algo/approximation

let path = buildGraph(4, @[edge(0, 1), edge(1, 2), edge(2, 3)], gkUndirected).value
let cover = vertexCover2Approx(path)
doAssert cover.isOk
doAssert cover.value == @[0, 1, 2, 3]           # the optimum {1, 2} has size 2: ratio 2
doAssert path.isVertexCover(@[1, 2])
doAssert path.isVertexCover(cover.value)
```

## Laws and invariants
- Every edge has an end in the cover (APPROX-VC-01).
- The matching is vertex-disjoint and the cover has at most twice its size (APPROX-VC-02).
- On graphs of up to 8 vertices the cover is at most twice the exact minimum found by brute force (APPROX-VC-03).
- The ratio 2 is reached on a path of four vertices (APPROX-VC-04).
- No edges give an empty cover; a self-loop puts its vertex in the cover (APPROX-VC-05).
- A directed graph is refused (APPROX-VC-06).
- `isVertexCover` accepts exactly the sets touching every edge (APPROX-VC-07).
- The result is deterministic (APPROX-VC-08).

## Complexity
Time O(V + E) after the edge list is produced; space O(V). The proof of the ratio is the matching argument above, not a measurement.

## Pitfalls
Adding only one end of each matched edge looks like it halves the cover but can leave edges uncovered:

```nim bad
if not covered[e.source] and not covered[e.target]:
  cover.add e.source                  # the edge to e.target may stay uncovered later
```

Fix: take both ends, as `maximalMatchingCover` does; that is what makes every later edge either covered already or matched. Another trap is picking the highest-degree vertex repeatedly: that greedy rule is natural but has no constant factor guarantee.
