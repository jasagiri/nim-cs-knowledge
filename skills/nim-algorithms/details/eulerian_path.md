# Eulerian path and circuit (Hierholzer)

## Intent
Walk every edge of a graph exactly once. A trail exists exactly when the edges form one connected piece and the degrees allow it; Hierholzer's algorithm builds it by following unused edges until it is stuck, which can only happen back at the start of a closed loop, then splicing in the loops found on the way back.

## Use when / avoid when
- Use it for route inspection, stroke-order puzzles, plotter paths and de Bruijn sequences.
- Use `dfs.md` or `graph.md` plus a search when you need a path that visits every vertex once (a Hamiltonian path); that problem is NP-hard and has nothing to do with this one.
- Avoid it when edges carry costs that must be minimised: that is the route-inspection (Chinese postman) problem, which first duplicates edges to fix the degrees.

## Nim shape
`eulerianPath(g)` returns `Option[seq[int]]`: the vertices of a trail using every edge once (one more entry than edges), or none. `eulerianCircuit(g)` additionally requires the trail to be closed. Both work on directed and undirected `Graph`s, with parallel edges and self-loops; a graph with no edges has the empty trail. The start vertex is the unbalanced (directed) or odd-degree (undirected) vertex if there is one, else the smallest vertex with an edge. Module: `src/nimcs/algo/eulerian_path.nim`.

```nim
import std/options
import nimcs/fp/result
import nimcs/algo/graph
import nimcs/algo/eulerian_path

let square = buildGraph(4, @[edge(0, 1), edge(1, 2), edge(2, 3), edge(3, 0)], gkUndirected).value
doAssert eulerianCircuit(square) == some(@[0, 1, 2, 3, 0])

let path = buildGraph(3, @[edge(0, 1), edge(1, 2)], gkUndirected).value
doAssert eulerianPath(path) == some(@[0, 1, 2])
doAssert eulerianCircuit(path).isNone
```

## Laws and invariants
- A trail found walks every edge exactly once and has edges + 1 vertices (GRAPH-EULER-01).
- A trail is found exactly when brute-force backtracking finds one; wrong degrees or disconnected edges give none (GRAPH-EULER-02).
- `eulerianCircuit` is closed and exists exactly when a closed trail does (GRAPH-EULER-03).
- Parallel edges and self-loops are each walked once (GRAPH-EULER-04).
- No edges gives the empty trail (GRAPH-EULER-05).
- The answer is deterministic (GRAPH-EULER-06).

## Complexity
Time O(V + E) after sorting the edge list the graph already keeps; space O(V + E) for the adjacency with edge ids, the used flags and the stack.

## Pitfalls
Checking only the degrees accepts a graph whose edges lie in two components, and running Hierholzer without the degree check can return a vertex list that is not a trail:

```nim bad
# degrees are fine, but the second triangle is never reached
let trail = hierholzer(g)
return some(trail)            # trail.len != edgeCount + 1
```

Fix: check the degree conditions first, then require the produced trail to have `edgeCount + 1` vertices, as `eulerianPath` does. For an undirected graph give each edge one id shared by both directions and mark it used when either direction is taken; otherwise the edge is walked twice.
