# Asymptotic and amortized analysis

## Intent
Say how the cost of an algorithm grows with the input, and check the claim by counting operations (comparisons, copies, bit flips), which is exact and repeatable, rather than by timing. Asymptotic notation drops constants and small inputs; amortized analysis spreads the cost of rare expensive steps over the cheap ones around them.

## Use when / avoid when
- Use counts to confirm a complexity claim you are about to write in a doc comment (a loop pair gives n(n-1)/2, a binary search gives at most floor(log2 n) + 1 probes).
- Use the aggregate method (total cost over n operations divided by n) first; use a potential function when the aggregate is hard to see.
- Avoid it as a proof: `isBigOOn` checks a stated constant over a finite range, so it can refute a wrong claim but only supports a right one.
- Avoid counting when the cost is dominated by memory or the cache: the count then misses the effect; measure time with a benchmark.
- Avoid amortized bounds where a single slow operation matters (a real-time loop): amortized O(1) still allows one O(n) step.

## Nim shape
Everything is a pure `func` returning counts. `linearSearchSteps`, `binarySearchSteps` and `naiveDuplicateComparisons` count work in a real algorithm. `appendSteps(n, growth)` simulates n appends to a growing array under `gDoubling` or `gByOne` and returns the cost of each; `potential` and `doublingAmortizedCosts` apply the potential method; `incrementBits` and `counterFlips` do the same for a binary counter. `isBigOOn` and `isBigOmegaOn` take the two cost functions as `noSideEffect` procs.

```nim
import nimcs/algo/analysis

# aggregate method: 100 doubling appends cost at most 3 per append, growing by one costs far more
doAssert appendSteps(100, gDoubling).totalCost <= 300
doAssert appendSteps(100, gByOne).totalCost == 5050

# potential method: every amortized cost is at most 3, though single appends cost up to 65
for a in doublingAmortizedCosts(100):
  doAssert a <= 3

func quadratic(n: int): int {.raises: [].} = n * n + 10 * n
func square(n: int): int {.raises: [].} = n * n
doAssert isBigOOn(quadratic, square, 11, 1, 1000)       # holds with c = 11
doAssert not isBigOOn(quadratic, square, 1, 1, 1000)    # refuted with c = 1
```

## Public API

Every exported symbol of `src/nimcs/algo/analysis.nim`, generated by `nim apiSections` (the
tests fail when it drifts). `import nimcs/algo/analysis` brings these names. A type they use from
another module (`Option`, `Result`, `Graph`) needs that module's import too, as in the example
above. A field marked `*` is readable outside the module; a type shown without fields is opaque,
built and read only through the functions.

```text
type Growth = enum
  gDoubling,                ## a full array gets twice the capacity (capacity 0 becomes 1)
  gByOne                     ## a full array gets one more slot
type AppendStep = object
  cost*: int                 ## 1 for the write plus the elements copied by a resize
  size*: int                 ## elements held
  capacity*: int             ## slots allocated
func ceilLog2(n: int): Option[int]
func linearSearchSteps(xs: openArray[int]; x: int): int
func binarySearchSteps(sortedXs: openArray[int]; x: int): int
func naiveDuplicateComparisons(xs: openArray[int]): tuple[found: bool, comparisons: int]
func isBigOOn(f, g: Measure; c, n0, upTo: int): bool
func isBigOmegaOn(f, g: Measure; c, n0, upTo: int): bool
func appendSteps(n: int; growth: Growth): seq[AppendStep]
func totalCost(steps: openArray[AppendStep]): int
func potential(size, capacity: int): int
func doublingAmortizedCosts(n: int): seq[int]
func incrementBits(bits: seq[bool]): tuple[bits: seq[bool], flips: int]
func counterFlips(n: int): int
```

## Laws and invariants
- Searching n distinct numbers pair by pair makes exactly n(n-1)/2 comparisons; an early duplicate stops the count (ANALYSIS-ASYMP-01).
- Binary search makes at most floor(log2 n) + 1 probes, so 1023 items need at most 10 (ANALYSIS-ASYMP-02).
- The witness checks accept a right constant and refute a wrong one (ANALYSIS-ASYMP-03).
- `ceilLog2(n)` is the k with 2^(k-1) < n <= 2^k, and none below 1 (ANALYSIS-ASYMP-04).
- Linear search takes position plus one steps, or the length when absent (ANALYSIS-ASYMP-05).
- n doubling appends cost at most 3n in total (ANALYSIS-AMORT-01).
- n appends growing by one cost exactly n(n+1)/2, more than 3n from n = 6 (ANALYSIS-AMORT-02).
- With the potential 2 * size - capacity every amortized cost is at most 3, the potential is never negative and the amortized costs add up to at least the real total (ANALYSIS-AMORT-03).
- n increments of a binary counter flip exactly 2n - popcount(n) bits; an increment yields the next number and keeps the old counter; the increment of an all-ones counter flips every bit (ANALYSIS-AMORT-04).

## Complexity
| Operation | Time | Space |
|---|---|---|
| `linearSearchSteps` | O(n) | O(1) |
| `binarySearchSteps` | O(log n) | O(1) |
| `naiveDuplicateComparisons` | O(n^2) worst case | O(1) |
| `appendSteps(n, ...)`, `doublingAmortizedCosts(n)` | O(n) | O(n) |
| `counterFlips(n)` | O(n log n) simulated (the flips themselves total under 2n) | O(log n) |

The counted algorithms: doubling append is amortized O(1) per append; growing by one is amortized O(n); a binary counter increment is amortized O(1).

## Pitfalls
Calling a bound "amortized" when it is an average over random inputs, or quoting amortized O(1) where an old version of the structure is reused: with persistent versions the same expensive step can be replayed many times.

```nim bad
# "append is O(1)": true amortized, false per call; this loop copies on every resize point
var xs: seq[int]
for i in 0 ..< n:
  xs.add i                  # one call near each power of two costs O(len)
echo "worst call: O(1)"     # wrong: the worst single call is O(n)
```

State which kind of bound it is, and test the aggregate with a count.

```nim
import nimcs/algo/analysis

let steps = appendSteps(64, gDoubling)
var worst = 0
for s in steps:
  worst = max(worst, s.cost)
doAssert worst == 33                   # one single append copies 32 elements
doAssert steps.totalCost <= 3 * 64     # yet the average stays constant
```
