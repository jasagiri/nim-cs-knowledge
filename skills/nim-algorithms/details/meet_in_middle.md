# Meet in the middle

## Intent
Cut an exponential search in half. For subset sum, split the items into two halves, list all subset sums of each half (at most 2^(n/2) each), sort them, and combine: a subset of the whole is one subset of each half, so a target is reached exactly when some left sum plus some right sum equals it, which a binary search on the sorted right list finds.

## Use when / avoid when
- Use it for subset-sum style questions with about 30 to 40 items and large values: counting subsets with a given sum, the nearest reachable sum, partition into two nearly equal parts.
- Use dynamic programming (`knapsack.md`) when the values are small: a table of size target is cheaper.
- Use `backtracking.md` when pruning cuts the search far below 2^n, or when the actual subsets (not only sums or counts) are needed.

## Nim shape
`countSubsetSum(items, target)`, `subsetSumExists(items, target)` and `closestSubsetSum(items, target)` return `Result[_, MitmError]`. Subsets are counted by index (equal items are distinct choices) and the empty subset has sum 0. To keep every sum inside `int` the module accepts at most `MaxItems` items of absolute value at most `MaxItemValue`, and a target within `MaxTarget`; otherwise the error says which limit broke. Module: `src/nimcs/algo/meet_in_middle.nim`.

```nim
import nimcs/fp/result
import nimcs/algo/meet_in_middle

doAssert countSubsetSum(@[1, 2, 3, 4], 5).value == 2        # {1, 4} and {2, 3}
doAssert subsetSumExists(@[3, 34, 4, 12, 5, 2], 9).value
doAssert closestSubsetSum(@[10, 20], 15).value == 10        # tie: the smaller sum
doAssert countSubsetSum(@[MaxItemValue + 1], 0).isErr
```

## Public API

Every exported symbol of `src/nimcs/algo/meet_in_middle.nim`, generated by `nim apiSections` (the
tests fail when it drifts). `import nimcs/algo/meet_in_middle` brings these names. A type they use from
another module (`Option`, `Result`, `Graph`) needs that module's import too, as in the example
above. A field marked `*` is readable outside the module; a type shown without fields is opaque,
built and read only through the functions.

```text
const MaxItems: int = 40
const MaxItemValue: int = 1000000000000'i64
const MaxTarget: int = 1000000000000000'i64
type MitmError = enum
  meTooManyItems,           ## more than MaxItems items
  meItemTooLarge,           ## an item has absolute value above MaxItemValue
  meTargetTooLarge           ## the target has absolute value above MaxTarget
func countSubsetSum(items: openArray[int]; target: int): Result[int, MitmError]
func subsetSumExists(items: openArray[int]; target: int): Result[bool, MitmError]
func closestSubsetSum(items: openArray[int]; target: int): Result[int, MitmError]
```

## Laws and invariants
- The count equals brute force over all 2^n subsets, equal items counted separately (MITM-COUNT-01).
- Reordering the items does not change the count (MITM-COUNT-02).
- Existence is true exactly when the count is positive (MITM-EXISTS-01).
- The closest sum equals brute force, the smaller sum winning a tie (MITM-CLOSEST-01, MITM-CLOSEST-02).
- Each limit has its own error and the limits themselves are accepted (MITM-LIMIT-01).
- Thirty equal items give the binomial counts without enumerating 2^30 subsets (MITM-SCALE-01).

## Complexity
Time O(2^(n/2) * n) (generating and sorting the sums of a half, plus one binary search per left sum) instead of O(2^n * n). Space O(2^(n/2)). For n = 40 that is about a million sums per half.

## Pitfalls
Searching the right list for a left sum without sorting it, or using a linear scan, brings back the quadratic cost, and a hand-rolled binary search that returns any one match counts a repeated sum once:

```nim bad
let at = right.binarySearch(target - l)     # one index, even if the sum repeats
if at >= 0: inc total
```

Fix: count a run of equal sums with `upperBound(want) - lowerBound(want)`, as `countSubsetSum` does. For the nearest sum, look at both neighbours of the insertion point, not only the one at or above it.
