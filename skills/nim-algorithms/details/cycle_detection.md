# Cycle detection (Floyd and three-colour search)

## Intent
A sequence produced by a function on a finite set must repeat; the question is where. Floyd's tortoise and hare finds the length of the tail before the cycle, the length of the cycle and its first value using two cursors and constant extra memory. For a directed graph the same question is answered by a depth-first search that colours vertices white, grey (on the current path) or black (finished): an arc into a grey vertex closes a cycle.

## Use when / avoid when
- Use `floydRho` for a linked list that may loop, a pseudo-random generator, or any state machine whose next state is a function of the current one and whose state space is small and indexable.
- Use `findCycle` to ask whether a directed graph has a cycle and to name one.
- Use `topo_sort.md` when an order of the vertices is wanted as well: it also reports a cycle when there is no order, and the two answers always agree (CYCLE-GRAPH-02).
- Avoid `floydRho` when the states are not integers in 0 ..< n; hash the states into indices first, or remember visited states in a set.

## Nim shape
`floydRho(f, start)` takes the function as a table (`f[i]` is the image of `i`) and returns `Option[Rho]` with `tail`, `cycle` and `entry`; it is none when the table is not a self-map of 0 ..< n. `iterateFunction(f, start, steps)` applies `f` `steps` times in O(n) using the cycle. `findCycle(g)` returns `Result[Option[seq[int]], CycleError]` and refuses an undirected graph. Module: `src/nimcs/algo/cycle_detection.nim`.

```nim
import std/options
import nimcs/fp/result
import nimcs/algo/graph
import nimcs/algo/cycle_detection

# 0 -> 1 -> 2 -> 3 -> 4 -> 2 ...
let shape = floydRho(@[1, 2, 3, 4, 2], 0)
doAssert shape.get == Rho(tail: 2, cycle: 3, entry: 2)
doAssert iterateFunction(@[1, 2, 3, 4, 2], 0, 1_000_000_000).isSome

let g = buildGraph(4, @[edge(0, 1), edge(1, 2), edge(2, 3), edge(3, 1)], gkDirected).value
doAssert findCycle(g).value == some(@[1, 2, 3])
```

built and read only through the functions.

```text
type Rho = object
  tail*: int
  cycle*: int
  entry*: int                ## the first value of the sequence that lies on the cycle
type CycleError = enum
  ceNotDirected              ## the graph search is defined for directed graphs only
func `==`(a, b: Rho): bool
func floydRho(f: openArray[int]; start: int): Option[Rho]
func iterateFunction(f: openArray[int]; start, steps: int): Option[int]
func findCycle(g: Graph): Result[Option[seq[int]], CycleError]
```

## Laws and invariants
- `floydRho` equals the first-seen-step oracle on every table and start (CYCLE-FLOYD-01).
- The entry is reached after `tail` steps and returns after exactly `cycle` steps; `tail + cycle <= n` (CYCLE-FLOYD-02).
- `iterateFunction` equals single stepping and works for huge counts (CYCLE-FLOYD-03).
- A permutation has no tail (CYCLE-FLOYD-04).
- A table with an image or start out of range gives none (CYCLE-FLOYD-05).
- A cycle returned by `findCycle` is a real cycle starting at its smallest vertex (CYCLE-GRAPH-01).
- A directed graph has a cycle exactly when `topoSort` fails (CYCLE-GRAPH-02).
- A self-loop is a one-vertex cycle; a DAG has none; repeated calls agree (CYCLE-GRAPH-03).
- An undirected graph is refused (CYCLE-GRAPH-04).

## Complexity
Floyd: time O(tail + cycle) <= O(n), extra space O(1). `iterateFunction`: O(n). `findCycle`: time O(V + E), space O(V) for the colours and the current path.

## Pitfalls
Starting both cursors at `start` makes the loop `while tortoise != hare` stop immediately:

```nim bad
var tortoise = start
var hare = start
while tortoise != hare:      # false at once: never advances
  tortoise = f[tortoise]
  hare = f[f[hare]]
```

Fix: start the tortoise one step ahead (`f[start]`) and the hare two steps ahead (`f[f[start]]`) as `floydRho` does. A second trap is running the graph search on an undirected graph: each edge looks like a two-vertex cycle, so `findCycle` refuses it.
