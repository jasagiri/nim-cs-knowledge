# Time as input (two clocks, read once at the edge, no zero time)

## Intent
A program asks the time for two reasons. To record or show a moment (a file's mtime, a log line, the name of a backup) it needs the wall clock, which jumps when NTP or a person sets it. To wait (a quiet period, a retry delay, a deadline) it needs the monotonic clock, which never jumps and means nothing outside the process. Keep the two as distinct types, read both once where an operation begins as one `Now`, and pass that value to everything that decides. A time that has not come yet is `none`, never 0.

## Use when / avoid when
- Use whenever code waits, times out, debounces or retries, and also records when it did something: the two needs pull toward different clocks.
- Use when a test must reach a moment ("the campaign starts next Monday", "an hour after the last change") without waiting for it or setting the machine's clock.
- Use with `dependency_record.md` when the clock itself must be swappable; this page is about which time the clock gives and where it is read, not about how it is passed.
- Avoid wrapping the clock in a global that tests replace (a fake-timer library, a mutable `now` proc): a test that forgets to restore it leaks a stopped clock into the next one, and tests that run in parallel fight over it.
- Avoid using the monotonic value for anything stored or sent to another machine; its origin differs per process and per boot.

## Nim shape
The module is `src/nimcs/patterns/time_as_input.nim`. `WallNs`, `MonoNs` and `Span` are `distinct int64`: only `MonoNs - MonoNs` gives a `Span`, only `MonoNs + Span` gives a `MonoNs`, and a wall time compares only with a wall time. `Now` holds one reading of both clocks; `sample()` is the edge that reads them, the only routine here that is not a `func`. The example decides when to send local changes: `SendPolicy` is sealed (`initSendPolicy` refuses a span that is not positive), `Sender` is plain data whose "never happened" times are `Option[MonoNs]`, and `decide`, `changed`, `sent` and `stamp` are `func`s of a `Now`, so the compiler refuses a clock read inside them.

```nim
import nimcs/fp/result
import nimcs/patterns/time_as_input

let p = initSendPolicy(seconds(2), seconds(5)).value
let t0 = Now(wall: WallNs(1_700_000_000_000_000_000), mono: MonoNs(1_000_000_000))
let s = idle().changed(t0)
doAssert p.decide(s, t0.after(millis(500))) == acWait     # not quiet yet
doAssert p.decide(s, t0.after(seconds(2))) == acSend      # quiet for 2 s
# the wall clock set back an hour: the wait is measured on the monotonic clock, so nothing changes
doAssert p.decide(s, t0.after(seconds(2)).wallJumped(-3_600_000_000_000)) == acSend
```

A failed send waits `retryAfter` on the monotonic clock, and what is recorded about a send is the wall clock of the same reading:

```nim
import std/options
import nimcs/fp/result
import nimcs/patterns/time_as_input

let p = initSendPolicy(seconds(2), seconds(5)).value
let t0 = Now(wall: WallNs(1_700_000_000_000_000_000), mono: MonoNs(1_000_000_000))
let tried = t0.after(seconds(3))
let s = p.sent(idle().changed(t0), tried, soFailed)
doAssert s.pending and s.retryAt.isSome
doAssert p.decide(s, tried.after(seconds(4))) == acWait
doAssert p.decide(s, tried.after(seconds(5))) == acSend
doAssert stamp(tried) == tried.wall
```

The shell reads the clocks once per round and hands the value in:

```nim
import nimcs/fp/result
import nimcs/patterns/time_as_input

let p = initSendPolicy(seconds(2), seconds(5)).value
var s = idle().changed(sample())
let now = sample()                 # one reading for the whole round
if p.decide(s, now) == acSend:
  s = p.sent(s, now, soSucceeded)
```

## Public API

Every exported symbol of `src/nimcs/patterns/time_as_input.nim`, generated by `nim apiSections` (the
tests fail when it drifts). `import nimcs/patterns/time_as_input` brings these names. A type they use from
another module (`Option`, `Result`, `Graph`) needs that module's import too, as in the example
above. A field marked `*` is readable outside the module; a type shown without fields is opaque,
built and read only through the functions.

```text
type WallNs = distinct int64
type MonoNs = distinct int64
type Span = distinct int64
type Now = object
  wall*: WallNs
  mono*: MonoNs
type SendPolicy {.requiresInit.} = object
type PolicyError = enum
  peQuietNotPositive, peRetryNotPositive
type Sender = object
  pending*: bool             ## local changes not yet sent
  lastChange*: Option[MonoNs] ## none: no change since the sender began
  retryAt*: Option[MonoNs]   ## the end of the wait after a failure; none: no wait
type Action = enum
  acWait, acSend
type SendOutcome = enum
  soSucceeded, soFailed
func `==`(a, b: WallNs): bool
func `<`(a, b: WallNs): bool
func `<=`(a, b: WallNs): bool
func `==`(a, b: MonoNs): bool
func `<`(a, b: MonoNs): bool
func `<=`(a, b: MonoNs): bool
func `==`(a, b: Span): bool
func `<`(a, b: Span): bool
func `<=`(a, b: Span): bool
func `-`(later, earlier: MonoNs): Span
func `+`(t: MonoNs; d: Span): MonoNs
func millis(n: int64): Span
func seconds(n: int64): Span
func after(n: Now; d: Span): Now
func wallJumped(n: Now; byNs: int64): Now
func initSendPolicy(quiet, retryAfter: Span): Result[SendPolicy, PolicyError]
func idle(): Sender
func changed(s: Sender; now: Now): Sender
func decide(p: SendPolicy; s: Sender; now: Now): Action
func sent(p: SendPolicy; s: Sender; now: Now; outcome: SendOutcome): Sender
func stamp(now: Now): WallNs
proc sample(): Now
```

## Laws and invariants
Why this is testable: every decision is a `func` of a `Now`, so a property can build any reading, including one where only the wall clock moved.
- Moving only the wall clock changes neither the decision nor the wait after a failure (PAT-TIMEASINPUT-01).
- With a pending change and no wait, it sends exactly when the change is `quiet` old (PAT-TIMEASINPUT-02).
- After a failure it waits exactly `retryAfter`, keeping the change pending (PAT-TIMEASINPUT-03).
- A success clears only what was in the send; the same inputs give the same decision; the record is the wall clock of the same reading (PAT-TIMEASINPUT-04).
- Policies need positive spans, `(t + d) - t == d`, the policy is sealed, and the two clocks do not mix (PAT-TIMEASINPUT-05).

## Complexity
Every routine is O(1). `Now` is two integers; reading it costs two system calls, once per operation instead of once per check.

## Pitfalls
Waiting on the wall clock, reading it in several places, and using 0 for "never":

```nim bad
import std/times

var lastChange = Time()             # 0: 1970, which also reads as "long ago"
var retryAt = Time()

proc shouldSend(pending: bool): bool =
  if getTime() < retryAt: return false   # set the clock back an hour: no send for an hour
  pending and getTime() - lastChange > initDuration(seconds = 2)   # a second read, a different moment
```

The same mistake in stored data: a record built without its time gets 0 and shows as 1970 (`Leaf(kind: ekDir, mode: 0o755)` with the `mtimeNs` left out). Build such records through a constructor that takes the time, and count hand-built ones in a test if the type cannot require it: `{.requiresInit.}` on a field type makes `seq` and `Table` of the record warn `UnsafeDefault` and `UnsafeSetLen` inside the standard library.

Fix: measure waits as `MonoNs` differences, read one `Now` at the edge, keep "not yet" as `none`, and take recorded times from `now.wall`.
