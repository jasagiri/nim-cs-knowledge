# Replace conditional with polymorphism

## Intent
A record with a tag and every field of every kind, plus routines that ask the tag in an `if` chain, spreads one decision over many places and ends each chain in a quiet default. The refactoring gives each kind its own data and moves the decision to one closed place. In this Nim style "polymorphism" is not inheritance or `method`: it is an object variant with an exhaustive `case`, or a record of procs that travels with the value.

## Use when / avoid when
- Use an object variant when the set of kinds is closed and the operations grow: the compiler then lists every `case` that forgot the new kind.
- Use a record of procs (`dependency_record.md`) when new kinds arrive from outside the module and the operations are few and fixed.
- Avoid when there are two kinds and one operation: an `if` is clearer than a type.
- Avoid inheritance and `method`: they hide the list of kinds and the repository's style forbids them (ADR-NCK-0002 S3).

## Nim shape
`src/nimcs/patterns/replace_conditional_with_polymorphism.nim`. `FlatParcel` and `costBefore` are the before: a `kind` tag, a weight and a distance that means nothing for a standard parcel. `Parcel` is the object variant (a field exists only for the kind that owns it) and `cost` has one branch per kind with no `else`. `Tariff` is the record of procs, built by `standard`, `express` and `pickup`. `toParcel` and `toTariff` are the migration steps, and the test compares all three shapes on generated parcels.

```nim
import nimcs/patterns/replace_conditional_with_polymorphism

let flat = FlatParcel(kind: kExpress, weightG: 250, distanceKm: 10)
let viaVariant = flat.toParcel.cost
let viaRecord = flat.toTariff.cost
doAssert flat.costBefore == viaVariant and viaVariant == viaRecord
doAssert viaVariant == 500 + 3 * 3 * 2 + 10 * 2
doAssert Parcel(kind: kPickup).cost == 0
```

## Public API

Every exported symbol of `src/nimcs/patterns/replace_conditional_with_polymorphism.nim`, generated by `nim apiSections` (the
tests fail when it drifts). `import nimcs/patterns/replace_conditional_with_polymorphism` brings these names. A type they use from
another module (`Option`, `Result`, `Graph`) needs that module's import too, as in the example
above. A field marked `*` is readable outside the module; a type shown without fields is opaque,
built and read only through the functions.

```text
type Kind = enum
  kStandard, kExpress, kPickup
type FlatParcel = object
  kind*: Kind
  weightG*: int
  distanceKm*: int
type Parcel = object
  case kind*: Kind
  of kStandard:
    weightG*: int
  of kExpress:
    expressWeightG*: int
    distanceKm*: int
  of kPickup:
    nil
type Tariff = object
  price*: proc (): int {.noSideEffect, raises: [].}
func costBefore(p: FlatParcel): int
func cost(p: Parcel): int
func toParcel(p: FlatParcel): Parcel
func standard(weightG: int): Tariff
func express(weightG, distanceKm: int): Tariff
func pickup(): Tariff
func toTariff(p: FlatParcel): Tariff
func cost(t: Tariff): int
func total(ps: openArray[Parcel]): int
```

## Laws and invariants
- The object variant gives the old chain's cost for every flat parcel (PAT-REPLACECONDITIONALWITHPOLYMORPHISM-01).
- The record of procs gives the old chain's cost for every flat parcel (PAT-REPLACECONDITIONALWITHPOLYMORPHISM-02).
- The total of a list is the sum of the old costs, and a pickup adds nothing (PAT-REPLACECONDITIONALWITHPOLYMORPHISM-03).
- Known parcels cost the cents of the rate card, and a negative weight counts as zero (PAT-REPLACECONDITIONALWITHPOLYMORPHISM-04).
- A `case` that leaves out one kind does not compile (PAT-REPLACECONDITIONALWITHPOLYMORPHISM-05).

## Complexity
Every shape costs O(1) per parcel. The record of procs allocates a closure per value; the variant allocates nothing and is the one to choose when a list of many small values is processed.

## Pitfalls
The common mistake is to keep the chain and end it with `else`: a kind added later falls into the last branch and gets a wrong answer without any error.

```nim bad
func cost(p: FlatParcel): int =
  if p.kind == kStandard: p.weightG div 100 * 3
  elif p.kind == kExpress: 500 + p.distanceKm * 2
  else: 0   # a new kind lands here silently
```

Switch on the variant's kind with no `else`, so that a new kind is a compile error at every `case`:

```nim
import nimcs/patterns/replace_conditional_with_polymorphism

func label(p: Parcel): string =
  case p.kind
  of kStandard: "standard"
  of kExpress: "express"
  of kPickup: "pickup"

doAssert Parcel(kind: kPickup).label == "pickup"
```

Also do not export the variant's discriminator as mutable: build a new value instead of assigning `kind`.
