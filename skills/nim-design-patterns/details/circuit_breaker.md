# Circuit breaker

## Intent
Calling a dependency that keeps failing makes every caller wait for a timeout and keeps the dependency loaded while it tries to recover. A breaker watches the outcomes and refuses calls for a while once failures persist, then lets one probe call through to find out whether the dependency is back. Here the breaker is an object variant (closed, open, half-open) whose transitions are pure functions of the breaker, the config and the time passed in.

## Use when / avoid when
- Use around calls to a remote service, a database or any dependency that can be down for longer than one retry.
- Use together with `retry_backoff.md`: backoff spaces out the retries of one caller, the breaker stops every caller once the failures are persistent.
- Avoid it for failures caused by the request itself (a bad argument): they say nothing about the dependency's health, so do not report them as failures.
- Avoid a breaker per call site when many sites share one dependency; share one value (or one per dependency) so they see the same failures.

## Nim shape
`src/nimcs/patterns/circuit_breaker.nim`. `Breaker` is an object variant: `bsClosed` carries the count of consecutive failures, `bsOpen` the tick it opened, `bsHalfOpen` a flag saying the probe is out. `initConfig(failureThreshold, openTicks)` validates the parameters. `allow(breaker, config, now)` returns the new breaker and a `Decision`; `recordSuccess` and `recordFailure(breaker, config, now)` take the outcome of a call. The clock is an argument (see `time_as_input.md`); the breaker never reads it.

```nim
import nimcs/patterns/circuit_breaker

let cfg = initConfig(2, 10).value
var b = closedBreaker()
b = b.recordFailure(cfg, 0)
b = b.recordFailure(cfg, 1)          # second consecutive failure: open at tick 1
doAssert b.state == bsOpen
doAssert b.allow(cfg, 5).decision == dReject
let (probing, d) = b.allow(cfg, 11)  # the pause is over: one probe
doAssert d == dAllow and probing.state == bsHalfOpen
doAssert probing.allow(cfg, 12).decision == dReject   # no second probe
doAssert probing.recordSuccess.state == bsClosed
```

The shell wraps a call: ask `allow`, call only on `dAllow`, report the outcome. The function below keeps the breaker in a caller-owned variable, so the only mutation is at the edge.

```nim
import nimcs/patterns/circuit_breaker

proc guarded(b: var Breaker; cfg: BreakerConfig; now: int; call: proc(): bool): string =
  let (next, d) = b.allow(cfg, now)
  b = next
  if d == dReject: return "rejected"
  if call():
    b = b.recordSuccess
    "ok"
  else:
    b = b.recordFailure(cfg, now)
    "failed"

let cfg = initConfig(1, 5).value
var b = closedBreaker()
doAssert guarded(b, cfg, 0, proc(): bool = false) == "failed"
doAssert guarded(b, cfg, 1, proc(): bool = true) == "rejected"
doAssert guarded(b, cfg, 6, proc(): bool = true) == "ok"
doAssert b.state == bsClosed
```

another module (`Option`, `Result`, `Graph`) needs that module's import too, as in the example

## Laws and invariants
- A fresh breaker is closed, counts no failures and allows every call (PAT-CIRCUITBREAKER-01).
- It opens at exactly the threshold-th consecutive failure, recording the time (PAT-CIRCUITBREAKER-02).
- A success while closed restarts the count (PAT-CIRCUITBREAKER-03).
- An open breaker refuses, unchanged, until `openTicks` have passed; at that moment the call is admitted as the probe and the breaker is half-open. A clock that reads earlier than the opening counts as "not yet" (PAT-CIRCUITBREAKER-04).
- While a probe is out, other calls are refused and the breaker is unchanged (PAT-CIRCUITBREAKER-05).
- A successful probe closes the breaker; a failed probe opens it again from the time of the failure (PAT-CIRCUITBREAKER-06).
- A success or failure reported while open (a late report from a call started before opening) changes nothing, so it cannot postpone the probe (PAT-CIRCUITBREAKER-07).
- For any history of events with a growing clock, a closed breaker has fewer failures than the threshold, no call passes an open breaker before the pause, and a refusal never changes the breaker (PAT-CIRCUITBREAKER-08).
- `initConfig` gives each out-of-range parameter its own error (PAT-CIRCUITBREAKER-09).

## Complexity
Every operation is O(1) time and space; the breaker is one small value.

## Pitfalls
Reading the clock inside the breaker makes the open period untestable without sleeping, and a shared mutable breaker in a global is hidden state.

```nim bad
var failures = 0
var openedAt = 0
proc allow(): bool =
  if failures >= 5 and epochTime() - openedAt < 30.0: return false
  true
```

Pass the time in and keep the state in a value:

```nim
import nimcs/patterns/circuit_breaker

let cfg = initConfig(5, 30).value
let b = closedBreaker()
doAssert b.allow(cfg, 0).decision == dAllow
```

Another trap: counting every error as a failure. Only report failures that say the dependency is unhealthy (timeouts, connection errors, 5xx), not the caller's own mistakes. Also remember that a half-open breaker admits one probe at a time; a probe whose result is never reported leaves the breaker half-open and refusing, so the shell must always report (a timeout counts as a failure).
