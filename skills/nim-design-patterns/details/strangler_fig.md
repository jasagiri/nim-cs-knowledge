# Strangler fig

## Intent
Replace a system one route at a time while the old one keeps answering. A front door holds a table from request prefixes to the system that answers them. Anything the table does not name still goes to the old system. Each step moves one prefix to the new system; moving it back is the same step with the other target. When the fallback and every entry name the new system, the old one can be switched off.

## Use when / avoid when
- Use when users cannot wait for a rewrite to be whole, and every request passes one place you control (a gateway, a router, a reverse proxy).
- Use when a step must be undoable in minutes: the undo is a table edit.
- Avoid when there is no single place that sees every request: the table has nowhere to live.
- Avoid when the two systems cannot be run side by side on the same data; the fig then strangles itself. See `parallel_change.md` for the data.
- The table does not make the two systems agree. Run both on the same requests in a test, or use the shadow stage of `branch_by_abstraction.md`, before moving a prefix.

## Nim shape
`src/nimcs/patterns/strangler_fig.nim`. `Table` holds a list of (prefix, target) entries, one per prefix, and a fallback target. `withRoute` names a prefix and is idempotent; `strangle` and `retreat` are `withRoute` with `tgModern` and `tgLegacy`. `route` picks the longest matching prefix, and `serve` calls the system it names. `isRetired` says whether the old system is out of the way.

```nim
import nimcs/patterns/strangler_fig

func legacy(request: string): string {.raises: [].} = "old " & request
func modern(request: string): string {.raises: [].} = "new " & request

let start = initTable()
doAssert start.serve(legacy, modern, "/orders/7") == "old /orders/7"

let step = start.strangle("/orders")
doAssert step.isOk
doAssert step.value.serve(legacy, modern, "/orders/7") == "new /orders/7"
doAssert step.value.serve(legacy, modern, "/users/3") == "old /users/3"

let back = step.value.retreat("/orders")
doAssert back.isOk and back.value.route("/orders/7") == tgLegacy
doAssert not step.value.isRetired
doAssert step.value.withFallback(tgModern).isRetired
```

## Public API

Every exported symbol of `src/nimcs/patterns/strangler_fig.nim`, generated by `nim apiSections` (the
tests fail when it drifts). `import nimcs/patterns/strangler_fig` brings these names. A type they use from
another module (`Option`, `Result`, `Graph`) needs that module's import too, as in the example
above. A field marked `*` is readable outside the module; a type shown without fields is opaque,
built and read only through the functions.

```text
type Target = enum
  tgLegacy, tgModern
type TableError = enum
  teEmptyPrefix
type Route = tuple[prefix: string, target: Target]
type Table = object
  entries*: seq[Route]       ## one entry per prefix, in the order the prefixes were first named
  fallback*: Target          ## where a request goes when no prefix matches
type System = proc (request: string): string {.noSideEffect, raises: [].}
func initTable(): Table
func withRoute(t: Table; prefix: string; target: Target): Result[Table, TableError]
func strangle(t: Table; prefix: string): Result[Table, TableError]
func retreat(t: Table; prefix: string): Result[Table, TableError]
func withFallback(t: Table; target: Target): Table
func route(t: Table; request: string): Target
func serve(t: Table; legacy, modern: System; request: string): string
func isRetired(t: Table): bool
```

## Laws and invariants
Why this is testable: the table is a value and `route` is a function of it, so "what changes when a prefix moves" is an equation about two tables.
- The longest named prefix of the request decides, and the fallback applies when none matches (PAT-STRANGLERFIG-01).
- When the two systems answer a request alike, moving a prefix does not change the response; a request outside the prefix keeps its route (PAT-STRANGLERFIG-02).
- Naming a prefix is idempotent and the last target wins; `retreat` after `strangle` of a prefix that went to the old system routes every request as before (PAT-STRANGLERFIG-03).
- A table is retired exactly when its fallback and every entry name the new system, and then no request reaches the old one (PAT-STRANGLERFIG-04).
- An empty prefix is refused, since it would be the fallback under another name (PAT-STRANGLERFIG-05).

## Complexity
`route` is O(entries × prefix length) here; a trie over the prefixes makes it O(request length). `withRoute` copies the entry list.

## Pitfalls
Moving a prefix before the new system answers it as the old one does changes what users see, and nothing in the router says so.

```nim bad
func serve(t: Table; legacy, modern: System; request: string): string =
  if request.startsWith("/orders"): modern(request)   # a hard-coded cutover, no table, no way back
  else: legacy(request)
```

Keep the cutover in the table, move one prefix at a time, and check the two systems agree on that prefix before the move:

```nim
import nimcs/patterns/strangler_fig

func legacy(request: string): string {.raises: [].} = request
func modern(request: string): string {.raises: [].} = request

let t = initTable().strangle("/orders").value
doAssert t.serve(legacy, modern, "/orders/1") == initTable().serve(legacy, modern, "/orders/1")
```

A stale entry is its own trap: after a retreat the entry stays in the table as a legacy route. That is intended (it records the decision), but `isRetired` is false until it is moved forward again.
