# Introduce parameter object

## Intent
A routine that takes six arguments, four of them integers in a row, is called correctly only by readers who remember the order; swapping two compiles and returns nonsense. A parameter object names each field, gives each a default that means "no restriction", and can be stored, compared, combined and tested by itself. The routine takes the data and the filter instead of the loose list.

## Use when / avoid when
- Use when the same group of three or more parameters is passed through more than one routine, or the order is the contract.
- Use when callers usually want the defaults and set one or two fields.
- Avoid when the arguments are unrelated; a record of them is a bag, not an object.
- For differing behaviour rather than differing data, pass a record of procs (`dependency_record.md`).

## Nim shape
`src/nimcs/patterns/introduce_parameter_object.nim`. `selectLoose` is the before, with three integers, a `StockRule` and a limit. `Filter` is the parameter object; `noFilter()` is "no restriction" and `withPrice`, `withMinRating`, `inStockOnly` and `limited` return a changed copy. `select(items, filter)` is the new routine, and `narrowedBy` combines two filters into the one that selects what both would. The test compares `selectLoose` and `select` on generated products and arguments.

```nim
import nimcs/patterns/introduce_parameter_object

let items = @[Product(id: 1, price: 500, rating: 4, inStock: true),
              Product(id: 2, price: 900, rating: 5, inStock: false),
              Product(id: 3, price: 300, rating: 2, inStock: true)]
let f = noFilter().withPrice(400, 1000).withMinRating(4)
doAssert items.select(f) == selectLoose(items, 400, 1000, 4, srAny, NoLimit)
doAssert items.select(f.inStockOnly).len == 1
doAssert items.select(noFilter()) == items
```

## Public API

Every exported symbol of `src/nimcs/patterns/introduce_parameter_object.nim`, generated by `nim apiSections` (the
tests fail when it drifts). `import nimcs/patterns/introduce_parameter_object` brings these names. A type they use from
another module (`Option`, `Result`, `Graph`) needs that module's import too, as in the example
above. A field marked `*` is readable outside the module; a type shown without fields is opaque,
built and read only through the functions.

```text
type Product = object
  id*: int
  price*: int                ## yen
  rating*: int               ## 0 .. 5
  inStock*: bool
type Filter = object
  minPrice*: int
  maxPrice*: int
  minRating*: int
  onlyInStock*: bool
  limit*: int                ## 0 means no limit
type StockRule = enum
  srAny, srInStockOnly
const NoLimit = 0
func noFilter(): Filter
func selectLoose(items: openArray[Product]; minPrice, maxPrice, minRating: int; stock: StockRule; limit: int): seq[Product]
func withPrice(f: Filter; minPrice, maxPrice: int): Filter
func withMinRating(f: Filter; minRating: int): Filter
func inStockOnly(f: Filter): Filter
func limited(f: Filter; limit: int): Filter
func matches(f: Filter; p: Product): bool
func select(items: openArray[Product]; f: Filter): seq[Product]
func narrowedBy(a, b: Filter): Filter
```

## Laws and invariants
- `select` with a filter equals `selectLoose` with the same six values (PAT-INTRODUCEPARAMETEROBJECT-01).
- The default filter selects everything in order (PAT-INTRODUCEPARAMETEROBJECT-02).
- Narrowing by two filters (without limits) equals selecting by each in turn, and `narrowedBy` is commutative and idempotent (PAT-INTRODUCEPARAMETEROBJECT-03).
- A stricter filter selects a subset (PAT-INTRODUCEPARAMETEROBJECT-04).
- A limit returns at most that many, in list order, and zero means no limit (PAT-INTRODUCEPARAMETEROBJECT-05).

## Complexity
Selection is O(items) and stops early at the limit. Building a filter is O(1) per `with` step (the record is five fields).

## Pitfalls
The common mistake is to wrap the arguments in an object but give it no defaults, so every caller must still fill in every field and the object is the same list in a new coat.

```nim bad
let f = Filter(minPrice: 0, maxPrice: 0, minRating: 0, onlyInStock: false, limit: 0)
# maxPrice 0 selects nothing: the caller had to know what "no limit" is
```

Start from a named default and change only what you mean:

```nim
import nimcs/patterns/introduce_parameter_object

let f = noFilter().limited(2)
doAssert f.maxPrice == high(int) and f.limit == 2
```

Also keep the "no restriction" value of each field as the neutral element of narrowing, so that combining filters never loosens one.

When callers build the record with a literal and name only the fields they mean, give the fields
defaults in the type (Nim 2 object field defaults) instead of a `noFilter()` constructor. A range
whose minimum exceeds its maximum matches nothing here, which is not an error; when a caller can
build such a range by mistake, reject it in a constructor that returns `Result` instead.

```nim
type Query = object
  minStops: int = 0
  maxStops: int = high(int)

func matches(q: Query; stops: int): bool {.raises: [].} =
  stops >= q.minStops and stops <= q.maxStops

doAssert Query(maxStops: 1).matches(1)
doAssert not Query(maxStops: 1).matches(2)
doAssert not Query(minStops: 3, maxStops: 1).matches(2)   # min > max matches nothing
```
