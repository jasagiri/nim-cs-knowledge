# Bulkhead

## Intent
One shared pool of workers lets a single slow tenant or dependency hold every worker, and then everyone waits. A bulkhead gives each compartment its own number of permits, so overload stays inside the compartment that caused it. The whole state is one value (limit and permits in use per compartment); admission is a pure function that returns the new value and the answer.

## Use when / avoid when
- Use around calls that share a scarce resource and can be grouped: per tenant, per downstream service, per priority class.
- Use when a refusal is acceptable and can be handled by the caller (fail fast, queue, shed).
- Avoid it for limiting a rate over time; that is `token_bucket.md`. A bulkhead limits calls in flight.
- Avoid deciding by queue length or deadline here; `load_shedding.md` does that, and the two combine: the bulkhead protects capacity per compartment, shedding protects latency in the queue.

## Nim shape
`src/nimcs/patterns/bulkhead.nim`. `initBulkhead([(name, permits), ...])` validates the compartments and returns `Result[Bulkhead, SetupError]`. `tryAcquire(b, compartment)` returns the new bulkhead and an `Admission` (`aAdmitted`, `aFull`, `aUnknownCompartment`); a refusal returns the bulkhead unchanged. `release(b, compartment)` returns a `Result`: releasing with no permit taken is an error, not a silent no-op. `usage` lists the permits in use sorted by name, so the table's own order never leaks.

```nim
import nimcs/patterns/bulkhead

let b0 = initBulkhead([("search", 1), ("checkout", 2)]).value
let (b1, a1) = b0.tryAcquire("search")
doAssert a1 == aAdmitted
let (b2, a2) = b1.tryAcquire("search")
doAssert a2 == aFull and b2 == b1                 # search is full ...
doAssert b2.tryAcquire("checkout").admission == aAdmitted   # ... checkout is not affected
doAssert b2.release("search").value == b0
```

The shell takes a permit, does the work, and releases in all cases; the bulkhead value lives in the caller.

```nim
import nimcs/patterns/bulkhead

proc withPermit(b: var Bulkhead; compartment: string; work: proc(): int): int =
  let (next, a) = b.tryAcquire(compartment)
  if a != aAdmitted: return -1
  b = next
  result = work()
  let back = b.release(compartment)
  doAssert back.isOk      # we took a permit just above, so this cannot fail
  b = back.value

var b = initBulkhead([("db", 1)]).value
doAssert withPermit(b, "db", proc(): int = 7) == 7
doAssert b.inUse("db") == 0
doAssert withPermit(b, "other", proc(): int = 7) == -1
```

## Public API

Every exported symbol of `src/nimcs/patterns/bulkhead.nim`, generated by `nim apiSections` (the
tests fail when it drifts). `import nimcs/patterns/bulkhead` brings these names. A type they use from
another module (`Option`, `Result`, `Graph`) needs that module's import too, as in the example
above. A field marked `*` is readable outside the module; a type shown without fields is opaque,
built and read only through the functions.

```text
type Bulkhead = object
type Admission = enum
  aAdmitted, aFull, aUnknownCompartment
type SetupError = enum
  seNoCompartments, seEmptyName, seDuplicateName, seLimitNotPositive
type ReleaseError = enum
  reUnknownCompartment, reNothingToRelease
func `==`(a, b: Bulkhead): bool
func initBulkhead(limits: openArray[(string, int)]): Result[Bulkhead, SetupError]
func limit(b: Bulkhead; compartment: string): int
func inUse(b: Bulkhead; compartment: string): int
func available(b: Bulkhead; compartment: string): int
func usage(b: Bulkhead): seq[(string, int)]
func tryAcquire(b: Bulkhead; compartment: string): tuple[bulkhead: Bulkhead, admission: Admission]
func release(b: Bulkhead; compartment: string): Result[Bulkhead, ReleaseError]
```

## Laws and invariants
- A free permit is admitted and raises the permits in use of that compartment by one (PAT-BULKHEAD-01).
- A full compartment refuses and the bulkhead is unchanged (PAT-BULKHEAD-02).
- Isolation: any operations on one compartment leave every other compartment unchanged (PAT-BULKHEAD-03).
- For any sequence of acquires and releases, permits in use stay between 0 and the limit, and a request is admitted exactly when a permit is free (PAT-BULKHEAD-04).
- An admitted acquire followed by its release gives back the same bulkhead (PAT-BULKHEAD-05).
- Releasing with nothing taken, and any use of an unknown name, get their own answers and change nothing (PAT-BULKHEAD-06).
- `initBulkhead` reports an empty set, an empty name, a duplicate name and a non-positive limit separately; `usage` is sorted by name (PAT-BULKHEAD-07).

## Complexity
`tryAcquire` and `release` copy the two tables, so they are O(c) in the number of compartments c (the price of returning a new value and keeping the old one valid); with a persistent map they would be O(log c). `usage` is O(c log c). Space is O(c).

## Pitfalls
A shared counter incremented before the work and decremented after, in a global, hides the state and leaks a permit when the work raises.

```nim bad
var inFlight = 0
proc call(work: proc()) =
  if inFlight >= 10: return
  inc inFlight
  work()          # if this raises, inFlight never goes down again
  dec inFlight
```

Keep the permits in a value and release in the shell even when the work fails; the release returns an error if it is ever done twice, which is how a double release shows up as a bug and not as extra capacity:

```nim
import nimcs/patterns/bulkhead

let b = initBulkhead([("a", 1)]).value
doAssert b.release("a").error == reNothingToRelease
```

Also size the limits so that they do not add up to more than the real resource if all compartments can be busy at once; a bulkhead that over-commits protects nothing.
