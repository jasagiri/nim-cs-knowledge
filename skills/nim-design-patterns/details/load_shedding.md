# Load shedding

## Intent
A service whose queue grows without bound answers every caller late. Shedding is the decision, taken before the work is queued, to refuse a request that cannot succeed and to say why: the queue is full, only important work is wanted now, or the deadline passes before the request would be served. Here the decision is a pure function of the limits, the time, the queue length and the request, and a ledger of request ids makes it idempotent, so a retry gets the answer it got the first time.

## Use when / avoid when
- Use at the entry of any queue whose callers can retry or give up.
- Use priorities when some work is worth keeping under overload and some is not.
- Avoid shedding for work that must not be lost (a payment); queue it durably or push back on the producer instead.
- Pair it with `retry_backoff.md` on the client side, or refused callers return at once and the overload continues.

## Nim shape
`src/nimcs/patterns/load_shedding.nim`. `Limits` has a queue maximum, a soft length from which low-priority work is shed, and the ticks one item takes; `initLimits` refuses inconsistent values. `judge` is the memoryless rule, with refusals checked in a fixed order: no id, expired, queue full, low priority shed, deadline unreachable. `decide` adds the `Ledger`: a known id returns its first decision and the same ledger, whatever the time and queue length are now. Time and queue length are arguments; the caller reads them.

```nim
import nimcs/patterns/load_shedding

let limits = initLimits(10, 6, 3).value
let req = Request(id: "r1", priority: pLow, deadline: 20)
let first = emptyLedger().decide(limits, 0, 2, req)
doAssert first.decision.admitted
# The queue is now full, but the same id keeps its first answer.
let again = first.ledger.decide(limits, 5, 10, req)
doAssert again.decision.admitted and again.ledger == first.ledger
# A new id meets the full queue.
doAssert limits.judge(5, 10, Request(id: "r2", priority: pHigh, deadline: 99)).reason == rQueueFull
```

## Public API

Every exported symbol of `src/nimcs/patterns/load_shedding.nim`, generated by `nim apiSections` (the
tests fail when it drifts). `import nimcs/patterns/load_shedding` brings these names. A type they use from
another module (`Option`, `Result`, `Graph`) needs that module's import too, as in the example
above. A field marked `*` is readable outside the module; a type shown without fields is opaque,
built and read only through the functions.

```text
type Priority = enum
  pLow, pHigh
type Request = object
  id*: string
  priority*: Priority
  deadline*: int             ## absolute tick by which the answer is useless to the caller
type Reason = enum
  rNoId, rExpired, rQueueFull, rLowPriorityShed, rDeadlineUnreachable
type Decision = object
  case admitted*: bool
  of true:
    nil
  of false:
    reason*: Reason
type Limits = object
type Ledger = object
func `==`(a, b: Decision): bool
func `==`(a, b: Ledger): bool
func initLimits(maxQueue, softQueue, ticksPerItem: int): Result[Limits, string]
func emptyLedger(): Ledger
func judge(l: Limits; now, queueLen: int; req: Request): Decision
func decide(ledger: Ledger; l: Limits; now, queueLen: int; req: Request): tuple[ledger: Ledger, decision: Decision]
func decidedCount(ledger: Ledger): int
func knows(ledger: Ledger; id: string): bool
```

## Laws and invariants
- A request id already decided returns its first decision and the same ledger (PAT-LOADSHEDDING-01).
- A request admitted at a longer queue is admitted at every shorter one (PAT-LOADSHEDDING-02).
- An admitted request had room, a future deadline, and `now + (queueLen + 1) * ticksPerItem <= deadline` (PAT-LOADSHEDDING-03).
- If low priority is admitted, high priority is admitted; at the soft length low is shed and high is not (PAT-LOADSHEDDING-04).
- Refusals name their reason in a fixed order (PAT-LOADSHEDDING-05).
- A request with no id is judged but not recorded; inconsistent limits are refused (PAT-LOADSHEDDING-06).

## Complexity
`judge` is O(1). `decide` is O(1) expected for the lookup and O(ledger size) to return the updated ledger, because the ledger is a value that is copied on write; a long-lived service keeps a bounded window of ids (the ledger grows without bound here, by design of a reference module).

## Pitfalls
The common mistake is to judge every attempt afresh. A client that retries after a timeout then gets "admitted" on the second attempt of a request that was refused on the first, or is admitted twice, and the deadline arithmetic is no longer about one request.

```nim bad
func decide(l: Limits; now, queueLen: int; req: Request): Decision =
  l.judge(now, queueLen, req)   # a retry of the same id is judged against today's queue
```

Record the decision under the id, and return the recorded one for a repeat:

```nim
import nimcs/patterns/load_shedding

let limits = initLimits(2, 1, 1).value
let r = Request(id: "a", priority: pHigh, deadline: 50)
let one = emptyLedger().decide(limits, 0, 2, r)    # queue full
let two = one.ledger.decide(limits, 0, 0, r)       # now empty, same id
doAssert not one.decision.admitted and two.decision == one.decision
```

Also remember that the deadline is an absolute tick and the clock is the caller's: do not read the time inside the decision.
