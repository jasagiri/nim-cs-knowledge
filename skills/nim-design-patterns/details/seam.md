# Seam

## Intent
A seam is a place where behaviour can be changed without editing the code at that place. Legacy code reaches for what it needs (a price list, a clock, a database) from inside, so it cannot be run or tested without all of it. In functional Nim the simplest seam is a parameter: a proc the routine is handed. Making a seam must not change what the routine does, so the first test is the old routine against the new one on the same inputs. A pinned list of input and output pairs (a characterization) then says whether a later change kept behaviour that nobody wrote down.

## Use when / avoid when
- Use before changing code you cannot yet test, to get a place where a test can supply its own answers.
- Use to pin down what a routine does today before you refactor it (`/refactoring` asks for this before any structural change).
- Avoid adding a seam to code you are about to delete, or to a routine that is already pure.
- Avoid several seams at once: add one, check old against new, then the next.
- A seam is for testing and substitution. If production also varies at that point, it is a strategy or a dependency record, and the name should say so.

## Nim shape
`src/nimcs/patterns/seam.nim`. `legacyTotal` is the routine before the seam: its price list is inside, and it counts an unknown SKU as 0. `Seam` is a proc from SKU to `Option[int]`. `defaultSeam` is the old wiring as a seam, and `total` is the same arithmetic with the lookup handed in; an unknown SKU is an error naming it. `pin` records what a routine does for a list of inputs, `firstDifference` finds the first input where a routine departs from the pins, and `holds` says there is none.

```nim
import std/options
import nimcs/patterns/seam

# 1. The seam changes nothing for what the old routine knew.
let basket = @["apple", "pear", "fig"]
doAssert total(defaultSeam(), basket) == ok(legacyTotal(basket), PriceError)

# 2. A test supplies its own prices.
let fake: Seam = proc(sku: string): Option[int] {.noSideEffect, raises: [].} =
  if sku == "apple": some(100) else: none(int)
doAssert total(fake, @["apple", "apple"]) == ok(200, PriceError)
doAssert total(fake, @["apple", "kiwi"]).error.unknownSku == "kiwi"

# 3. Pin today's behaviour, then check a change against it.
let pins = pin(legacyTotal, @[@["apple"], basket])
doAssert pins.holds(legacyTotal)
let slower: Total = proc(skus: seq[string]): int {.noSideEffect, raises: [].} = legacyTotal(skus) + 1
doAssert pins.firstDifference(slower) == some(0)
```

## Public API

Every exported symbol of `src/nimcs/patterns/seam.nim`, generated by `nim apiSections` (the
tests fail when it drifts). `import nimcs/patterns/seam` brings these names. A type they use from
another module (`Option`, `Result`, `Graph`) needs that module's import too, as in the example
above. A field marked `*` is readable outside the module; a type shown without fields is opaque,
built and read only through the functions.

```text
type Seam = proc (sku: string): Option[int] {.noSideEffect, raises: [].}
type PriceError = object
  unknownSku*: string
type Total = proc (skus: seq[string]): int {.noSideEffect, raises: [].}
type Pin = tuple[input: seq[string], output: int]
type Pins = seq[Pin]
func legacyTotal(skus: seq[string]): int
func defaultSeam(): Seam
func total(prices: Seam; skus: seq[string]): Result[int, PriceError]
func pin(f: Total; inputs: seq[seq[string]]): Pins
func firstDifference(pins: Pins; f: Total): Option[int]
func holds(pins: Pins; f: Total): bool
```

## Laws and invariants
Why this is testable: with the lookup handed in, the routine is a function of its arguments, so "same as before" and "same as an independent model" are equations.
- For any known SKUs, the total through the default seam equals the hard-wired routine's (PAT-SEAM-01).
- For any prices supplied as the seam, the total is the sum of the prices with the discount, as an independent model computes it (PAT-SEAM-02).
- An unknown SKU makes the total an error naming the first one; no price is invented (PAT-SEAM-03).
- Pins taken from a routine hold for it; for a changed routine, `firstDifference` is the index of the first pinned input where it differs (PAT-SEAM-04).

## Complexity
`total` is O(SKUs) lookups. `pin` and `firstDifference` run the routine once per input.

## Pitfalls
A characterization copies what the code does, including its mistakes. The legacy routine here counts an unknown SKU as 0. Pinning that as "correct" would make the refactoring unable to fix it.

```nim bad
let pins = pin(legacyTotal, @[@["ghost"]])   # pins output 0 for an unknown SKU
doAssert pins.holds(legacyTotal)            # and from now on 0 is "right"
```

Pin only inputs whose behaviour you mean to keep, and put the known difference in its own test, as here:

```nim
import nimcs/patterns/seam

doAssert legacyTotal(@["ghost"]) == 0
doAssert total(defaultSeam(), @["ghost"]).isErr
```

Also keep the default seam equal to the old wiring until the pins are green; change the wiring in a separate step.
