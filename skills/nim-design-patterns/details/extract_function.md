# Extract function

## Intent
A long routine that computes four named things in a row, with a comment between each, hides four functions. Extracting each one gives it a name, a signature that lists what it needs and a result that can be tested alone, and leaves the original as a short sequence that reads like the comments did. Behaviour does not change; the test compares the old routine with the new one.

## Use when / avoid when
- Use when a comment says "now compute X", when a block has one input and one output, or when you want to test one step without the others.
- Use when two routines repeat the same block with different surroundings.
- Avoid when the block reads and writes many locals: bundle them first (`introduce_parameter_object.md`), or the extracted function takes a long argument list and is no clearer.
- Avoid extracting one-line expressions that already read well.

## Nim shape
`src/nimcs/patterns/extract_function.nim`. `summaryBefore` totals an order, applies a bulk discount, adds tax and formats a line in one body. `subtotal`, `discountOf`, `taxOf`, `summarize` and `render` are the extracted steps; `summary` is their pipeline and produces the same text. `summarize` returns a `Summary` record so callers can use the parts without parsing text.

```nim
import nimcs/patterns/extract_function

let lines = @[Line(unitPrice: 6000, quantity: 2)]
doAssert lines.subtotal == 12000
doAssert lines.subtotal.discountOf == 600
doAssert lines.summary == lines.summaryBefore
doAssert lines.summarize == Summary(subtotal: 12000, discount: 600, tax: 1140, total: 12540)
```

## Public API

Every exported symbol of `src/nimcs/patterns/extract_function.nim`, generated by `nim apiSections` (the
tests fail when it drifts). `import nimcs/patterns/extract_function` brings these names. A type they use from
another module (`Option`, `Result`, `Graph`) needs that module's import too, as in the example
above. A field marked `*` is readable outside the module; a type shown without fields is opaque,
built and read only through the functions.

```text
type Line = object
  unitPrice*: int
  quantity*: int
type Summary = object
  subtotal*: int
  discount*: int
  tax*: int
  total*: int
const BulkThreshold = 10000
const BulkPercent = 5
const TaxPercent = 10
func summaryBefore(lines: openArray[Line]): string
func subtotal(lines: openArray[Line]): int
func discountOf(subtotal: int): int
func taxOf(amount: int): int
func summarize(lines: openArray[Line]): Summary
func render(s: Summary): string
func summary(lines: openArray[Line]): string
```

## Laws and invariants
- The pipeline's text equals the single body's text for every order (PAT-EXTRACTFUNCTION-01).
- The subtotal is additive over concatenation and zero for no lines (PAT-EXTRACTFUNCTION-02).
- The discount is zero below the threshold and a fixed share from it (PAT-EXTRACTFUNCTION-03).
- The parts add up, and the tax is that of the discounted amount, rounded down (PAT-EXTRACTFUNCTION-04).

## Complexity
Unchanged by the refactoring: O(lines) for the subtotal and O(1) for each other step.

## Pitfalls
The common mistake is to extract a block that depends on a variable it also assigns, passing it as `var`. The new function then has a hidden output and cannot be used or tested as a value.

```nim bad
func applyDiscount(subtotal: var int) =
  if subtotal >= 10000: subtotal -= subtotal * 5 div 100   # input and output are the same variable
```

Take the value, return the result, and let the caller decide what to do with it:

```nim
import nimcs/patterns/extract_function

let sub = 12000
let net = sub - sub.discountOf
doAssert net == 11400
```

Also name the function for what it computes (`discountOf`), not for where it was (`part2`), and keep rounding rules in the function that owns them.
