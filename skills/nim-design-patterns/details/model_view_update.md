# Model, view, update

## Intent
Keep all of the state of an interactive program in one value, make everything that can happen a message, and write the program as two pure functions: `update(model, msg)` gives the next model and `view(model)` gives the screen. A session is then just a list of messages, so the same log always gives the same model and the same screen, any intermediate state can be inspected, and a bug report is a log that replays.

## Use when / avoid when
- Use for interactive state with many events: a form, a game, an editor buffer, a wizard.
- Use when you want replay, undo or time-travel debugging; they follow from the shape.
- Avoid for one value that changes once; a function is enough.
- Avoid putting effects in `update`; return a description of the effect (`functional_core.md`) and perform it in the loop.

## Nim shape
`src/nimcs/patterns/model_view_update.nim`. A counter with a step size and an undo stack. `Model` is a plain object; `Msg` is a closed object variant (`increment`, `decrement`, `setStep`, `undo`, `reset`, built by small functions). `update` is total: a step outside `MinStep .. MaxStep` is clamped, an undo with nothing to undo changes nothing. `view` renders the whole screen as text from the model alone. `replay` folds a log from a start model and `trace` returns every intermediate model.

```nim
import nimcs/patterns/model_view_update

let log = @[increment(), increment(), setStep(5), increment(), undo()]
let m = log.replay
doAssert m.count == 2 and m.step == 5
doAssert m.view == "count=2 step=5 undo=2"
doAssert log.trace.len == log.len + 1
doAssert log.replay == log.replay
```

## Public API

Every exported symbol of `src/nimcs/patterns/model_view_update.nim`, generated by `nim apiSections` (the
tests fail when it drifts). `import nimcs/patterns/model_view_update` brings these names. A type they use from
another module (`Option`, `Result`, `Graph`) needs that module's import too, as in the example
above. A field marked `*` is readable outside the module; a type shown without fields is opaque,
built and read only through the functions.

```text
type Model = object
  count*: int
  step*: int                 ## always in `MinStep .. MaxStep`, see `update`
  history*: seq[int]         ## earlier counts, newest last, for `mUndo`
type MsgKind = enum
  mIncrement, mDecrement, mSetStep, mUndo, mReset
type Msg = object
  case kind*: MsgKind
  of mSetStep:
    step*: int
  of mIncrement, mDecrement, mUndo, mReset:
    nil
const MinStep = 1
const MaxStep = 10
func init(): Model
func increment(): Msg
func decrement(): Msg
func setStep(n: int): Msg
func undo(): Msg
func reset(): Msg
func update(m: Model; msg: Msg): Model
func view(m: Model): string
func replay(log: openArray[Msg]; start = init()): Model
func trace(log: openArray[Msg]; start = init()): seq[Model]
```

## Laws and invariants
- Replaying the same log twice gives the same model and the same view (PAT-MODELVIEWUPDATE-01).
- Replaying `b` from the model of `a` equals replaying `a` then `b` (PAT-MODELVIEWUPDATE-02).
- `trace` has one model per message plus the start, step by step `update`, ending at the replay (PAT-MODELVIEWUPDATE-03).
- Undoing a change returns the previous model, and `reset` is idempotent (PAT-MODELVIEWUPDATE-04).
- The step stays in its range, and an empty undo changes nothing (PAT-MODELVIEWUPDATE-05).

## Complexity
`update` is O(1) for the counter, except that the history is appended by copy, which makes a long log O(n squared) here; use a persistent list or `ds/` stack when the history is long. `view` is O(size of the model). `replay` is O(messages) updates.

## Pitfalls
The common mistake is to let `update` read the clock or a random number. The log no longer determines the model, and replay stops working.

```nim bad
func update(m: Model; msg: Msg): Model =
  if msg.kind == mIncrement:
    Model(count: m.count + int(epochTime()), step: m.step, history: m.history)   # not a function of its arguments
```

Put anything the transition needs into the message, so that the log carries it:

```nim
import nimcs/patterns/model_view_update

# the step arrives inside the message, not from the environment
let m = init().update(setStep(4)).update(increment())
doAssert m.count == 4
```

Also keep `view` free of state: if two equal models can render differently, the screen is not a function of the model.
