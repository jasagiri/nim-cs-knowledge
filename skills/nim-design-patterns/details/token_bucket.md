# Token bucket

## Intent
A rate limiter lets a burst through and then holds the long-run rate to a limit. The bucket holds up to a capacity of tokens and gains tokens at a fixed rate; a request takes tokens or is refused. There is no timer: the bucket remembers when it was last updated, and every operation receives `now` and computes the refill from the elapsed time.

## Use when / avoid when
- Use to limit calls per client, per API key or per dependency, when short bursts are fine.
- Use when the limiter must be tested for any timeline without sleeping.
- Avoid it to limit concurrency (calls in flight); that is `bulkhead.md`.
- Avoid a bucket whose capacity is much larger than the rate times the period you care about: the burst then dominates the limit.

## Nim shape
`src/nimcs/patterns/token_bucket.nim`. `initConfig(capacity, refillTokens, refillTicks)` says that `refillTokens` tokens arrive every `refillTicks` ticks, up to `capacity`. `fullBucket(config, now)` starts full. `tryTake(bucket, now, n)` returns the new bucket and whether the `n` tokens were granted. `available(bucket, now)` counts whole tokens, `refill(bucket, now)` brings the bucket up to date. The amount is stored in units of one `refillTicks`-th of a token, so each tick adds exactly `refillTokens` units and no rounding error builds up, however the elapsed time is split between calls.

```nim
import nimcs/patterns/token_bucket

let cfg = initConfig(3, 1, 10).value        # capacity 3, one token per 10 ticks
var b = fullBucket(cfg, 0)
for _ in 1 .. 3:
  let (next, granted) = b.tryTake(0, 1)
  doAssert granted
  b = next
doAssert not b.tryTake(0, 1).granted        # burst used up
doAssert not b.tryTake(9, 1).granted        # 9 ticks: 0.9 of a token
doAssert b.tryTake(10, 1).granted           # 10 ticks: one token
```

The shell reads the clock once and passes it in. The function below limits a client; the bucket sits in a caller-owned variable.

```nim
import nimcs/patterns/token_bucket

proc admit(b: var Bucket; now: int; cost: Positive): bool =
  let (next, granted) = b.tryTake(now, cost)
  b = next          # keep the refilled bucket even when refused
  granted

var b = fullBucket(initConfig(2, 1, 1).value, 0)
doAssert admit(b, 0, 2)
doAssert not admit(b, 0, 1)
doAssert admit(b, 1, 1)
```

tests fail when it drifts). `import nimcs/patterns/token_bucket` brings these names. A type they use from
another module (`Option`, `Result`, `Graph`) needs that module's import too, as in the example
above. A field marked `*` is readable outside the module; a type shown without fields is opaque,
built and read only through the functions.

```text
  ceCapacityOutOfRange, ceRefillTokensOutOfRange, ceRefillTicksOutOfRange

```

## Laws and invariants
- A new bucket holds exactly its capacity (PAT-TOKENBUCKET-01).
- A granted request takes exactly `n` tokens and a refused one takes none (PAT-TOKENBUCKET-02).
- The bound: for any requests with a growing clock, the total granted never exceeds `capacity + refillTokens * elapsed div refillTicks` (PAT-TOKENBUCKET-03). This is the property that makes it a rate limiter.
- The tokens held stay between 0 and the capacity (PAT-TOKENBUCKET-04).
- `refill` composes: refilling at an intermediate time first gives the same bucket as refilling directly, and refilling twice at one time equals once (PAT-TOKENBUCKET-05).
- A drained bucket is full again after exactly `ceil(capacity * refillTicks / refillTokens)` ticks and not before (PAT-TOKENBUCKET-06).
- A clock that goes backwards creates no tokens, and a request larger than the capacity is always refused (PAT-TOKENBUCKET-07).
- `initConfig` gives each out-of-range parameter its own error, and the largest parameters do not overflow (PAT-TOKENBUCKET-08).

## Complexity
All operations are O(1) time and space.

## Pitfalls
Refilling by adding `rate * elapsed` as a float and truncating loses fractions at every call, so calls made often get fewer tokens than calls made rarely.

```nim bad
proc refill(tokens: var float; rate: float; lastCall: var float; now: float) =
  tokens = min(capacity, tokens + rate * (now - lastCall))
  lastCall = now
```

Count in units where each tick adds a whole number and never round; the composition law above (PAT-TOKENBUCKET-05) is what the test checks:

```nim
import nimcs/patterns/token_bucket

let b = fullBucket(initConfig(5, 1, 3).value, 0).tryTake(0, 5).bucket
doAssert b.refill(1).refill(2).refill(7) == b.refill(7)
```

Also keep the last bucket when a request is refused (as `admit` does); dropping it throws the computed refill away, though the result stays correct because `refill` is recomputed from the stored time.
