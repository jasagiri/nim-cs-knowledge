# Command buffer (read, then write)

## Intent
A step often has to remove the things that die and add the things that split, and the natural loop does both to the collection it is reading. In Nim that fails at run time: the `for` loop over a `seq` asserts that the length did not change. The ways around it that compile are a copy of the collection per frame, or a `ref` per element that several places mutate. A command buffer splits the step in two: a read pass decides and records the changes as data, a write pass applies them to the owner afterwards.

## Use when / avoid when
- Use it when a pass over a collection has to add or remove elements, or change elements that other elements refer to: game or simulation steps, graph rewrites, UI trees, a scheduler's tick.
- Use it when the changes should be inspectable, loggable or replayable before they happen; the plan is a `seq` of plain values.
- Use `command` when each change needs an inverse for undo; the buffer is the same idea without history. Use `functional_core` when the effects leave the program (I/O): there the commands are performed by a shell, here they are applied to a value.
- Avoid it when the pass changes only the element it is looking at and nothing else depends on it: update in place or build a new `seq` with `map`.

## Nim shape
The world keeps its units in a `SlotMap` (`slot_map`), so a command names its target by `Handle` and a handle to a unit that is gone is rejected. `WorldCmd` (named apart from `command`'s `Cmd`, so both modules can be imported in one file) is an object variant: `wcSpawn` carries a unit, `wcDespawn` a handle, `wcDamage` a handle and an amount. `plan(w, damage)` takes the world by value and only reads it; it returns the commands in slot order. `applyAll(w, cmds)` takes the world as `sink` and applies the commands in order; a command whose handle is stale does nothing. `step` is `plan` and then `applyAll`.

The rules of the example: a unit whose `hp` is at most the damage is despawned (and does not split); any other unit takes the damage; a unit with `splits` whose `hp` falls from above `SplitThreshold` (3) to that or below spawns one child with its new `hp` and `splits` unset, so a unit splits at most once. A damage of zero or less plans nothing. The children are not visited by the step that made them, because the plan was computed before any of it was applied.

```nim
import std/options
import nimcs/ds/slot_map
import nimcs/patterns/command_buffer

let first = emptyWorld().spawn(Unit(hp: 5, splits: true))
let second = first.world.spawn(Unit(hp: 2, splits: false))
let cmds = plan(second.world, 3)
doAssert cmds.len == 3          # damage the first, spawn its child, despawn the second
doAssert cmds[2] == despawnCmd(second.handle)

let after = applyAll(second.world, cmds)        # the world had other uses above, so this copies once
doAssert after.units.len == 2
doAssert after.units.get(first.handle) == some(Unit(hp: 2, splits: true))
doAssert after.units.get(second.handle).isNone
```

Applying a batch is a fold of the one-command function, and a command with a stale handle changes nothing, so a double despawn is harmless:

```nim
import nimcs/ds/slot_map
import nimcs/patterns/command_buffer

let w = emptyWorld().spawn(Unit(hp: 9, splits: false))
let d = despawnCmd(w.handle)
let once = applyAll(w.world, [d])
let twice = applyAll(w.world, [d, d, damageCmd(w.handle, 4)])   # the damage after the despawn is ignored
doAssert once == twice
doAssert once.units.len == 0
```

## Public API

Every exported symbol of `src/nimcs/patterns/command_buffer.nim`, generated by `nim apiSections` (the
tests fail when it drifts). `import nimcs/patterns/command_buffer` brings these names. A type they use from
another module (`Option`, `Result`, `Graph`) needs that module's import too, as in the example
above. A field marked `*` is readable outside the module; a type shown without fields is opaque,
built and read only through the functions.

```text
const SplitThreshold = 3
type Unit = object
  hp*: int
  splits*: bool
type World = object
  units*: SlotMap[Unit]
type WorldCmdKind = enum
  wcSpawn, wcDespawn, wcDamage
type WorldCmd = object
  case kind*: WorldCmdKind
  of wcSpawn:
    unit*: Unit
  of wcDespawn:
    target*: Handle
  of wcDamage:
    victim*: Handle
    amount*: int
func emptyWorld(): World
func `==`(a, b: Unit): bool
func `==`(a, b: World): bool
func `==`(a, b: WorldCmd): bool
func spawnCmd(unit: Unit): WorldCmd
func despawnCmd(target: Handle): WorldCmd
func damageCmd(victim: Handle; amount: int): WorldCmd
func spawn(w: sink World; unit: Unit): tuple[world: World, handle: Handle]
func plan(w: World; damage: int): seq[WorldCmd]
func applyCmd(w: sink World; c: WorldCmd): World
func applyAll(w: sink World; cmds: openArray[WorldCmd]): World
func step(w: sink World; damage: int): World
```

## Laws and invariants
- `plan` leaves the world equal to what it was, and equal worlds give equal plans (PAT-COMMANDBUFFER-01).
- After a step, a unit whose hp was at most the damage is gone and every other unit lost exactly the damage (PAT-COMMANDBUFFER-02).
- A damage after a despawn of the same handle in one batch is ignored (PAT-COMMANDBUFFER-03).
- Despawning twice equals despawning once, even with a spawn in between that reuses the slot (PAT-COMMANDBUFFER-04).
- Units spawned during a step have the hp the plan gave them and are not damaged by that step (PAT-COMMANDBUFFER-05).
- `applyAll` equals applying the commands one at a time (a fold) (PAT-COMMANDBUFFER-06).
- A command with a stale or unknown handle changes nothing (PAT-COMMANDBUFFER-07).
- Equal worlds and equal commands give equal worlds (PAT-COMMANDBUFFER-08).
- A splitting unit spawns exactly one child when damage takes it from above the threshold to the threshold or below, and in no other case (PAT-COMMANDBUFFER-09).
- A damage of zero or less plans nothing and leaves the world unchanged (PAT-COMMANDBUFFER-10).
- A single `spawn` adds a unit; a single damage lowers hp without removing the unit and stops at the ends of `int` (PAT-COMMANDBUFFER-11).
- With the world moved in at its last use, applying damage or despawn commands allocates nothing, whatever the size (PAT-COMMANDBUFFER-12).

## Complexity
| Operation | Time | Space |
|---|---|---|
| `plan` | O(n) for n units | O(c) for c commands |
| `applyCmd` with the world moved in | O(1): a slot map update | O(1) extra; none for damage and despawn, amortised for spawn |
| `applyAll` of c commands | O(c) | O(1) extra beyond spawns |
| `step` | O(n + c) | O(c) for the plan |

The world is a `sink` parameter: a caller that moves it in at its last use pays for no copy of the units. A caller that still uses the world afterwards gets one copy of the slots per `applyAll` or `step` call (O(n)), and an unchanged old world; the batch does not copy per command. Measured with `-d:nimAllocStats` (tests/test_patterns_command_buffer.nim): 5 damage commands and 5 despawn commands applied to worlds of 10, 100 and 1000 units, each moved in, allocate nothing. `step` itself allocates the plan.

## Pitfalls
Adding to the `seq` inside the loop that reads it fails at run time, because the loop asserts that the length did not change (and under `-d:danger` it reads past the old length).

```nim bad
type Unit = object
  hp: int
  splits: bool

proc stepUnits(units: var seq[Unit]; damage: int) =
  for u in units:
    if u.splits and u.hp - damage <= 3:
      units.add Unit(hp: u.hp - damage)     # the loop asserts the length did not change
```

Read in one pass and record the change; apply it after the pass.

```nim
import nimcs/ds/slot_map
import nimcs/patterns/command_buffer

let w = emptyWorld().spawn(Unit(hp: 4, splits: true)).world
let next = step(w, 1)                           # the child is spawned after the pass has ended
doAssert next.units.len == 2
```

Getting past the `var` error with a copy of the collection or a `ref` per element compiles, and costs an allocation per frame or a second owner of every element.

```nim bad
type Unit = ref object
  hp: int

proc stepUnits(units: var seq[Unit]) =
  let snapshot = units                          # a copy of the seq every call
  for u in snapshot:
    u.hp -= 1                                   # and the same refs behind both seqs
    if u.hp <= 0: units.delete(units.find(u))
```

Keep one owner and refer to units by handle, so a despawn in the batch cannot leave a dangling reference: a later command with that handle is ignored.

```nim
import nimcs/ds/slot_map
import nimcs/patterns/command_buffer

let a = emptyWorld().spawn(Unit(hp: 1, splits: false))
let batch = [despawnCmd(a.handle), damageCmd(a.handle, 5)]
doAssert applyAll(a.world, batch).units.len == 0
```
