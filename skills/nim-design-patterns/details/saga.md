# Saga

## Intent
An operation that spans several services cannot be one transaction. A saga runs its steps in order and, when one fails, undoes the steps that succeeded by running their compensations in reverse order. Here a saga is data and the interpreter is a pure state machine: it says which effect to perform, the shell performs it and reports the result, and the log records what was asked and what happened.

## Use when / avoid when
- Use for multi-step operations across stores or services (book a seat, charge a card, send a ticket) where each step has a meaningful undo.
- Use when the order of compensations and the log must be tested without running any real effect.
- Avoid it when a single database transaction covers all the steps; that is simpler and stronger.
- Avoid compensations that are not idempotent: a shell may have to repeat one after a crash. For making one step's state change and its message atomic, see `transactional_outbox.md`.

## Nim shape
`src/nimcs/patterns/saga.nim`. An `Effect` is data (`name`, `payload`); a `SagaStep` names an action and a compensation, both effects. `start(steps)` gives a `Saga`; `nextEffect` is the effect to perform now (an action going forward, a compensation going backward, `none` when finished or stuck); `feed(saga, result)` reports the result as an `EffectResult` (`erOk`, `erFailed`). `run(steps, handler)` is the whole loop with the shell passed in as an `EffectHandler`. `outcome` is `soCompleted`, `soCompensated` or `soStuck`; `log` and `pending` are values to inspect. A failed action is assumed to have had no effect, so its own compensation is not run; a failed compensation stops the saga as stuck and nothing is skipped.

```nim
import nimcs/patterns/saga

let steps = @[
  step("reserve", effect("reserve", "seat-4"), effect("release", "seat-4")),
  step("charge", effect("charge", "42"), effect("refund", "42")),
  step("ticket", effect("issue", "t-1"), effect("void", "t-1"))]

# The handler is the world: here the ticket step fails.
let s = run(steps, proc(e: Effect): EffectResult =
  if e.name != "issue": erOk else: erFailed)
doAssert s.outcome == soCompensated
var names: seq[string]
for entry in s.log: names.add entry.effect.name
doAssert names == @["reserve", "charge", "issue", "refund", "release"]
```

A shell that performs real effects steps the machine itself, which is the same loop as `run` and ends in the same value:

```nim
import std/options
import nimcs/patterns/saga

proc perform(e: Effect): EffectResult =
  echo "performing ", e.name, " ", e.payload
  erOk

var s = start(@[step("a", effect("do-a"), effect("undo-a"))])
while true:
  let e = s.nextEffect
  if e.isNone: break
  s = s.feed(perform(e.get))
doAssert s.outcome == soCompleted
```

## Public API

Every exported symbol of `src/nimcs/patterns/saga.nim`, generated by `nim apiSections` (the
tests fail when it drifts). `import nimcs/patterns/saga` brings these names. A type they use from
another module (`Option`, `Result`, `Graph`) needs that module's import too, as in the example
above. A field marked `*` is readable outside the module; a type shown without fields is opaque,
built and read only through the functions.

```text
type Effect = object
  name*: string
  payload*: string
type SagaStep = object
  name*: string
  action*: Effect
  compensation*: Effect
type LogKind = enum
  lkAction, lkCompensation
type LogEntry = object
  kind*: LogKind
  step*: string
  effect*: Effect
  ok*: bool
type EffectResult = enum
  erOk, erFailed
type Outcome = enum
  soRunning,                ## more effects are to be performed
  soCompleted,              ## every action succeeded
  soCompensated,            ## an action failed and every earlier step was undone
  soStuck                    ## a compensation failed; `pending` lists what is left to undo
type Saga = object
type EffectHandler = proc (e: Effect): EffectResult {.noSideEffect, raises: [].}
func `==`(a, b: Effect): bool
func `==`(a, b: LogEntry): bool
func `==`(a, b: Saga): bool
func `==`(a, b: SagaStep): bool
func effect(name: string; payload = ""): Effect
func step(name: string; action, compensation: Effect): SagaStep
func start(steps: openArray[SagaStep]): Saga
func outcome(s: Saga): Outcome
func log(s: Saga): seq[LogEntry]
func nextEffect(s: Saga): Option[Effect]
func pending(s: Saga): seq[Effect]
func feed(s: Saga; res: EffectResult): Saga
func run(steps: openArray[SagaStep]; handler: EffectHandler): Saga
```

## Laws and invariants
- When every action succeeds the saga completes, the log holds the actions in order and no compensation runs (PAT-SAGA-01).
- When action k fails, the actions up to k ran, then the compensations of k-1 down to 0 in reverse order; k itself is not compensated (PAT-SAGA-02).
- When the first action fails nothing is compensated (PAT-SAGA-03).
- When a compensation fails the saga stops as stuck, nothing further runs, and `pending` lists the compensations still owed, the failed one first (PAT-SAGA-04).
- Every action that succeeded has exactly one successful compensation when the saga ends compensated (PAT-SAGA-05).
- Reports on a finished or stuck saga change nothing, so a repeated report cannot move it (PAT-SAGA-06).
- A shell that steps through `nextEffect` and `feed` performs the same effects and ends in the same saga as `run` (PAT-SAGA-07).
- An empty saga is completed with an empty log (PAT-SAGA-08).
- A started saga names the first action, and each result moves it to the next effect (PAT-SAGA-09).

## Complexity
`start` copies the steps, O(n). Each `feed` copies the log, so it is O(L) in the log length L and a whole run is O(n^2) worst case in the number of steps; for sagas of tens of steps this is irrelevant, and a persistent list of entries would make each `feed` O(1).

## Pitfalls
Running effects inline and compensating in a `try/except` mixes what to do with doing it, hides the order of compensation in control flow, and swallows a failed compensation.

```nim bad
proc bookTrip() =
  try:
    reserveSeat()
    chargeCard()
    issueTicket()
  except:
    discard refundCard()      # was the card charged? unknown
    discard releaseSeat()
```

Describe each step with its compensation as data and let the interpreter decide what to undo:

```nim
import nimcs/patterns/saga

let steps = @[step("charge", effect("charge"), effect("refund")),
              step("ticket", effect("issue"), effect("void"))]
let s = run(steps, proc(e: Effect): EffectResult =
  if e.name != "issue": erOk else: erFailed)
doAssert s.outcome == soCompensated and s.log.len == 3
```

Compensations are not rollbacks: the world may have changed between the action and its undo (an email cannot be unsent), so a compensation should be a business-level correction, and it must be safe to repeat.
