# Phantom types

## Intent
A phantom type parameter appears in a type's name but not in its data: `Id[User]` and `Id[Order]` are both an `int` at run time and are different types to the compiler. The parameter is a label that the type checker compares, so mixing two kinds of id, adding metres to seconds, or passing unchecked text where checked text is required becomes a compile error and costs nothing at run time.

## Use when / avoid when
- Use for identifiers of different entities that are all integers or strings (`Id[User]`, `Id[Order]`).
- Use for quantities with units (`Quantity[Meter]`), where the unit change must be an explicit function.
- Use for a state that a routine requires (`Email[Validated]`): the type records that a check ran.
- Avoid it when the value must be unforgeable. A `distinct` type can be converted explicitly by any caller (`Email[Validated]("x")` compiles); use an object with a private field and a smart constructor (`smart_constructor.md`).
- Avoid it when a run-time value is needed to tell the cases apart (a tag read from a file); use an object variant (`adt.md`).

## Nim shape

Module: `src/nimcs/fp/phantom_type.nim`: `Id[T]`, `Quantity[U]` with unit tags `Meter`, `Centimeter`, `Second`, and `Email[S]` with state tags `Raw` and `Validated`. The tags are empty `object` types; the parameter is declared on a `distinct` type, which keeps the representation and drops every operation until you define it.

```nim
import nimcs/fp/phantom_type

type
  User = object
  Order = object

let u = idOf[User](7)
let o = idOf[Order](7)
doAssert u == idOf[User](7)
doAssert not compiles(u == o)                       # different kinds do not mix

let lengths = qty[Meter](2) + qty[Meter](3)
doAssert lengths == qty[Meter](5)
doAssert not compiles(qty[Meter](2) + qty[Second](3))
doAssert toCentimeters(lengths) == qty[Centimeter](500)
```

State in the type: only `validateEmail` produces a `Validated` address, and `domainOf` accepts nothing else, so it has no failure case to handle.

```nim
import nimcs/fp/[result, phantom_type]

let checked = validateEmail(rawEmail("ann@example.com"))
doAssert checked.isOk
doAssert domainOf(checked.value) == "example.com"
doAssert validateEmail(rawEmail("ann@example")).isErr
doAssert not compiles(domainOf(rawEmail("ann@example.com")))
```

## Public API

Every exported symbol of `src/nimcs/fp/phantom_type.nim`, generated by `nim apiSections` (the
tests fail when it drifts). `import nimcs/fp/phantom_type` brings these names. A type they use from
another module (`Option`, `Result`, `Graph`) needs that module's import too, as in the example
above. A field marked `*` is readable outside the module; a type shown without fields is opaque,
built and read only through the functions.

```text
type Id[T] = distinct int
type Meter = object
type Centimeter = object
type Second = object
type Quantity[U] = distinct int
type Raw = object
type Validated = object
type Email[S] = distinct string
func idOf[T](n: int): Id[T]
func raw[T](id: Id[T]): int
func `==`[T](a, b: Id[T]): bool
func `<`[T](a, b: Id[T]): bool
func qty[U](n: int): Quantity[U]
func amount[U](q: Quantity[U]): int
func `+`[U](a, b: Quantity[U]): Quantity[U]
func `-`[U](a, b: Quantity[U]): Quantity[U]
func `==`[U](a, b: Quantity[U]): bool
func scaled[U](q: Quantity[U]; factor: int): Quantity[U]
func toCentimeters(m: Quantity[Meter]): Quantity[Centimeter]
func toMetersExact(cm: Quantity[Centimeter]): Result[Quantity[Meter], string]
func rawEmail(text: string): Email[Raw]
func validateEmail(e: Email[Raw]): Result[Email[Validated], string]
func domainOf(e: Email[Validated]): string
func text[S](e: Email[S]): string
```

## Laws and invariants
- Ids of one kind compare as their numbers and unwrap to them; ids of two kinds do not compile together (FP-PHANTOMTYPE-01).
- Quantities of one unit form a commutative, associative group under `+` and `-` with `qty(0)` as identity, and `scaled` distributes over `+`; two units do not add (FP-PHANTOMTYPE-02).
- Meters to centimeters and back is the identity; centimeters that are not a multiple of 100 give an error, not a rounded value (FP-PHANTOMTYPE-03).
- `validateEmail` accepts exactly one `@` with a non-empty name before it and a domain with a dot that is neither its first nor last character, keeps the text, and the domain is what follows the `@` (FP-PHANTOMTYPE-04).
- A raw address does not compile where a validated one is required (FP-PHANTOMTYPE-05).
- The parameter costs nothing: sizes equal those of the underlying `int` or `string` (FP-PHANTOMTYPE-06).
- The guard is bypassed by an explicit conversion; it protects against mistakes, not forgery (FP-PHANTOMTYPE-07).

## Complexity
No run-time cost: the types have the representation of `int` or `string`, and each wrapper or unwrapper is a conversion that disappears in the generated C. `validateEmail` is O(length of the text).

## Pitfalls
Forgetting that a plain number has no label. If the function takes `int`, the mix-up is back:

```nim bad
func shipTo(order: int; user: int): string = "ship " & $order & " to " & $user
echo shipTo(userId, orderId)        # swapped, and it compiles
```

```nim
import nimcs/fp/phantom_type

type
  User = object
  Order = object

func shipTo(order: Id[Order]; user: Id[User]): string {.raises: [].} =
  "ship " & $raw(order) & " to " & $raw(user)

doAssert shipTo(idOf[Order](5), idOf[User](9)) == "ship 5 to 9"
doAssert not compiles(shipTo(idOf[User](9), idOf[Order](5)))
```

A `distinct` type has none of its base type's operations: define `==`, `<` and the arithmetic you need, and only those. `Quantity` has `+`, `-`, `==` and `scaled` but no `*` of two quantities and no `+` with a plain `int`, because those would be wrong (metres times metres is not metres).
