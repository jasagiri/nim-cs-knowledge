# Functor, applicative and monad

## Intent
A functor is a container with a `map` that changes what is inside and leaves the shape alone; an applicative can also combine independent containers (`ap`, `map2`); a monad can run a step whose next step depends on the previous result (`flatMap`). The names describe shapes that `Option`, `Result`, `seq` and `Stream` already share. Naming the shape tells you which laws each type must obey and which operation to reach for.

## Use when / avoid when
- Use `map` when a pure function changes the content and the container's case (present / absent, ok / error) must not change.
- Use `map2` or `ap` to combine values that do not depend on each other; use `flatMap` when a later step needs an earlier value (`Result` railway, list of choices).
- Avoid `flatMap` where `map2` is enough: the independent form shows readers that no step depends on another.
- Avoid inventing a shared `Functor` type: see "What Nim's types cannot say" below. Write each type its own `map`, and a duck-typed generic when one routine must serve several.

## Nim shape

Module: `src/nimcs/fp/functor_monad.nim`. It adds `ap` (for `Option`, `Result`, and `seq` of functions), `map2` (`Option`, `Result`) and `flatMap` for `seq`. `map` and `flatMap` of `Option` come from `std/options`, those of `Result` from `nimcs/fp/result`, those of `Stream` from `nimcs/fp/lazy_stream`.

```nim
import std/options
import nimcs/fp/[result, compose, functor_monad]

func add(x, y: int): int {.raises: [].} = x + y
func halve(x: int): Result[int, string] {.raises: [].} =
  if x mod 2 == 0: ok(x div 2, string) else: err(int, "odd")

doAssert map2(some(1), some(2), add) == some(3)
doAssert map2(ok(1, string), err(int, "b"), add) == err(int, "b")
doAssert ok(8, string).flatMap(halve).flatMap(halve) == ok(2, string)
doAssert ok(6, string).flatMap(halve).flatMap(halve) == err(int, "odd")
func succ1(x: int): int {.raises: [].} = x + 1
let step: Fn[int, int] = succ1
let fs = @[step]
doAssert fs.ap(@[1, 2]) == @[2, 3]
```

### What Nim's types cannot say
Nim 2 has no higher-kinded type parameters, so "any container `F` that has `map`" cannot be written as a type; GADTs, arrows and comonads are not language features either. Consequently there is no `Functor[F]` to implement: `Option`, `Result`, `seq` and `Stream` each define their own `map` and `flatMap`, and the shared shape is a convention enforced by the law tests, not by the compiler. The workaround is a generic that is checked when it is instantiated: it calls `map` on a type parameter (`mixin map` makes the call resolve at the call site), and a type without a suitable `map` is rejected there.

```nim
import std/[options, sequtils]
import nimcs/fp/result

func inc1(x: int): int {.raises: [].} = x + 1

func bumpTwice[C](x: C): C {.raises: [].} =
  mixin map
  x.map(inc1).map(inc1)

doAssert bumpTwice(some(1)) == some(3)
doAssert bumpTwice(ok(1, string)) == ok(3, string)
doAssert bumpTwice(@[1, 2]) == @[3, 4]
doAssert not compiles(bumpTwice(5))
```

A `concept` can name the operations one concrete container must offer (see `type_class.md`), but a concept for "`map` of any container" would again need a type parameter that takes type arguments, so each concept is written for one element type. The functor laws are therefore a test to run per type, as in `tests/test_fp_functor_monad.nim`. The decision and its measured cost are in `docs/adr/ADR-NCK-0004-abstractions-beyond-nim-types.md`.

Future: nimony (the next Nim compiler) has type plugins that compute a type from types. A plugin `Apply(F, A)` that builds `F[A]` would let one `fmap` serve every container once nimony re-expands a deferred plugin type after `F` is bound and lets a plugin answer the reverse question for inference; neither works on nimony master as of 2026-11-21. This page keeps the per-type form until this repository targets nimony.

## Public API

Every exported symbol of `src/nimcs/fp/functor_monad.nim`, generated by `nim apiSections` (the
tests fail when it drifts). `import nimcs/fp/functor_monad` brings these names. A type they use from
another module (`Option`, `Result`, `Graph`) needs that module's import too, as in the example
above. A field marked `*` is readable outside the module; a type shown without fields is opaque,
built and read only through the functions.

```text
func ap[A, B](f: Option[Fn[A, B]]; x: Option[A]): Option[B]
func ap[A, B, E](f: Result[Fn[A, B], E]; x: Result[A, E]): Result[B, E]
func ap[A, B](fs: openArray[Fn[A, B]]; xs: openArray[A]): seq[B]
func flatMap[A, B](xs: openArray[A]; f: proc (x: A): seq[B] {.noSideEffect, raises: [].}): seq[B]
func map2[A, B, C](a: Option[A]; b: Option[B]; f: proc (x: A; y: B): C {.noSideEffect, raises: [].}): Option[C]
func map2[A, B, C, E](a: Result[A, E]; b: Result[B, E]; f: proc (x: A; y: B): C {.noSideEffect, raises: [].}): Result[C, E]
```

## Laws and invariants
- Functor: `x.map(identity) == x` and `x.map(f).map(g) == x.map(compose(g, f))` for `Option`, `Result`, `seq` and `Stream` (FP-FUNCTORMONAD-01).
- Applicative: applying a wrapped identity changes nothing (FP-FUNCTORMONAD-02); wrapping a function and a value then applying equals wrapping the application, and interchange holds (FP-FUNCTORMONAD-03).
- `ap` agrees with the monadic definition `x.flatMap(v => some(f(v)))` (FP-FUNCTORMONAD-04).
- Monad: `some(x).flatMap(f) == f(x)`, `o.flatMap(some) == o`, and `flatMap` is associative, for `Option` (FP-FUNCTORMONAD-05) and for `seq` with a singleton list (FP-FUNCTORMONAD-06).
- Failure order: `none` wins in `Option`; in `Result` the first error from the left wins and the later one is not collected (FP-FUNCTORMONAD-07).
- `map2(a, b, f)` equals mapping a curried `f` over `a` and applying to `b` (FP-FUNCTORMONAD-08).
- `ap` on lists applies every function to every value, functions outermost (FP-FUNCTORMONAD-09).
- A generic written against `map` is instantiated per type and a type-constructor parameter is not available (FP-FUNCTORMONAD-10).

## Complexity
`Option` and `Result` operations are O(1). `ap` on lists is O(|fs| * |xs|) time and space; `flatMap` on `seq` is linear in the total length of the produced lists. `Stream` `map` is O(1) to build and costs when pulled.

## Pitfalls
`Result.ap` and `map2` report only the first error. To collect all the errors of independent checks, validate into a list of errors instead; a `Result` cannot do that.

```nim bad
# both fields are wrong, but the caller only ever sees the first message
let form = map2(parseName(""), parseAge("x"), makeForm)
```

```nim
import nimcs/fp/[result, functor_monad]

func pair(a, b: int): (int, int) {.raises: [].} = (a, b)

let checked = map2(err(int, "name is empty"), err(int, "age is not a number"), pair)
doAssert checked == err((int, int), "name is empty")
```
