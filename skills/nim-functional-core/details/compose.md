# Composition and pipelines

## Intent
Small functions become a program by being composed: the output of one is the input of the next. Composition is associative and has a neutral element (`identity`), so a pipeline can be grouped any way, split into pieces and reassembled without changing its meaning. `compose(f, g)` is "g, then f"; `andThen(f, g)` is the same function in reading order.

## Use when / avoid when
- Use when the same chain of steps is applied in many places or built from a list at run time.
- Use plain method-call chains (`input.parse.validate.render`) when the steps are fixed at the call site; Nim's call syntax is already a pipeline.
- Avoid composing functions that can fail with unrelated error types: chain them with `flatMap` on `Result` (see `result.md`).
- Avoid deep closure stacks in hot code: each composed step is a closure call.

## Nim shape
`src/nimcs/fp/compose.nim`: `Fn[A, B]` (a pure function value), `identity`, `compose`, `andThen`, `composeAll`.

```nim
import std/strutils
import nimcs/fp/compose

func trim(s: string): string {.raises: [].} = s.strip
func shout(s: string): string {.raises: [].} = s.toUpperAscii
func exclaim(s: string): string {.raises: [].} = s & "!"

let viaCalls = "  hi ".trim.shout.exclaim
let pipeline = andThen(trim, shout).andThen(exclaim)
let steps = @[Fn[string, string](trim), Fn[string, string](shout), Fn[string, string](exclaim)]
doAssert viaCalls == "HI!"
doAssert pipeline("  hi ") == "HI!"
doAssert composeAll(steps)("  hi ") == "HI!"
```

### Higher-order functions, closures and comprehensions
A higher-order function takes or returns a function; `compose`, `andThen` and `composeAll` do both. A closure is a function value together with the variables it uses. Two facts decide whether a closure is safe to keep:

- A composition keeps the function values it was built from; reassigning the variable that held one later does not change it (FP-COMPOSE-07).
- A closure reads a captured `var` when it is called, not when it was made; copy the value into a `let` first to freeze it (FP-COMPOSE-08).
- Closures made in a loop share the loop variable, so all of them see its last value. Build each one by calling a function, whose parameters are a fresh frame per call (FP-COMPOSE-09). A `let` copy inside the loop body does not help.

```nim
import nimcs/fp/compose

func times(k: int): Fn[int, int] {.raises: [].} =
  result = proc(x: int): int {.noSideEffect, raises: [].} = x * k   # k is this call's parameter

func inc1(x: int): int {.raises: [].} = x + 1

let triple = times(3)
doAssert andThen(triple, inc1)(5) == 16
var factor = 2
let live = proc(x: int): int = x * factor
factor = 5
doAssert live(2) == 10                      # the variable's value at the call, not at creation
```

```nim
import std/sequtils
import nimcs/fp/compose

func times(k: int): Fn[int, int] {.raises: [].} =
  result = proc(x: int): int {.noSideEffect, raises: [].} = x * k

proc sharedLoopVar(): seq[int] =
  var made: seq[proc(x: int): int]
  for i in 0 ..< 4:
    made.add(proc(x: int): int = x * i)      # every closure shares the one `i`
  made.mapIt(it(10))

proc viaFunction(): seq[int] =
  var made: seq[Fn[int, int]]
  for i in 0 ..< 4:
    made.add(times(i))                       # each call captures its own parameter
  made.mapIt(it(10))

doAssert sharedLoopVar() == @[30, 30, 30, 30]
doAssert viaFunction() == @[0, 10, 20, 30]
```

`collect` from `std/sugar` is Nim's list comprehension: a `for` loop, with an optional `if`, whose last expression is added to the result. With a `filter` and a `map` it builds the same list in one pass (FP-COMPOSE-10); give it `newSeq` for a sequence or `initHashSet` with `{x}` items for a set.

```nim
import std/[sequtils, sugar]

let xs = @[1, 2, 3, 4, 5, 6]
let squaresOfEvens = collect(newSeq):
  for x in xs:
    if x mod 2 == 0:
      x * x
doAssert squaresOfEvens == @[4, 16, 36]
doAssert squaresOfEvens == xs.filter(proc(x: int): bool = x mod 2 == 0).map(proc(x: int): int = x * x)
```

A function that takes a number and returns a function (`times`) is partial application; `times(k)(x)` gives what a two-argument `x * k` gives (FP-COMPOSE-11).

## Public API

Every exported symbol of `src/nimcs/fp/compose.nim`, generated by `nim apiSections` (the
tests fail when it drifts). `import nimcs/fp/compose` brings these names. A type they use from
another module (`Option`, `Result`, `Graph`) needs that module's import too, as in the example
above. A field marked `*` is readable outside the module; a type shown without fields is opaque,
built and read only through the functions.

```text
type Fn[A; B] = proc (a: A): B {.noSideEffect, raises: [].}
func identity[T](x: T): T
func compose[A, B, C](f: proc (b: B): C {.noSideEffect, raises: [].}; g: proc (a: A): B {.noSideEffect, raises: [].}): Fn[A, C]
func andThen[A, B, C](f: proc (a: A): B {.noSideEffect, raises: [].}; g: proc (b: B): C {.noSideEffect, raises: [].}): Fn[A, C]
func composeAll[T](steps: openArray[Fn[T, T]]): Fn[T, T]
```

## Laws and invariants
- `compose(f, g)(x) == f(g(x))`; `andThen(f, g)(x) == g(f(x))` (FP-COMPOSE-01).
- Composition is associative (FP-COMPOSE-02).
- `identity` is a left and right unit (FP-COMPOSE-03).
- `andThen(f, g)` and `compose(g, f)` are the same function (FP-COMPOSE-04).
- `composeAll` runs first to last; an empty list is `identity` (FP-COMPOSE-05).
- Map fusion: `xs.map(g).map(f) == xs.map(compose(f, g))`, one pass instead of two (FP-COMPOSE-06).

## Complexity
Building a composition is O(1) (`composeAll`: O(k) to copy k steps). Calling it costs the sum of its steps plus one closure call per step. Fusing two maps halves the number of passes and the intermediate sequences.

## Pitfalls
Mixing up the order: `compose` reads right to left. If you think in reading order, use `andThen`.

```nim bad
let f = compose(shout, trim)     # runs shout first, then trim: probably not what was meant
```

```nim
import std/strutils
import nimcs/fp/compose

func trim(s: string): string {.raises: [].} = s.strip
func shout(s: string): string {.raises: [].} = s.toUpperAscii

let f = compose(shout, trim)     # trim first, then shout
let g = andThen(trim, shout)     # the same function, in reading order
doAssert f(" a ") == g(" a ")
```

The function types need `{.noSideEffect, raises: [].}`: a `proc` that echoes or may raise is rejected by the compiler, on purpose.
