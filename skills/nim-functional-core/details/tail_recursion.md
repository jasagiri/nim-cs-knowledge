# Tail recursion and loops

## Intent
A recursive routine whose last action is the recursive call is in tail form: nothing is left to do afterwards, so in principle its frame could be reused. Nim does not guarantee that. Whether a tail call becomes a jump depends on the C compiler and its settings, so a recursion that goes as deep as its input is not safe for large inputs even in tail form. The reliable pattern is: find the invariant with a recursion, carry the partial result in an accumulator argument, then write the final routine as a loop with local `var`s.

## Use when / avoid when
- Use plain recursion when the depth is small and bounded by the structure (a balanced tree's height, a handful of levels) and the recursive form is the clearest statement of the idea.
- Use the accumulator form to derive the loop: the accumulator arguments become the loop's local variables.
- Use the loop for anything whose depth grows with `n` or with the length of a list.
- Avoid exponential recursion (`fibNaive`) beyond tiny inputs; the accumulator form is linear.

## Nim shape

Module: `src/nimcs/fp/tail_recursion.nim`: three families, each as naive recursion, accumulator recursion and loop: `sumToNaive` / `sumToAcc` / `sumToLoop`, `fibNaive` / `fibAcc` / `fibLoop`, and `gcdRec` / `gcdLoop` (Euclid, already in tail form).

```nim
import nimcs/fp/tail_recursion

doAssert sumToNaive(100) == 5050        # a frame per step: fine for small n
doAssert sumToAcc(100, 0) == 5050       # tail form: the partial sum is in the argument
doAssert sumToLoop(100) == 5050         # the accumulator became a local var
doAssert fibNaive(15) == fibLoop(15)    # exponential time against linear
doAssert gcdLoop(48, 18) == gcdRec(48, 18)
```

The rewrite from tail recursion to a loop is mechanical. The accumulator arguments become `var`s declared before the loop, the base case becomes the loop's exit, and the argument expressions of the recursive call become one simultaneous assignment (a tuple assignment, so no new value is read after it was overwritten):

```nim
func sumDigits(n: Natural; acc: int): int {.raises: [].} =
  if n == 0: acc else: sumDigits(n div 10, acc + n mod 10)

func sumDigitsLoop(n: Natural): int {.raises: [].} =
  var rest: int = n          # the argument, as a local
  var acc = 0                # the accumulator, as a local
  while rest != 0:
    (rest, acc) = (rest div 10, acc + rest mod 10)
  acc

doAssert sumDigits(9045, 0) == sumDigitsLoop(9045)
```

The `var`s never leave the routine, so the function is still pure from outside (ADR-NCK-0002 S5).

## Public API

Every exported symbol of `src/nimcs/fp/tail_recursion.nim`, generated by `nim apiSections` (the
tests fail when it drifts). `import nimcs/fp/tail_recursion` brings these names. A type they use from
another module (`Option`, `Result`, `Graph`) needs that module's import too, as in the example
above. A field marked `*` is readable outside the module; a type shown without fields is opaque,
built and read only through the functions.

```text
type FibIndex = range[0 .. 92]
func sumToNaive(n: Natural): int
func sumToAcc(n: Natural; acc: int): int
func sumToLoop(n: Natural): int
func fibNaive(n: FibIndex): int
func fibAcc(n: Natural; a, b: int): int
func fibLoop(n: FibIndex): int
func gcdRec(a, b: Natural): int
func gcdLoop(a, b: Natural): int
```

## Laws and invariants
- Naive recursion, accumulator recursion and loop compute the same sum, equal to the closed form (FP-TAILRECURSION-01).
- The accumulator generalises the result: `sumToAcc(n, a) == a + sumToNaive(n)` (FP-TAILRECURSION-02).
- Naive, accumulator and loop Fibonacci agree (FP-TAILRECURSION-03); the loop reaches `fib(92)`, the last value that fits in `int`, and obeys the recurrence (FP-TAILRECURSION-04).
- The loop runs in constant stack for `n = 10_000_000` and gives the closed-form value (FP-TAILRECURSION-05).
- `gcdRec` and `gcdLoop` agree, are symmetric, and divide both arguments (FP-TAILRECURSION-06).

## Complexity
`sumTo*`: O(n) time; the naive and accumulator recursions use O(n) stack unless the backend reuses frames (not guaranteed), the loop O(1). `fibNaive` is exponential in time; `fibAcc` and `fibLoop` are O(n) time. `gcd*` is O(log min(a, b)) time.

## Pitfalls
Trusting the tail form for a deep input. The accumulator version below is still a recursion of depth `n`:

```nim bad
echo sumToAcc(100_000_000, 0)     # a call per step; do not rely on the compiler to remove them
```

```nim
import nimcs/fp/tail_recursion

doAssert sumToLoop(100_000_000) == 5000000050000000
```

A second trap: in an `if` expression a subrange-typed branch makes the whole expression that subrange, so `if n < 2: n else: bigger` raises `RangeDefect` when the other branch is out of range. Convert the branch (`int(n)`), as `fibNaive` does.
