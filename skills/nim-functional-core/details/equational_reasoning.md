# Equational reasoning

## Intent
In pure code, `let y = f(x); y + y` and `f(x) + f(x)` mean the same, and a short argument can show that two whole routines are equal. That lets you refactor by substituting equals for equals: fuse stages, drop a repeated step, replace a loop with a formula. The argument is the proof; a property test on generated inputs is the evidence that the argument has no hole.

## Use when / avoid when
- Use to speed up or simplify a pure pipeline without changing what it computes, and to explain why a rewrite is safe.
- Use a property test of `old(x) == new(x)` on generated inputs next to every such rewrite.
- Avoid it where a step has an effect (printing, a counter, randomness, time): substituting a call by its value, or the reverse, changes the program.
- Avoid it on floating-point sums and products: `(a + b) + c` and `a + (b + c)` can differ, so reassociation is not an equal step there. Rewrite exact integer arithmetic freely.

## Nim shape

Module: `src/nimcs/fp/equational_reasoning.nim`: pairs of equal forms. `stagedTotal` / `fusedTotal`, `normalizeStaged` / `normalizeOnce`, `rangeSumLoop` / `rangeSumFormula`, `countIf` / `countIfChunked`, and the cautionary `sumLeft` / `sumRight`.

```nim
import nimcs/fp/equational_reasoning

# three stages, three intermediate lists  ==  one pass
doAssert stagedTotal([1, 2, 3, 4]) == fusedTotal([1, 2, 3, 4])
# strip . lower . strip  ==  strip . lower  (strip is idempotent, lower does not move whitespace)
doAssert normalizeStaged("  MiXed ") == normalizeOnce("  MiXed ")
# a loop  ==  its closed form
doAssert rangeSumLoop(1000) == rangeSumFormula(1000)
```

The rewrite rules used, all valid for pure functions: replacing a name by its definition and back; `map f . map g == map (f . g)` (see `compose.md`); a `filter` before a `map` becomes a condition inside one loop; `f . f == f` for idempotent `f` (see `idempotence.md`); `count (a ++ b) == count a + count b`, which is why a count can be computed in chunks and added.

```nim
import nimcs/fp/equational_reasoning

func isOdd(x: int): bool {.raises: [].} = x mod 2 != 0

let xs = @[3, 8, 5, 5, 2, 7]
doAssert countIfChunked(xs, isOdd, 2) == countIf(xs, isOdd)
doAssert countIf(xs[0 .. 2], isOdd) + countIf(xs[3 .. 5], isOdd) == countIf(xs, isOdd)
```

## Laws and invariants
- `stagedTotal(xs) == fusedTotal(xs)` for every list (FP-EQUATIONALREASONING-01).
- `normalizeStaged(s) == normalizeOnce(s)`, and `normalizeOnce` is idempotent (FP-EQUATIONALREASONING-02).
- `rangeSumLoop(n) == rangeSumFormula(n)` while the sum fits in `int` (FP-EQUATIONALREASONING-03).
- `countIfChunked(xs, p, k) == countIf(xs, p)` for every chunk size `k`, and `countIf(a & b, p) == countIf(a, p) + countIf(b, p)` (FP-EQUATIONALREASONING-04).
- For a pure `f`, `let y = f(x); y + y` equals `f(x) + f(x)`; for a function with an effect it does not (FP-EQUATIONALREASONING-05).
- `sumLeft` and `sumRight` differ on `[0.1, 0.2, 0.3]`: float reassociation is not an equal step (FP-EQUATIONALREASONING-06).

## Complexity
The fused pipeline is one pass with O(1) extra space; the staged one is O(n) time per stage and O(n) extra space per intermediate list. The closed form is O(1) against the loop's O(n). The chunked count is O(n) in total, and the chunks are independent, which is what permits splitting the work.

## Pitfalls
Substituting a call by its value is a rewrite that only pure functions allow. With a counter, the two forms are different programs:

```nim bad
var calls = 0
proc next(): int =
  inc calls
  calls
# starting from calls == 0:
#   next() + next()          is 1 + 2 == 3
#   let n = next(); n + n    is 1 + 1 == 2
# the forms are not equal, so neither may be rewritten into the other
```

```nim
func nextAfter(calls: int): (int, int) {.raises: [].} =
  (calls + 1, calls + 1)     # the new state is part of the result

let (first, afterFirst) = nextAfter(0)
let (second, afterSecond) = nextAfter(afterFirst)
doAssert first + second == 3 and afterSecond == 2
```

Make the state an argument and a result, and the call is a value again. Do not apply an equality outside the domain it was shown for: `rangeSumFormula` is exact only while `n * (n + 1)` fits in `int`.
